### 🚀 框架与工具链

- **[Storybook 11 beta：官方 agent skills + 无头 `storybook tools` CLI + 类型安全的 CSF 4](https://storybook.js.org/blog/storybook-11-beta/)**（`11.0.0-beta.0` 于 **2026-11-03** 发布，博客与广泛报道在 **11-09 ~ 11-10**；正式版排期 **2026-12**）：这一版真正的方向变化不是 UI，而是**把 Storybook 变成「Agent 能读的组件知识库」**。**官方 skills** 有两个入口：`ui-workflow`（建 UI → 写 story → 跑测试 → 出可评审的产物）与 `component-docs`（用尽量少的 token 查组件 API / 元数据 / 示例）；后续 beta 说明里 `ui-workflow` 又被拆成四个 skill，并用 `AGENTS.md` 串成工作流。**skills 会随升级/新建项目自动装上**，同时发布在 skills.sh 以及 Claude Code、Codex 的插件渠道；MCP 仍然支持。**无头 CLI**：`storybook tools` 提供 `docs list` / `docs show` / `test run`（走 Vitest）/ `review create`，**不需要跑起 Storybook 实例**——这条对 CI 和 Agent 都更关键，因为它把「查文档」从浏览器里挪到了命令行。**写法上**：CSF 4 带「factories」API，story 可以是类型安全的，官方给了 codemod，CSF 3 仍支持；框架侧新增 `react-component-meta`、`vue-component-meta` 与 `@storybook/angular-vite`，Web Components（CEM）与 Svelte 5 支持改善。**体积与速度**：包体约小 **25%**，context/docgen 投递据称比 v10 快最多 **10×**。试用：`npx storybook@next upgrade` 或 `npm create storybook@next`。⚠️ 三点：**beta 期 API 会变**，团队共享的 story 与 codemod 建议等 12 月正式版再批量跑；**「10× 快」是官方基准**，取决于你的组件规模与 docgen 配置，别当成承诺；另外 skills 自动装进项目意味着 **`.storybook` 之外会多出 Agent 相关文件**，先把它们纳入 review 流程再合入。

- **[Zustand 5.1 与 XState 6 beta：状态库开始主动为 Agent 铺路](https://github.com/statelyai/docs/blob/7ee0c6084b28c683bf3f9e24006c4a6d7cb81d69/content/blog/2026-11-05-xstate-v6-beta/index.mdx)**（XState v6 beta 的公告是 **2026-11-05**，Zustand 5.1 同期，两者在 **11-11 ~ 11-12** 的 This Week In React #305 里被一起汇总）：**Zustand 5.1** 补了三件长期被要求的东西——**`persist` 支持异步 storage 与 migrations**、**`rehydrate()` 可 await**、**可以从 Redux DevTools 派发 action**。**XState 6 beta** 的变化更大：**transition 变成普通函数**、**Standard Schema 类型**、`xstate/fsm` 回归、实验性的**持久化执行**（`xstate/durable`，面向 Restate / Inngest / Cloudflare Workflows / Temporal 这类宿主），并新增一个 **JSON 输出的 CLI**（`inspect` / `validate` / `simulate` / `test` / `replay` / `diff` / `migrate`）。**最值得注意的一条**：XState 会把**给 Agent 看的文档直接放进 `node_modules/xstate/docs`**，同时对残留的 v5 配置给出迁移报错。⚠️ **Zustand 5.1 是 patch 级、XState 6 是 beta**，后者连 API 形态（transition 从对象变函数）都是破坏性的，**不要在生产上跨大版本升**；`xstate/durable` 明确标了实验性，接 Temporal 之类的宿主前先看它有没有稳定语义。

- **[Flutter 3.50 转稳定：Wasm 在 Safari 与 Firefox 变成「可选开启」，原生互操作转正](https://github.com/flutter/website/blob/61c335aff8e60fd55383416187f05f89c99f7034/sites/www/content/blog/whats-new-in-flutter-3-50/index.md)**（**2026-11-11** 稳定版，随 Dart 3.14；**11-13** 被中文/日文社区大范围转述）：对 Web 侧最实际的是 **Wasm 支持面扩大**——此前默认只在 Chromium（Chrome/Edge 137+）跑，现在 **Safari 26.2+（macOS / iOS）与 Firefox 147+** 也能跑，但**需要显式在 `web/flutter_bootstrap.js` 里配 `wasmAllowList`**（`blink: true, webkit: true, gecko: true`），默认值仍是 `webkit: false, gecko: false`，官方说未来稳定版会改默认。Flutter 自称重度组件基准下**帧率是 JS 版的 2× 以上**（自家基准）。**缓存侧新增 `--web-content-hash`**：给 JS / Wasm / 资源文件名加内容哈希并重写 `flutter_bootstrap.js`，让这些文件可以长缓存、而 `index.html` 与 bootstrap 保持 no-cache。**原生互操作转正**：Objective-C 的 FFIgen 与 Java/Kotlin 的 JNIgen 从实验转稳定，Dart 可以直接同步调原生 API（包括后台 isolate），Pigeon 也加了预览态的 FFI/JNI 模式；平台通道仍然可用，不必重写。另有两个值得知道的：**`--no-deprecated-js-interop`** 会在依赖仍引用 `dart:html` / `dart:js` / `package:js` 时直接构建失败（这些是 Wasm 的前置条件）；实验性的 **WebParagraph** 让浏览器负责文字排版，CanvasKit 从约 **5.46 MB 缩到 3.75 MB**，并解决 CJK 的「豆腐块」闪烁。⚠️ 三个坑：**Material / Cupertino 内置库正式废弃**，新项目改用 `package:material_ui`（有迁移指南与 `MaterialUiCompatibilityBridge`）；`RegularWindow` → `Window`、`sizedToContent` → `shrinkWrap` 是破坏性重命名；另外 **Wasm 优化不等于所有应用都变快**——它的收益集中在重绘制场景，表单/长列表类页面差别很小。

- **[Claude Code 2.1.323：实验性 Code Mode（Claude 写 JS 调自己的工具）+ 插件版本区间](https://github.com/anthropics/claude-code/releases/tag/v2.1.323)**（**2026-11-12** 发布，11-13 起被 DevelopersIO / ClaudeKit 等拆解；是 11-10 推过的 2.1.322 的直接后继）：**Code Mode** 是这版的头条——**默认关闭，可在组织级禁用**，打开后 Claude 不再一条条发工具调用，而是**写一段 JavaScript 去调用它的工具**。**但今天你还看不到细节**：changelog 里指向的开关文档页在 11-13 仍是 **404**，设置项名称、它与权限规则怎么交互都没有公开说明，已有分析明确建议「不要猜配置项名字」。**第二条对团队更实际**：`plugin.json` 新增 **`engines["claude-code"]` 版本区间**，超出区间的插件**不安装、不更新、不加载**，安装/更新时自动挑最新的兼容版本；`claude plugin validate` 现在会对 **TypeScript hooks 模块做类型检查**（默认警告，`--strict` 下失败）。**安全侧三处收口值得逐条看**：**①** 变量值里带 `*` 的 Bash 允许规则（如 `Bash(PORT=* npm run dev)`）会在启动时告警；**②**「don't ask again」生成的允许规则**如果看起来含密钥、或会写进被 git 跟踪的 `settings.local.json`，就只对本次会话生效、不落盘**——这正是 11-09 那期 Apiiro 报告的直接回应；**③** hook 返回的「allow」**不再能覆盖失败中的权限检查**。**一处静默的破坏性变化**：内部调用的 **git / ripgrep 现在不带登录凭据与 API key 运行**——这是好事，但**依赖这些环境变量的 credential helper 或 hook 会静默失效**。**另一处容易踩的**：**未识别的模型 ID 现在默认按 1M 上下文处理**（此前 200K），在真实窗口更小的网关后面会直接报错，可用 `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` 退回。其余：移除 MCP v1 client 与 `subagentStatusLine` 设置、hook 运行时有 30 秒进度心跳、Artifact 上传支持 `.docx`。⚠️ 三点：**Code Mode 是实验性且文档缺失**，现在开等于无文档试飞；**插件 engines 区间会让「明明装了却不生效」成为新的排障项**，升级后先跑 `claude plugin validate`；**变更总量巨大**（第三方统计约 294 项、其中约 20 项破坏性/废弃），**升级前先看自己有没有自定义 hook、网关与插件**。

- **[Google 开源 A2UI 1.0：Agent 不再回一堵文字，而是回「可渲染的 UI 描述」](https://developers.googleblog.com/a2ui-10-build-delightful-fast-reliable-agentic-experiences/)**（**2026-11-11** 发布 1.0 稳定版，Apache-2.0；11-12 ~ 11-13 被 SD Times 与中文社区跟进）：这条对前端最直接——**它把「Agent 的输出」从 Markdown 文本变成了一个有 schema 的 UI 描述**。**机制**：Agent 不再返回 HTML 或可执行代码，而是发一段**声明式 JSON**，描述一块「surface」（表单、图表、选择器），宿主应用用**自己预批准的组件目录**把它渲染成原生控件——**设计上就是安全的**（没有可执行代码），且在各平台都是原生速度。**1.0 新增**：**双向函数调用**（`callAgentFunction` / `callRendererFunction`）、无障碍支持、扩展元数据、按组件混用 catalog、`createSurface` 上支持内联组件与数据模型。**渲染器**：React / Angular / Lit（Web）、Flutter（移动+桌面）、SwiftUI（iOS）、Jetpack Compose（Android，目前 0.9.1，1.0「即将」）；Web 与 Flutter 渲染器也**能在 MCP Apps 宿主（Gemini、Claude）里跑**。**Agent SDK**：Python / TypeScript / Dart。**采用方**：Atlassian、Alation、Bloomberg、**字节跳动（Lynx / Jev）**，CopilotKit 有贡献。**传输无关**：可走 AG-UI、A2A、MCP、SSE、WebSocket，定位是**补充 AG-UI 而不是替代**。⚠️ 三点：**协议到 1.0，但 npm 上的渲染器与包里仍有大量停在 0.15.0 / 0.9.1**，这是真实的成熟度落差，接之前先对齐版本；**「预批准组件目录」意味着你得先有一套设计系统能映射过去**，没有组件库的团队接它的成本会比想象中高；另外它解决的是「Agent 怎么输出 UI」，**不解决「UI 该长什么样」**——生成质量仍取决于 Agent 选组件的判断力。

- **[MCP 的两条安全线与一个新 SDK：官方 servers 补了 6 个洞、AWS MCP 有高危绕过、C# SDK 2.0 转无状态](https://github.com/modelcontextprotocol/servers/releases)**（**2026-11-11** 前后集中出现）：**第一件（该立刻升）**：**MCP Servers v2.4.0** 修了三个官方 server 里的 **6 个漏洞**——`server-filesystem` 2.3.0 的路径边界问题、`mcp-server-git` 里「不可信仓库配置会执行外部程序」、`mcp-server-fetch` 的 IPv6 私有地址判断与 robots.txt 匹配。**第二件（高危、无绕过方案）**：**AWS API MCP Server 的 CVE-2026-125271**——操作名里含**连续大写字母**时会**匹配不上 deny-list**，等于策略可被绕过；**已在 1.5.1 修复，官方说没有 workaround**。**第三件（生态）**：微软发布**官方 C# SDK 2.0**，实现 **2026-07-28 那版「默认无状态」规范**——去掉 `initialize` 握手与 `Mcp-Session-Id`、新增 `server/discover`、改用多轮往返请求（MRTR）。⚠️ **把这三条连起来看才是重点**：**「无状态 + 无内建鉴权 / 权限 / 审计」是同一枚硬币的两面**——协议变简单了，但**授权、限流、审计全落到你自己的网关上**；官方 server 的漏洞集中在**路径边界与「信任仓库配置」**这两类，正好是「把一个本地工具暴露成远程端点」时最容易忘的地方。动作：**升级 `server-filesystem` / `mcp-server-git` / `mcp-server-fetch` 到 v2.4.0、AWS API MCP Server 到 1.5.1**，并给所有 MCP 端点加上与普通后端同等级的鉴权与日志。

- **[《重新发现 WebKit Bug 322883》：同一任务里启动的多个 Worker，只有第一个能连上 Service Worker](https://nuxx.net/blog/2026/11/12/rediscovering-webkit-bug-322883/)**（**2026-11-12**）：这篇的价值在于**一个能解释「离线为什么时好时坏」的具体机制**。症状：在**同一个任务里**连续 `new Worker()` 启动多个 worker 时，**只有第一个**能正常连上 service worker，其余**绕过它直接走网络**，于是「离线地图」这类依赖 SW 缓存拦截请求的场景会**部分资源加载失败**——而且因为只有一部分失败，很容易被误判成网络抖动。作者确认它与 **8 月的一份报告重复**、**至今未修**，但在 **Safari 27.3 iOS beta 上无法复现**（可能是版本差异，也可能与触发条件有关）。⚠️ 两点：文中给出的复现条件很具体（**同一 task 内同步启动**），**拆到 `setTimeout` / `await` 之后往往就绕开了**，这是可以立刻用的 workaround；但**根因在 WebKit 侧**，workaround 只能覆盖你自己的代码，第三方库里的批量 worker 创建仍需逐个排查。
