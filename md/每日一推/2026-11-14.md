- **[Expo Simulators：云端 iOS 模拟器 / Android 模拟器，专为 Agent 而做](https://expo.dev/blog/introducing-expo-simulators-cloud-simulators-built-for-agents)**（**2026-11-12** 发布，所有付费套餐可用）：解决的问题很具体——**Agent 在 Linux、Windows（WSL）或云端沙箱里跑，没有 Mac，跑不了 iOS 模拟器**。现在可以按需起一个云端模拟器：**安装构建 → 用和本地一样的工具驱动（agent-device / Argent / Appium）→ 交回证据**（录屏、截图、日志、网络、CPU / 内存），全程不占本地内存。**每个会话一个独立 VM**，所以并行 Agent 不会互相踩。**入口**：CLI（`eas simulator:start` 或 `npx eas-cli@latest simulator --platform ios`）、REST API，以及官方的 **Expo Simulators skill**；自带浏览器实时预览，另有一种 `web-preview-only` 会话只观察不控制。**价格**：按用量 **$0.10 / 分钟**（约 $6/小时），Starter / Production / Enterprise 每月含 60 分钟。⚠️ 四点：**它只解决「模拟器」这一个瓶颈**——**编译 iOS 包仍然需要 Mac 或 EAS Build**；**没有真机**；**启动与排队比本地慢**，**iOS 无障碍树快照可能要几十秒**（做 a11y 断言的 Agent 会明显变慢）；Expo 预告的 **Agent Sessions**（带提示注入防护的企业级触发层）要到 11 月底才给细节。

- **[11-13 的 npm 事故日：三个恶意包，加上 pnpm 11.x 的一串供应链 CVE](https://o3.security/malware/npm/casamare)**（npm 恶意包 advisory 于 **2026-11-13** 披露；pnpm 的 CVE 在 **11-03** 公布、修复版本分布在 10.34.x / 11.4 ~ 11.11）：**三个包，全部版本受影响、没有修复版本**：**`casamare`**（GHSA-xqvf-vmv8-fhw5）、**`ansi-sanitize`**（GHSA-59gv-286x-7347）、**`lineparse`**（GHSA-949g-9w76-cwfw），分类都是 **CWE-506 内嵌恶意代码**。**`casamare` 的细节最值得知道**：它被描述成一个**被投毒的 Angular SDK**，在 `dist/assets/5760.pbf` 里带一段 **313 KB 混淆过的浏览器载荷**，把 **localStorage / sessionStorage 里的 token、cookie 与浏览器指纹**外发到托管在 **supabase.co** 的端点，并且**在 SPA 路由切换时反复触发**。**处置口径按 GitHub 的标准来**：装过 / 跑过这些包的主机**一律视为完全失陷**，**卸载不等于清除**——要在干净机器上轮换凭据、重建主机、检查 lockfile / `node_modules` / CI 缓存，并在内部 registry 里禁掉这三个名字。**pnpm 那条线是另一件事但同一个主题**：**11.4 / 10.34.0** 起把 tarball 完整性不匹配改成**硬失败**（`ERR_PNPM_TARBALL_INTEGRITY`，只能 `--update-checksums` 绕过）、**拒绝缺 `integrity:` 的 lockfile 条目**、**不再跨 registry 复用未限定范围的凭据**、**git 依赖的 `commit` 必须是 40 位 SHA**（堵 `--upload-pack` 注入）、**patch 文件不能逃出包目录**（CVE-2026-50017 / 50021 / 50014）；后续 **10.34.4 / 11.7.0** 又修了 hoisted 安装下 lockfile 别名逃出 `node_modules` 的问题（CVE-2026-59196），代理环境变量展开（CVE-2026-101043，11.11.0 / 10.34.5）与 pacquet 的名字穿越（CVE-2026-101044）也各有修复。⚠️ 三条落到动作上：**升级 pnpm 到 11.11.0+ 或对应 10.34.5+**；把 **`minimumReleaseAge` / release-age 门禁**打开（新发包先在隔离环境晾几小时，能挡掉大部分这类投毒窗口）；另外 **OpenCode 在 11-12 修了一个 RCE**（GHSA-632h-h47v-g4x4，`/global/upgrade` 会把攻击者给的包名传给 npm/pnpm/Bun，修复版 **1.18.22**）——**AI 工具本身也是供应链入口**，别把它的自动升级当无害操作。

### 🎨 浏览器与 CSS

- **[Chrome 158 下周二（11-17）在 Stable 停掉 XSLT：只影响 0.02% 的页面，但会静默坏掉](https://developer.chrome.com/docs/web-platform/deprecating-xslt)**（Chrome 158 全量稳定 **2026-11-17**；Origin Trial 自 **Chrome 152 / 2026-08-25** 起，企业策略试用自 **Chrome 146**）：**被移除的是两样**——`XSLTProcessor` 这个类，和文档里的 XSLT 处理指令（`<?xml-stylesheet type="text/xsl" ...?>`）。**时间点要分清三层**：**11-17 起在 Stable 上对所有人停止运行**（OT 与企业策略参与者除外）；**Chrome 176（2027-08-17）** OT 与策略到期、彻底关掉；**XML 本身和 `type="text/css"` 的处理指令不受影响**，Chromium 还计划把 libxml2 换成内存安全的 Rust XML 解析器。**为什么值得今天写**：它命中率低（约 **0.02%** 的页面加载用 XSLT，用处理指令的不到 **0.001%**），但**一旦命中就是白屏或数据不渲染**，而且**不会有明显的报错**——典型的「老后台系统在升级后突然坏了」。**迁移路径**共四条：挪到**服务端做 XSLT**、改成 **JSON + JS 渲染**、用 **SaxonJS**（浏览器里的 XSLT 3.0）、或用社区给的 **WASM `XSLTProcessor` polyfill** / 套 polyfill 的扩展。⚠️ 三点：**WebKit 与 Gecko 都支持移除**，所以这不是「换个浏览器就没事」，只是时间差；**企业策略只是缓期**，2027-08 之后一样关；**SaxonJS 与 polyfill 的行为与原生有差异**（尤其扩展函数与 `document()`），迁移后要拿真实样式表跑一遍对照。

### 📚 好文精选

- **[《默认跨浏览器：Modern Web Guidance 里的 Baseline 回退机制》](https://developer.chrome.com/blog/cross-browser-by-default)**（Chrome for Developers，**2026-11-12**；是 11-12 那期 Modern Web Guidance 1.0 的配套第三篇，11-13 还有一篇 recap）：**这篇补的是前两篇没讲的坑**——Agent 拿到「现代写法」之后，**怎么知道该不该加回退**。**它给的数字很干脆**：在 MWG 自己的评测里，**不带指南的模型在「特性检测 / `@supports` / 回退」这类检查上只有 43% 通过率，带指南是 87%**——也就是说另一半问题不是「不会写新特性」，而是「**新特性写上了，但没兜底**」。**机制**：指南里嵌了来自 **`web-features` 包**的实时 Baseline 状态与浏览器版本，据此定两条默认规则——**Widely available → 直接用，不写回退代码**；**Newly available / Limited availability → 用现代特性 + 一个经过验证的回退**（例子：`<dialog closedby>` 在 Chrome 134 / Edge 134 / Firefox 141 可用，**Safari 不支持**）。**四种回退模式**：**① 渐进增强、不写回退**（`text-wrap: balance`、Speculation Rules）；**② CSS `@supports` 检测**（锚点容器查询）；**③ 轻量、零依赖的自写 JS**；**④ 条件加载的 polyfill**（只在原生缺失时动态加载）。⚠️ 三点：**这是 Google 自述的评测**，43% / 87% 不可独立复核；**「Baseline 状态」是快照**，`web-features` 会更新，结论要跟着刷新；**这篇文章的真正用途是给「你自己写 agent 规则」当模板**——四条回退模式可以直接抄进团队的 review 清单，而不必装整包。
