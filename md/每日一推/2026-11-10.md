### 🎨 浏览器与 CSS

- **[Firefox 160 稳定版发布：CSS 侧只多了一个别名，`random()` 默认关闭——更正 11-08 的说法](https://developer.mozilla.org/en-US/docs/Mozilla/Firefox/Releases/160)**（2026-11-10 发布，构建于 11-09 上 FTP；同日 153.7 与 115.46 ESR 一并更新）：**先把勘误说清楚**。11-08 那期按 beta / Nightly 说明写了「`random()` 落地」，但稳定版开发者说明里 **CSS 部分只有一条**：**`::-webkit-input-placeholder` 作为 `::placeholder` 的别名**（bug 2083700）。`random()`（bug 2071165）一直是 **pref-gated**，开关是 `layout.css.random.enabled`，从 **158 起只在 Nightly 可用**；把它对全体用户打开的 **bug 2072252 挂在 161.0a1 的 release notes 车次上**，也就是说**至少要到 161 才可能默认可用**，160 不是。同理，**锚点元素 `transform` 参与定位**那条也只出现在 Nightly 说明里，160 稳定版说明没有对应条目——建议按「未在 160 默认可用」处理。**稳定版真正新增的 Web 平台内容**：**WebTransport 一批接口变更**（`headers` 选项与 `responseHeaders`；`exportKeyingMaterial()` 改为必须传 `context`、并用 `outputLength` 取代原来的长度参数；新增 `incomingMaxBufferedDatagrams` / `outgoingMaxBufferedDatagrams` 取代非标准的 `*HighWaterMark`；`datagramsReadableType: "bytes"` 支持 BYOB 读取）；**Web Speech API 的端上语音识别**（桌面端、约 40 种语言，不走云端，Android 上没有）；**移除**非标准的 `MozScrolledAreaChanged`（可用 `layout.scrolled-area-changed.content.enabled` 临时救回）；扩展侧的 `runtime.PlatformInfo.arch` 在 arm64 上不再返回 `aarch64`。实验性（默认关）：**`blocking="render"`** 属性与 **CSS Typed OM 算术**。消费端变化：**Mini Window**（把标签页或选中内容拉进一个置顶小窗）、**画中画 0.25×–2.0× 倍速**、**MKV（FLAC / MP3 / PCM）播放**、macOS 上 **WebGL 改走 Metal**、地址栏「粘贴并搜索」与域名更高对比、重复的应用互跳提示可以选「永不」、保存的 PDF 里 MathML 对辅助技术可读。⚠️ 两点：`random()` 想现在就用只能改 `about:config`，别写进生产样式；这条勘误也说明**beta / Nightly 说明不等于稳定版清单**，以后碰到 CSS 新函数先查 MDN 的 Stable 页。
- **[CSS Color 4 的 CR 草案修订了色域映射的边界处理](https://www.w3.org/TR/css-color-4/)**（2026-11-03 由 W3C 发布，11-10 才被中文技术媒体转出来）：改的是**接近纯黑 / 纯白时的色域映射（gamut mapping）边界条件**——把原先在极值附近可能出现的映射抖动与钳制问题收口，属于「规范文本先对齐，浏览器再跟」的那类改动。同一个窗口里 **CSS Fonts 4 的 WD** 也更新了字距（kerning）与彩色字体调色板的表述。⚠️ 这两条**对今天写代码的人没有可执行影响**：CR / WD 是规范成熟度标记，不是支持清单；实际行为仍以你目标浏览器的实现为准，真正该看的是配套的 WPT 用例有没有跟着改。

- **[Simon Willison 的 pelican 测试：Fable 5.2 在 `max` 档烧掉 12.8 万 thinking token，一张图都没画出来](https://simonwillison.net/2026/Nov/9/llm-anthropic/)**（2026-11-09，随 `llm-anthropic 0.31` 发布一起做的实测）：这条的价值不在模型好坏，而在**一个能直接改你默认配置的发现**。他把那条「骑自行车的鹈鹕」SVG 基准在 **low / medium / high / xhigh / max** 五档各跑了一遍，**结论是 xhigh 最好**；**max 档直接失败**——**花了 12.8 万 thinking token 仍没产出图片**，`stop_reason` 是 `max_tokens`。原因是 Anthropic 的 **thinking token 计入输出上限**，而 Fable 5.2 的输出上限就是 **128K**，于是一轮长思考刚好把额度烧光。他指出这**是 Opus 5.5 上见过的同一个 bug**，而且**对 Fable 系列是新的**：Fable 5 和 5.1 在 max 档都能正常出图。**给你的动作**：用 5.2 做「一次性要我一个完整产物」的任务（SVG、单文件组件、完整 HTML 页）时，**先把推理档设成 xhigh 而不是 max**，否则你看到的是「什么都没有返回」而不是一个更差的结果——这类失败在批量跑的时候很难被发现。⚠️ 单人、单条提示词的观察，不是评测；但它是可复现的，而且和官方「thinking 计入输出上限」的文档描述一致。
