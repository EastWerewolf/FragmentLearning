### 🎨 浏览器与 CSS

- **[Safari Technology Preview 257：修掉 Safari 27 在 60Hz 屏上的滚动卡顿，`<select multiple>` 变成下拉](https://webkit.org/blog/18652/release-notes-for-safari-technology-preview-257/)**（**2026-11-18** 发布，覆盖 macOS Tahoe 与 macOS Golden Gate；WebKit 变更区间 **324654@main ~ 326096@main**）：**这条的实用价值集中在「修回归」而不是「加特性」**。**三个真的会被人投诉的问题**：**① 60Hz 屏上的滚动卡顿**——这是 **Safari 27 的回归**，不是老问题；**② Adaptive Dark Mode 的滤镜让渐变多的页面渲染变慢、滚动发涩**（Safari 27.3 beta 的自动深色又添了一条性能账）；**③ 视频的一串毛病**——离屏播放后回到页面内联视频黑屏、拖到未缓冲区间后卡住、循环 WebM 在第二次边界处停、video.js 站点上字幕被控件挡住、退出全屏后视频短暂缩小。**表单侧有个可见变化**：**`<select multiple size="1">` 在 macOS 上改为渲染成下拉**；另有一个**默认关闭**的预览：增强版 `<select>` 支持 `multiple` / listbox 渲染与 **`<selectedcontent>`**。**Web 扩展**：注册一次监听器带来的内存修复、`declarativeNetRequest` 的自定义头名与配额重复计数、`"message_serialization": "structured_clone"`、`runtime.MessageSender` 上的 `windowId`；**安全上禁止把标签导航到 `javascript:` URL**。**API 与无障碍**：`requestIdleCallback`、`AbortSignal.any()` 的 GC、`SubtleCrypto.deriveBits()` 的范围校验、Blob worker 的源、ReportingObserver 的一批修复、WebAuthn 跨设备回退 URL 扩展、OpenID4VP 与 org-iso-mdoc 凭证请求可一起呈现；SVG `<a>` / `<g>` 现在会画焦点轮廓，`element.focus()` 在页面未聚焦时也会派发 focus / focusin。⚠️ 三点：**TP 不是给生产用的**，它领先 Safari 27.3 正式版约一个月；**`<select multiple size="1">` 变下拉是行为变化**，依赖它渲染成列表的老表单要复测；**Adaptive Dark Mode 的性能问题只修了一半**——它仍是「给不支持的站点自动反色」，做品牌色的站点该测的还得测。

### 🤖 AI 与开发

- **[Claude Code 2.1.330：内置画图 mod `easel`，`/loop` 与定时任务从 7 天延长到 30 天](https://github.com/anthropics/claude-code/releases/tag/v2.1.330)**（**2026-11-20** 发布，约 **142 项**改动：98 修复 / 16 新增 / 11 改进 / 6 项被标为破坏性；是 11-20 那期推的 **2.1.329** 的下一个版本）：**三件值得单独说**：**① `easel`**——内置 mod，能按要求画图，并**自动在 MCP 指标结果下方附图**；限 **Pro / Max**（Team / Enterprise 视可用性），**只在 macOS 与 Linux**，自动配图可在 `/config` 里关。**② 企业组织登录**——`claude auth login` 后可直接登进 **Enterprise Admin Console**，自动套用组织设置与组织指定的云厂商 / 网关。**③ 无人值守的两个变化**：**`/loop` 与定时任务的上限从 7 天延到 30 天**（此前创建的任务仍按 7 天结束）；**更多 `rm` 命令**（指向根目录 / home / 顶层目录 / 工作目录本身）**需要批准**，且在**没人能应答的场景直接拒绝**——这条对 CI 与后台跑循环的人是硬约束。**另有两条语义变更**：**`deniedMcpServers` 里的名字条目现在只隐藏被点名的那一个 claude.ai connector**，同 URL 的其它 connector 不受影响——**要全禁就写精确 URL**；**`--start-dir` / `SELF_HOSTED_RUNNER_START_DIR`** 让自托管 runner 从仓库子目录起步，`/metrics` 新增 runner 的「下单到注册」「下单到首个会话」耗时。**VS Code 侧**补了 `/fork` 与 `/workflows`，以及 `claudeCode.escapeStopsClaude` 设置。**修复里最该知道的三条**：长对话压缩后**几分钟的卡死**、**WebFetch 挂起或返回空**、**`ExitWorktree` 误删其它会话的 worktree**；另有并发保存设置丢改动、`--continue` / `--resume` 得到空会话、MCP 的「JSON schema is invalid」导致整轮失败、`/stats` 按 UTC 而非本地时间统计，以及**回退了 2.1.329 里「`max_tokens` 溢出不再自动重试」的改动**。⚠️ 四点：**定时任务 30 天 + 更多 `rm` 拒绝**是一对——长周期无人值守更容易撞上「需要人批准」的墙；**`deniedMcpServers` 的语义变了**，靠名字兜底的组织要改成 URL；**`easel` 只覆盖 macOS / Linux**，Windows 用户看不到；这条与 11-19 / 11-20 推的 2.1.326 ~ 2.1.329 是同一条三条连发之后的第四个版本，**升级节奏本身也值得纳入你的变更管理**。

- **[OpenCode 2.3.2：修掉 GPT-6.2 的提示词缓存漏洞，每步未缓存输入从 14,000 token 降到 3](https://opencode.ai/changelog)**（**2026-11-18** 发布（约 01:30 UTC）；上游 PR #64542 与 #64544 在 **11-17 23:58 / 11-18 00:22** 合入；2.3.1 在约一小时前发布）：**这条是这周最具体的「省钱修复」**。**问题**：**GPT-6.2 不会缓存放在 Responses API `instructions` 字段里的系统提示词**，于是 OpenCode 在**每个 agent 步骤**都把整段提示词当**未缓存输入**重新计费。**修法**：在**所有 Responses 路由**（OpenAI API key 与 ChatGPT 登录、GitHub Copilot、Zen、Azure、OpenRouter）上，把系统提示词改成**排在前面的 `developer` 消息**，从第二步起就能命中缓存；`/responses/compact` 也读同一段缓存前缀。**官方给的数字**：在 GitHub Copilot 上跑 `gpt-6.2-sol`，**每步未缓存输入从约 14,000 token 降到 3**。**同期版本还有**：2.3.1 把 GPT-6.2 Sol / Astra 加进 ChatGPT 登录的模型列表、后台压缩摘要改由 `compaction.background: false` 控制、超时的 shell 命令**转入后台而不是被杀**、恢复 `CLAUDE.md` 回退（`OPENCODE_DISABLE_CLAUDE_CODE`）、把实验性 schedules 改名为 **automations**；**2.3.0 起后台 subagent 成为默认**。⚠️ 四点：**「14,000 → 3」是厂商在 Copilot 路由上的测量**，换 provider、换模型不一定复现；**这是绕开上游 API 行为的补丁**，OpenAI 若改了 `instructions` 的缓存策略，这段逻辑要跟着改；**30 天内约 20 个稳定版**，pin 版本比跟最新更稳；**缓存命中依赖前缀完全一致**，你在系统提示里插时间戳之类的动态内容会让它失效。

- **[Codex CLI 0.170.0：TUI 里能打实时语音电话，同名的 MCP server 可分环境共存](https://github.com/openai/codex/releases/tag/rust-v0.170.0)**（**2026-11-18 03:40 UTC** 发布；上一个稳定版 **0.169.0** 在 11-13，**0.169.1** 在 11-17 打补丁）：**新增三件**：**① TUI 里的 WebRTC 实时语音通话**（#61172）——终端里直接和 Agent 通话；**② OpenTelemetry HTTP exporter 的认证头会自动刷新**（#61028），长期跑的可观测性不用再靠重启；**③ 同名 MCP server 跨环境共存的实验性支持**（#60905）——多环境（本地 / 容器 / 远端）各挂一个同名 server 时不再互相覆盖。**修的部分很集中**：**超大的 WebSocket 请求改为立即回退到 HTTP**（按服务端声明的大小限制，不再重试， #60840 / #60841）；**MCP OAuth 凭据在取消 / 登录 / 登出时的竞争**（#60849 / #60981）；**Cloud 会话的自动重连**并保留进行中的恢复轮次（#60969 / #61014）；**Windows 的原子文件替换、沙箱权限保留、运行时注册恢复**（#60872 / #60943 / #60944）；**权限更新与子线程不再丢失已有的沙箱限制**（#60936 / #61134）；重叠根目录下的文件搜索结果去重、空白查询的线程搜索片段修复。文档侧更新了**沙箱的权限配置与文件系统规则**说明（#61133）。⚠️ 三点：**「同名 MCP server」是实验特性**，多环境混跑前先做隔离验证；**0.169 → 0.170 只隔了 5 天**，它是持续交付型 CLI，别把某个 patch 当长期基座；有一份第三方拆解把这一版写成「子代理可见性 / 音频转写 / 云端冻结修复」，**PR 号与实际 changelog 对不上**，以 GitHub release 为准。

- **[GitHub 允许企业把 Copilot 的 skill / agent / hooks / MCP server 锁死在插件里](https://github.blog/changelog/2026-11-16-control-where-github-copilot-customizations-come-from/)**（changelog **2026-11-16**；配置写在 `.github-private` 治理仓的 `copilot/managed-settings.json`）：**新的 managed setting `strictPluginOnlyCustomization` 管五类东西**：**skills、custom agents、hooks、MCP servers、可执行的 Copilot 扩展**（指 **canvas provider**，**不含 VS Code Marketplace 扩展**）。管理员可以**五类全锁，也可以只锁其中几类**——比如**只锁 MCP server 与扩展，放开 skills / agents / hooks**。**它不是市场允许清单**，也**不等于「只用企业托管插件」**：要限制插件**来源**，得配合 **`strictKnownMarketplaces`** 一起用；已有的托管设置可以通过 `enabledPlugins` 要求或屏蔽指定插件。**目标很明确**：让批准的 MCP 工具与 canvas 通过**共享插件库**分发，而**不是一刀切关掉能力**。**可用性**：**GitHub Enterprise Cloud**，且成员持有企业或其组织发放的 **Copilot Business / Copilot Enterprise** 许可。⚠️ 三点：**公告没说「被拦下的自定义如何告知开发者」、也没说审计日志是否记录拦截**，这是落地时必须自己测的空白；**锁 MCP server 之后，个人写的 `.mcp.json` 会失效**，对重度自定义的团队是一次行为突变；它与 11-18 推的 8 个官方 connectors 是配套关系——**一边放官方连接器进来，一边把非官方入口关掉**，这就是企业侧这轮的主线。

- **[Snap 的 Easy Lens CLI：Claude Code / Cursor / Codex 能直接生成并发布 Snapchat AR 镜头](https://techcrunch.com/2026/11/18/snapchat-now-lets-developers-build-ar-lenses-with-ai-coding-assistants-like-claude-code-and-cursor/)**（**2026-11-18** 发布；免费，需 Snapchat 账号，入口 `easylens.snapchat.com/cli`，支持 Mac / Windows / Linux）：**它是「编码 Agent 变成分发渠道」的第一批实例**。**工作流**：在**同一个会话里**完成**搭 → 试 → 发**——从 **100+ 个 AR 积木**与 **50+ 个 AI 资产生成器**里组装，**渲染预览视频并推到你的手机**，再**发布到 Snapchat 并看表现**；出错可以让助手直接改、几分钟出新版本。**官方宣称为**：一个完整的小游戏**一天内从想法做到已发布**，**不手写代码**；支持**带排行榜的 Web Lens 游戏**、相机 Lens 与美颜效果。**面向三类人**：把浏览器小游戏移植成 Web Lens 的游戏开发者、导入自有素材的 AI 创作者、把营销素材转成 AR 的代理商与品牌。**规则不变**：内容审核与 Easy Lens 应用一致；**Lens+ Payouts 成员可分成**——Snap 称上个月付给 Lens+ 创作者 **180 万美元**（年化约 2,160 万）。⚠️ 四点：**「不写代码」是厂商口径**，复杂交互仍要理解 Lens 的构建块与限制；**免费不等于免审**，发布走同一套内容审核；**分成只对 Lens+ 成员开放**，别把它当成通用变现路径；Web Lens 与相机 Lens 的能力边界不同，把浏览器游戏移植过来要先确认输入与性能预算。
