### 🌐 语言与规范

- **[TypeScript 7.1 Beta](https://github.com/microsoft/TypeScript/issues/63703)**（2026-10-06）：7.0 最大的短板——**没有稳定的编程接口**——在 7.1 补上：Content Mapper、Emit、Language Service API 全部进入稳定面，Vue / Volar、Svelte、Astro 的 `@astrojs/check`、Angular 编译器以及 typescript-eslint 的类型感知规则终于可以迁移（目前多数仍通过 `@typescript/typescript6` shim 跑在 TS 6 上）。语言侧还新增 `es2026` 的 `lib` / `target`、`Promise.allKeyed` / `allSettledKeyed` 类型（TC39 Await Dictionary，Stage 3）、import attributes 的 `type` 参与模块解析、Source Phase Imports。官方计划 **7.1 稳定版 11-24**。[功能速览](https://www.sukerou.com/2026/10/typescript-71-beta-5.html)
- **[CSSWG 10-14 会议：mesh gradient 与 diffusion curve gradient 获接受](https://www.w3.org/2026/10/14-css-minutes.html)**（2026-10-14）：Amelia Bellamy-Royds 提出的两种新渐变类型进入 CSS 工作组决议——网格渐变（mesh）与扩散曲线渐变（diffusion curve），沿用部分 SVG 2 的语法思路，同时让 CSS 渐变可用于 SVG；语法仍在征集反馈。会议还接受了 **`@sheet`**（在一个文件里打包多个具名样式表，暂无浏览器实现），并讨论了 [css-navigation-1 中「按文档 URL 安全地设置样式」](https://lists.w3.org/Archives/Public/public-css-archive/2026Oct/0345.html)，目标是去掉自定义视图过渡里最后一点 JS。

### 🚀 框架与工具链

- **Cloudflare 收购 Deno 的后续影响**（2026-10-09 宣布）：Deno 团队（含 Ryan Dahl、Bert Belder）整体加入 Cloudflare Workers 团队，核心目的是把 Deno 的 **celld** 项目并入 **workerd**，让 Workers 可以自托管。代价是——**Deno 运行时只再维护一年**（每月 2.9.x LTS 修复，至 2027-10，不再加新特性），**Deno Deploy 6 个月后关停**，JSR 与 rusty_v8 转移到 Cloudflare 继续。社区已出现两个分叉：[Dodo](https://github.com/are-we-dodo-yet/dodo)（drop-in 替代，先把 `deno_graph` / `deno_ast` / `deno_lint` 等散落仓库合并进单仓）与 [Ende](https://ende.sh)（反方向：移除 Node 兼容、Deploy、KV、Jupyter，回到 Deno 原生路线）。[Simon Willison 的记录](https://simonwillison.net/2026/Oct/9/deno-is-joining-cloudflare/)｜[Socket.dev 分析](https://socket.dev/blog/deno-acquisition)｜[官方状态 issue #37030](https://github.com/denoland/deno/issues/37030)
- **[Bun 1.4.3：内置 `bun check` 类型检查](https://bun.sh/blog/bun-v1.4.3)**（2026-10-10）：把 `typescript-go`（TypeScript 7 的 Go 实现）移植进 Bun，读现有 `tsconfig.json`、支持 project references、吃满多核，只做检查不产出文件。官方基准比 `tsc 7.0.2` 快 **3–6.4 倍**、内存少 **2.2–4.9 倍**，通过 TS 7.0.2 全部 51,210 条 conformance 测试；`bun run/test/build --check` 均可调用。第三方实测（Scrydon 104 个项目）冷检查从 124.9s 降到 51–68s，但**增量热检查仍可能输给 `tsc`**。注意：若 `package.json` 里已有名为 `check` 的脚本，`bun check` 会执行该脚本而非内置检查器，需改用 `bun --check`。
- **[Panda CSS 2.0](https://panda-css.com/blog/panda-css-v2)**（2026-09-29 发布，10-16 起被 JSer.info 等集中收录）：编译器核心用 **Rust + Oxc** 重写（NAPI 绑定 `@pandacss/compiler`），提取速度提升 **15–37 倍**、watch 模式约 **360 倍**；同一份 Oxc AST 在 CLI / 打包器 / 浏览器 WASM 间复用。通过 source transform 与打包器集成后，`css()`、style props、recipes 在构建期编译成普通类名字符串，**样式运行时从产物中消失**。破坏性变更：ESM-only、Node 22+、`hooks` 移入 `plugins`、`createStyleContext` 拆分、CLI 命令重命名；新增 `panda doctor` / `analyze` / `debug`、`viewTransition()`、`positionTry()` 与排版 preset。
- **[Preact 11](https://preactjs.com/blog/preact-11/)**（2026-09-30，11.0.1 于 10-07 跟进）：六年「Road to Preact 11」的收尾，属于增量式大版本——**Hydration 2.0**、自动 ref 转发（不再需要 `forwardRef`）、`createPortal` 进入核心、依赖比较改为 `Object.is`、**ESM-only**（移除 CJS/UMD）、移除 `render()` 第三个参数。多数升级问题集中在类型上，官方提供 [v11 升级指南](https://preactjs.com/guide/v11/upgrade-guide)。
- **[Node.js 26.12.0（Current）](https://nodejs.org/en/blog/release/v26.12.0)**（2026-10-14）：`node:http` 新增 `websocketMask()` / `websocketUnmask()`（RFC 6455 掩码，主要面向库作者）；运行时 / 测试 / watch / 权限的**配置文件支持转为稳定**；`require(esm)` 继续推进；升级 SQLite 3.54.0、OpenSSL 3.5.9、npm 11.20.0。同日发布 24.22.0「Krypton」LTS。另注意：**10-21 有安全版本**（最高 HIGH），**10-28 Node 26 转为 Active LTS**。
- **[QUnit 3.0](https://qunitjs.com/blog/2026/09/27/qunit-3-0-0/)**（2026-09-27）：原生 ESM 分发、`before` / `after` 钩子可拿到 module context、默认超时改为 3 秒、多条旧警告升级为错误；要求 Node 18+，移除 PhantomJS / AMD / Bower，HTML Reporter 默认主题重做（即时渲染、更早暴露错误）。

### 🎨 浏览器与 CSS

- **[Firefox 158](https://www.firefox.com/en-US/firefox/158.0/releasenotes/)**（2026-10-13）：补齐三大引擎中最后一个缺口——**`calc()` 支持带单位的乘除**（如 `calc(100% / 3)`、`calc(var(--w) / var(--h) * 100%)`，无意义的 `calc(10px * 10px)` 仍非法），Chrome 140+ 与 Safari 26 早已支持。同时新增 **`corner-shape`** 及其全部 longhand、**`random()`** CSS 函数、`plus-lighter` 可用于 `background-blend-mode`。JPEG XL 默认启用（此前 10-16 已提过，此处不重复展开）。本次修复 **77 个 CVE**（30 High / 33 Moderate / 14 Low，无 Critical），含 24 个 use-after-free 与 8 个沙箱逃逸。
- **[Chrome 157 Beta](https://chromestatus.com/release-notes/157)**（2026-10-14 起 Beta，桌面版 157.0.8103.6 于 10-16；稳定版计划 **11-03**）：
  - **Android 端设备内 Language Detector API**：此前仅桌面可用，现下放到 Android，可离线识别文本语言。
  - CSS：**corner 简写属性**（一次性设置各角 `border-radius` / `corner-shape`）、**`text-overflow: <string>`**（自定义溢出省略字符串）、`position-visibility: anchor-valid`（ship `anchor-visible` / `anchor-valid`，弃用复数写法）、单轴滚动容器的 scroll snap。
  - **HTML-in-canvas 原语**：可自定义 HTML 渲染进 canvas 的方式（此前的 Canvas UI 组件库正建立在这套实验 API 上）。
  - 其他：SVG 在 `<object>` / `<embed>` 中支持 `object-fit` / `object-position`；替代 `insertAdjacentHTML` 的新 HTML 插入/流式方法；实验性 **Decisions API**（`window.DecisionModel`）。
- **Baseline 视角的「十月新特性」需要降温**：根据 [web-features explorer](https://web-platform-dx.github.io/web-features-explorer/browsers/chrome/) 的记录，Chrome 155 起新上的 **JPEG XL、`symbols()`、`text-decoration-skip-spaces`、文本导入属性**目前都**没有**进入 Baseline——分别被 Chromium / Safari / Firefox 的另一侧阻塞。换句话说，「Chrome 支持」不等于「可以放心用」，选型前仍应查 webstatus.dev 或 BCD，而不是只看某一家发布说明。

### 🤖 AI 与开发

- **[Reflection AI 开源 Beam：501B 编程 Agent 模型](https://reflection.ai/blog/beam-is-available)**（2026-10-16，Apache 2.0）：自家首个开放权重模型，MoE **501B 总参数 / 23B 激活**、约 **1M 上下文**、纯文本，提供 BF16 / FP8 / NVFP4 与投机解码 drafter。训练重点在「少花 token 的推理」——用 RL 惩罚冗余输出，面向 GitHub issue 修复、代码维护与长时工具调用。发布即有 40+ 家部署伙伴（AWS SageMaker / Trainium3、Azure、CoreWeave、Databricks、Cloudflare、Ollama、LM Studio 等），并配套开源 CLI Agent harness **Mirror**（Python 前端 + Rust 核心），也测试过 Pi、OpenCode、Hermes。Artificial Analysis 给出的 Intelligence Index 为 **30**，在开源模型中约第十、美国开源模型中仅次于 Meta Muse Spark Open（39）；AutomationBench-AA 48.5%，但 Terminal-Bench 4.0 仅 **3.0%**，长程编码仍是短板，官方主打的是 token 效率（约 26k 输出 token/任务）。
- **[Perplexity 开源 Agent 沙箱 SPACE](https://github.com/perplexityai/space)**（2026-10-15，Apache 2.0）：Sandboxed Platform for Agentic Code Execution，Rust 编写、HTTP + SSE 接口，每个任务一个 **Firecracker microVM**，凭据与出网策略放在 VM 外控制；支持 pause / resume / clone / snapshot（最长保留一周）。自 2026-07 起承载所有 Perplexity Computer 会话（每天数百万个沙箱），启动比原商业方案快 3–5 倍。安全测试中让多个前沿模型尝试越狱：**108 次 VM→宿主逃逸全部失败**，但在允许部分出网的场景下有 **11/54 次网络策略绕过**（DNS 欺骗 / CDN 共享 IP），已用源 IP 校验修补。内置 **E2B 兼容层**，可直接跑 E2B Python SDK；Akamai、CoreWeave、Crusoe 已提供托管或部署支持。
- **NVIDIA Nemotron 3.5 Bolt + RTX Spark 开卖**（2026-10-15 / 10-16；此前 10-16 只提到同系列 Super VL，属新进展）：**74B-A9B** 的混合 Mamba-2 / Transformer LatentMoE，经「Star Elastic」从 120B 模型蒸馏后量化到 **2.0625 bit/元素**，塞进 **24GB** 显存，**256K 上下文**，配 LiLiCorr 投机解码 drafter 可达约 84 TPS；llama.cpp / vLLM / Ollama / LM Studio 均可跑，权重与训练配方按 OpenMDW-1.1 开放。10-16 起搭载 RTX Spark 的笔记本（微软、惠普，$2,599 起）与 $5,999 开发者主机在美开卖，JetBrains **Junie Local** 宣布 Day-0 支持（约 55 tok/s）。[模型页](https://research.nvidia.com/labs/nemotron/Nemotron-3.5-Bolt-24GB/)｜[NVIDIA 技术博客](https://developer.nvidia.com/blog/code-test-and-deploy-on-one-machine-with-nvidia-rtx-spark)
- **[WordPress 官方 MCP Adapter 插件](https://wordpress.org/plugins/mcp-adapter/)**（v0.7.0，2026-10-02 进入 WordPress.org，本周安装量超 4 万）：把 WordPress 的 **Abilities API** 桥接到 MCP，将注册的 ability 转成 MCP 的 tools / resources / prompts，本身不提供 AI 功能。支持 MCP 修订版 **2025-11-25** 与 **2026-07-28**（无状态 / 无会话生命周期）、HTTP 与 STDIO 两种传输；ability 默认私有，需显式 `meta.public` / `meta.mcp.public` 才暴露。要求 WP 6.9+ / PHP 7.4+，接入点为 `/wp-json/mcp/mcp-adapter-default-server`。官方定位仍是实验性 canonical 插件，不进核心。[GitHub](https://github.com/WordPress/mcp-adapter)
- **MCP 企业侧本周集中落地**（10-13 前后）：[Notion 3.8](https://test.aiagentstore.ai/ai-agent-news/daily/2026-10-14) 加入第三方 Agent 的 MCP 接入、Skills API 与 MCP 治理；**Shopify Shop MCP** 开放商品搜索、购物车与 Shop Pay 结账；**Workday Trusted Agent Platform** 用 MCP 暴露 HR / 财务数据的 headless 访问。加上 WordPress 的官方适配器，MCP 正在从「开发者玩具」变成 CMS / 电商 / ERP 的标准接入层。

### 📚 好文精选

- **[The best coding agent still fails 42% of maintainer-style checks](https://daehnhardt.com/blog/2026/10/16/ai-weekly-signals-frontiercode-best-agent-fails-42-percent-maintainer-reviews/)**（2026-10-16）：基于 FrontierCode 1.1 基准的拆解——Claude Opus 5.5 以 52% 领先，但**约 42% 的尝试至少挂掉一项阻断性检查**（编译、测试、规范、范围蔓延等）。结论不是「Agent 不行」，而是「维护者式的验收标准」和「能写代码」是两件事，CI 门禁仍然不可省。
- **[Why don't more developers "use the platform"?](https://javascriptweekly.com/issues/805)**（JavaScript Weekly #805，2026-10-06）：从 Popover、Invoker Commands、Anchor Positioning 等原生能力出发，讨论为什么「平台已经能做」和「开发者真的会用」之间仍有巨大鸿沟——兼容性数据、调试体验、跨浏览器差异、组件库惯性，缺一不可。与 10-16 推过的 dnd-kit / Nolan Lawson 两篇是同一条讨论线的延续。
- **[We checked 554 web features. 15 are gated by the OS, not the version](https://reptile.haus/journal/caniuse-os-gated-web-features-browserslist-baseline-2026/)**（2026-10-14）：作者对照 web-features 3.42.0 后发现，**554 个特性里有 15 个实际受操作系统门控**（如 `zstd`、JPEG XL、iOS 上的 Fullscreen / MSE）。Baseline 在 2026 年移除了 OS 级 caveat，于是「Baseline newly available」不再等于「每台设备都能用」——做 browserslist 与降级策略时必须另查。
- **[Thank You, Deno](https://app.hncompanion.com/item?id=50112331)**（HN 讨论，2026-10 上旬）：收购消息下最值得读的一串讨论，核心不是情怀，而是「一个开源运行时被大厂收编后，社区到底能不能接住」——Dodo 的仓库整合路线、Ende 的「去 Node 兼容」路线，以及把项目交给基金会的提议，都在这里交锋。
