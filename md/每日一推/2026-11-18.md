- **[Vite 8.4.0-beta.1：`server.fs.strict` 多了 `'extended'`，`optimizeDeps.rollupOptions` 被直接删掉](https://github.com/vitejs/vite/releases/tag/v8.4.0-beta.1)**（**2026-11-16** 发布；当前稳定版仍是 **8.3.8（11-11）**；注意这与 11-16 那期推的 **8.3.7 安全补丁**是两条线）：**三件会直接影响你配置的事**：**① `server.fs.strict` 新增第三个值 `'extended'`**（#23972）——在原有白名单之外，**连插件 `load` 钩子加载的模块也要过检查**（以 `\0` 开头的虚拟模块除外），明显是冲着 **monorepo / pnpm 把 `node_modules` 软链到项目根之外**的场景；它是**可选开启**，但一旦开启，**原本能读到的路径可能被拒**，得把它们补进 `server.fs.allow`。配套还加了 `environment.addSafeModule`（#23974，让插件登记「源码里引用了、但 import 分析漏掉」的模块）、**按 environment 分开的 safeModulePaths**（#23973）与**从 HTML 登记引用**（#23169）。**② `optimizeDeps.rollupOptions` 被移除**（#23760）——注意它和 `optimizeDeps.esbuildOptions` 不同：后者会**自动转换**成 `rolldownOptions`，前者是**直接删掉**，写了也不报错、**静默失效**，升级前先 grep 一遍。**③ `css.devSourcemap` 改名**为 `dev.sourcemap.css`（#23765）。**另有几项值得顺手收**：**worker chunk 进入构建清单**（#23699）、构建清单挂到 build environment 上（#23292）、CSS 预加载重试（#23710）、**不再产出空 CSS 文件**（#24059）、CSS 的 `url()` 支持子路径导入（#23869）、`--configLoader` 稳定且 `runner` 弃用（#23714）、SSR 的 bundled dev 模式（#21626）、WASM source-phase imports（#22675）、preview 压缩输出 wasm（#24051）。⚠️ 三点：**这是 beta**，`--configLoader` 这类「稳定化」也仍可能变；**`fs.strict: 'extended'` 是收紧**，本地开发没问题、CI 里用软链的 monorepo 最容易踩；另外**别把这条和 11-16 的安全补丁混着升**——补丁该今天打完，beta 想试再单独开分支。

- **[《The harness (still) matters》：同一模型换个壳，成本能差 5 倍，最佳壳还会随模型变](https://github.com/tmustier/harness-benchmarks)**（仓库与报告在 **2026-11 中旬**持续更新，The New Stack / DevOpsChat 在 **11-17** 集中报道 FrontierHarness Eval v1.1）：**这篇的价值是把「壳（harness）」从玄学变成可测的量**。**核心结论**：**没有一份公开研究能找到在所有模型、所有任务上都最优的 harness**；**最强的证据是 FrontierHarness Eval v1.1**（Runta + Baseten）——**22 个 harness × 5 个模型 × 62 个任务 × 4 次尝试 = 27,280 次运行、830 亿 token**，结果是**约 64% 的推理花费花在失败或超时的运行上**，而**唯一与「每个成功任务的成本」稳定相关的因素是 agent 的步数**。**最能抄走的一句**：**最佳 harness 会随模型变化**——Codex CLI 配 GLM-5.3 时排第 1，配 Kimi-K3 时掉到第 16。**方法论也值得学**：该元综述只把「固定模型与推理强度、只换 harness 或运行时组件」的对比算作品质证据，**单组件消融单独标注**，不和整壳对比混在一起。**这和今天 GitHub 那条是同一件事的两面**：前者是厂商给自己的 CLI 做对照，后者是第三方把 22 个壳放在一起。⚠️ 四点：**62 个任务的样本不大**，结论按方向看；**「64% 花在失败上」高度依赖超时设置与重试策略**，不是所有流水线都这么差；**元综述的结论受限于它收录的研究口径**，不同来源的任务集不可直接相加；落到工程上就两条——**换模型时重新挑 harness**，以及**把失败 run 的 token 计入预算**（这也是为什么 11-15 那期的 TestMu 报告说「验证」比「生成」更该花钱）。
