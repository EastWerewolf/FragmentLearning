### 🎨 浏览器与 CSS

- **[macOS 27.2 beta 的 Safari 支持手势拖拽标签页，触屏 MacBook 的影子越来越清楚](https://www.ithome.com/1/013/280.htm)**（2026-10 下旬，beta 3 / beta 4；[iSpazio 原文](https://www.ispazio.net/2286703/macbook-pro-touchscreen-macos-27-2-beta-4-finder-safari)）：泄露出来的改动是**标签页拖动时会抬起并缩放**（典型的触屏拖拽反馈），**长按直接弹上下文菜单**（不再先问 Siri）；同时在照片、备忘录、快速查看和 Dock 里都能找到类似的触摸/长按代码。这本身是系统层的事，但和 Web 侧有两点关系：一是**触屏 Mac 一旦成真，`pointer: fine` 的假设要重写**，hover 依赖型的交互要准备触屏退化路径；二是这类「浏览器手势」通常先在 Safari 落地，其余引擎跟进要看是否有标准提案。⚠️ 现有证据是 beta 里的字符串与动画，苹果未确认硬件，传闻指向 **10-28** 的发布会。
- **[Chrome 157 Beta 说明：`corner` 简写把 `border-radius` 和 `corner-shape` 合成一行](https://developer.chrome.com/blog/chrome-157-beta)**（Beta 2026-10-15 起，稳定版 **2026-11-03**）：离稳定还有一周多，值得提前看的是四项——**`corner` 简写**及其逐角子简写，能同时设圆角与**形状**（呼应 10-21 推过的 `corner-shape` / Interop 2027 议题）；**`position-visibility: anchor-valid`**，锚点元素隐藏/失效时让 popover 自动退场；**`text-overflow` 接受 `<string>`**，省略号之外可以用任意字符串；以及 **`object-fit` / `object-position` 开始作用于 `<object>` / `<embed>` 里的 SVG 文档**。安全侧一条要留意：**Background Fetch 开始强制 CORS**，此前借它绕过 CORS 与本地网络访问检查的用法会失效。另有 `Sanitizer` 的 `javascriptURLs` 选项、Service Worker 里暴露 `ProgressEvent`、Android 上的 Language Detector API。单复数 `anchor-visible` / `anchor-valid` 在这一版收敛，写旧写法的要改。

### 🤖 AI 与开发

- **[Nanbeige4.3-33B：33B 稠密智能体编程模型，Apache 2.0、512K 上下文](https://huggingface.co/Nanbeige/Nanbeige4.3-33B)**（2026-10-24 上架 Hugging Face，含 Base 版）：BOSS 直聘旗下南北阁实验室的作品，走的是和当下主流相反的路——**33B 稠密（Llama 式）而不是 MoE**，512K（524,288）上下文，思维链默认开启，工具调用走 XML 格式。自报成绩（最高思考档、同 harness）对 Qwen3.8-27B：**Terminal-Bench 2.1 80.9 vs 73.0**、DeepSWE 65.5 vs 42.5、Automation Bench 54.2 vs 38.3、AIME 2026 95.2；输的两项是 **SWE-Bench Pro 60.3 vs 61.7** 与 GDPval 84.8 vs 86.4，**Terminal-Bench 4.0 只有 23.8**（新一代基准上明显掉队）。定位说得很直白：**它是个「教师模型」，之后蒸馏出 Nanbeige4.3-3B 做端侧**。部署成本要算清楚——BF16 约 **66GB**，长上下文 KV cache 约 112GB，官方建议 **4 卡张量并行**；4-bit 量化约 20GB。⚠️ 全部为自报、无第三方复现，MarkTechPost 指出它列的竞品 SWE-Bench Pro 数值疑似与对方模型卡对调，引用前先自己跑一遍。
- **[AWS 开源 Infinity：让 Agent 在等工具时「睡过去」的 Rust 运行时](https://aws.amazon.com/cn/blogs/opensource/introducing-infinity-a-runtime-for-extreme-agent-concurrency/)**（2026-10-23，Apache 2.0，与 UC Berkeley 的 Hydro 项目合作）：核心机制不复杂但影响很大——**把每次工具调用当成一个 await 点**（类似 Rust 的 stackless coroutine）：Agent 发起调用后，运行时派发请求、**把会话历史落盘、然后把 Agent 从内存里整个丢掉**；恢复时按「装载历史 → 一次模型补全 → 持久化输出 → 最多派发一个工具调用 → 退出」的切片执行。官方数字：**空闲 Agent 约 100KB**，所以 **8GB 内存能放约 7.5 万个**；压测用模拟模型 + 内存存储、单核（AMD EPYC 9R14）跑 **8 万个 Agent × 20 轮 = 320 万次补全**。还有一套「step mode」的无状态部署参考（SQS FIFO + 每步一个 Lambda + Aurora DSQL 存历史 + DynamoDB 去重 + EventBridge 定时），号称**等 3 天 CI 的 Agent 消耗零算力**。为了在「一次工具调用只回一个结果」的约束下送异步事件，它引入了**合成工具调用**（`receive_event__injected`），另有 `spawn_thread` / `report_to_parent` 做子 Agent、一个 MCP 兼容层和示例编码 Agent（Infinity Code）。⚠️ 官方自评「早期研究版本」，数字是 AWS 自己的、未独立复现；未解问题包括乱序事件的处理、调度与优先级、长生命周期 Agent 树的历史压缩、以及无状态下如何证明事件真实性。
- **[Ollama 支持语音合成：`ollama run phonon "..."` 直接朗读](https://ollama.com/blog/speech-models)**（2026-10-24，需 Ollama v0.40.11+）：首个语音模型是 Gradium 的 **Phonon** 家族——基础版 **31M**（Apache 2.0），40M 的多语言版（`phonon:40m-fr / -de / -es / -pt / -multilingual`）是 **CC BY-NC 4.0，仅限非商用**；**暂不支持中文**。可用 `--voice` 或 API 的 `voice` 选音色（Zoey、Easton、Freya、Hadley、Harper、Sterling、Toby，默认 `default`）。**目前只有 macOS Apple Silicon，走 MLX 加速**，Windows / Linux 官方口径「即将支持」；官方称在 M5 Max 上比 Gradium 自家运行时快约 **35%**，WER 与 HF Transformers 持平。实用的用法是把对话输出管进 TTS：`ollama run gemma4 ... | ollama run phonon`，重定向即可存 WAV。API 走 **OpenAI 兼容的 `/v1/audio/speech`**，24kHz 单声道、默认 WAV 或裸 16-bit PCM、边生成边流式返回，输入上限 **4096 字符**。对做前端语音交互的人，这意味着**本地全链路（LLM + TTS）不再需要额外服务**。
- **[Claude Platform 以「Anthropic 托管」形态整体上 Google Cloud](https://claude.com/resources/articles/claude-models-on-google-cloud-anthropic-managed)**（2026-10-22 发布，Google Cloud 侧 10-23 公告）：和 10-23 推过的「OpenAI 模型进 Google Cloud」正好反向。关键是**不是缩水版**——**功能与原生 Claude Platform 对齐，新特性 / beta 同日上线**；用**现有 GCP IAM 凭据**接入、**单张 GCP 账单**、消耗可抵扣既有云承诺。两种形态要分清：**Anthropic 托管**（Anthropic 是数据处理方，功能全、首发即用）vs 既有的**Google 托管**（Google 是数据处理方，有区域驻留、VPC-SC、CMEK、Model Armor / Agent Engine 集成）。落地的东西不少：**Claude Managed Agents（beta）**、代码执行、computer use、agent skills、Advisor（beta）、Files API、citations、web search/fetch、**MCP connector（beta）**、prompt caching、batch，以及 Claude Console；**Opus 5.5 的 Fast Mode 也在这里 GA**（输出约 2.5× 快，$8 / $40 每百万输入输出）。模型面是 Fable 5.1 / Opus 5.5 / Sonnet 5.5 / Haiku 5.5，端点目前 **US 与 Global**。对企业的实际含义：**「模型」和「云承诺」的绑定又紧了一层**，已经在 GCP 上做采购的团队可以少开一个供应商。

### 📚 好文精选

- **[HandsOn：清华团队用 66 个任务给「灵巧手」量了一次底](https://eu.36kr.com/zh/p/4041153787892617)**（arXiv 2610.26765，2026-10-25 中文报道）：可组合仿真平台，5 种机械臂 × 6 种灵巧手 × 约 200 种刚体 / 关节 / 可变形资产，**66 个人工验证任务 + 1.8 万条人类遥操作示范（约 56 小时，LeRobot v2.1 格式）**；分成有示范的 **Core-50**（测执行）和无目标任务示范的 **Transfer-16**（测泛化与技能组合）。结果很难看但很有价值：8 个多任务策略里最好的 **Core-50 成功率 29.1%**，**Transfer-16 上所有受训策略均低于 1%**；GPT-6 零样本经 `move_eef` 接口跑 660 次，Core-50 5.2%、Transfer-16 1.9%；工具使用与精细装配只有 2–3%。代码与数据已开源。和前端无关，但它是「**给一个能力造一把诚实的尺子**」的样本——比又一张 SOTA 表更有信息量。
- **[用 TypeScript 复刻 Infinity 的「挂起式 Agent」](https://dev.to/bobbyhalljr/aws-open-sourced-infinity-lets-build-a-tiny-agent-that-sleeps-between-tool-calls-in-typescript-3mja)**（2026-10-24 前后）：跟着 AWS 的发布读源码不如看这篇——作者用一个几十行的 TypeScript 例子把核心思想落地：**不要把 Agent 当成一个常驻的 while 循环，而要当成「一串可以随时中断的步骤」**，状态外置、每步只做一件事。对正在自建 Agent 编排的人，这篇能直接回答一个具体问题：**你的 Agent 在等外部工具时，到底占不占内存？**
