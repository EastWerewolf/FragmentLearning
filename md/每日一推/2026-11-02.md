### 🚀 框架与工具链

- **[Rspack 2.3：解析器换到 SWC Next，大项目构建内存掉 27%](https://rspack.rs/zh/blog/announcing-2-3)**（2026-10-29，`@rspack/core@2.3.0`）：这一版的主角不是新功能，而是**把 JS 解析器整体迁移到 SWC Next**——这是 SWC 团队与 Rstack 团队合做的下一代编译器，基于 Yuku 风格的解析器架构 + 扁平 ESTree AST，官方称原生解析比 SWC 快至多 **3 倍**、走 JS API 快至多 **10 倍**；Rspack 把解析器**和所有 parser 插件**一次性迁完，替换掉旧的 `swc_experimental_*` 栈（SWC Next 0.2.0 → 0.3.1）。实测数字分三层：**解析**上 three.js 从 23ms → 20ms（指令数 −24%）、React 10k 从 207ms → 193ms；**内存**上真实大项目峰值 RSS 从 **28.3 GiB → 20.5 GiB（−27%）**，dev server 稳态 RSS −35%，并新增基于 `allocative` 的内存快照便于排查；**整体构建**比 2.2.0 快约 **5%**，部分大项目可到 20%。功能侧两个值得用的：`splitChunks.dedupDepth`（生产默认 1）与 `splitChunks.minRemainingSize`，用来压掉重复模块和碎片小 chunk；另有实验性缓存支持**按 loader 缓存 transform**（1 万个模块的 babel-loader 场景快至 5.7 倍）、CSS 独立入口与 CSS externals。⚠️ 范围要看清：SWC Next 目前**只覆盖解析与语义分析**，`swc-loader` 与压缩仍走稳定版 `swc_core`，用 JS 写的 SWC Next transform 插件要等 **2.4 / 2.5**。

### 🤖 AI 与开发

- **[OpenAI 确认：12 月起 ChatGPT 与 Codex 共用一个额度池，按 token 计](https://help.openai.com/en/articles/20001625-understanding-chatgpt-and-codex-usage-limits)**（2026-11-01 官方帮助中心 + 订阅邮件）：这条会直接改掉很多人的日常体感。**Plus、Pro、Business 三档**从 12 月起**共享** ChatGPT 与 Codex 的用量；官方给的理由是「把 ChatGPT Work 的 Agent 能力并进主聊天」，而 Work 与 Codex 本来就是一个池子，所以等于**把日常聊天也并入同一个池**。三个关键机制：**一、计量单位从「消息条数」变成 token**，消耗取决于模型选择与任务复杂度；**二、Instant 聊天不占额度**（基本维持不限量）；**三、用完后的选择是等重置、升级、或买 credits**，Settings → Usage 里能看合并后的剩余量与重置时间。⚠️ 目前**还没公布**各档的具体 token 额度、12 月的确切日期，以及按模型/功能的完整计费表。两条背景一起看更清楚：10-29 OpenAI 刚把 Pro 100 / Pro 500 / Business Premium 的 Work 与 Codex 额度翻倍并撤回了 Pro 200 的削减，但**把 Plus 排除在外**，社区当时就有意见；这次合池又轮不到 Plus 享受翻倍，等于「额度收紧 + 涨价预期」同时落在最便宜的付费档上。另有一条容易忽略的收紧：新增**设备/账号数量上限**，同一设备上能用的付费账号数被限制（Go、Plus、Pro 各档），超了会提示 "Device limit reached" 或被登出（Business / Enterprise / Edu / Free 不受限）。
- **[美团发布 LongCat-2.5：1.6T 参数、原生多模态、全程国产算力](https://longcat.ai/blog/longcat-2.5)**（2026-11-02）：在「参数效率」被反复讨论的这一年，这条走的是相反的路线——**把规模做满，同时把训练与推理的工程问题在国内硬件上解掉**。规格：总参 **1.6T** 的 MoE，每 token 激活约 **480 亿**；原生多模态，把视觉信号转成多层级的离散 token 与文本统一处理（因此能读交互式网页、3D 页面，并号称支持 Visual Coding）；中训练阶段**最长 100 万 token 序列**、累计数万亿 token；大规模长程 RL 强化智能体编程与端到端工程能力，另外重点强化了商业分析（如自动搭渠道利润表）。工程侧的两个数字更实在：针对国产卡**显存 <80GB** 的现实，用超节点并行 + 双重分片 FSDP，把长序列 SFT 单卡吞吐相对 DDP 基线拉高 **86%**；推理用 **W4A4** 量化，相比 W8A8 INT8，Prefill / Decode 吞吐分别 **+43.3% / +42.77%**，TTFT / TPOT 降 **15.91% / 19.72%**。评测（自报）：Terminal-Bench **v2.1 88.4 / v4.0 38.5**（v4.0 略高于 GPT-5.6-Sol 的 37.3）、BrowseComp 91.9、MCP Atlas 83.1、Vision2Web 78.6、MathVision 96.5，整体落在 Claude Opus 4.8 与 Opus 5 之间、部分项超过 Opus 5。获取方式：官网与 API 已开放，**GitHub / Hugging Face 权重「即将上线」**。⚠️ 全部为自报口径，权重未放出前无法复现；「国产算力」的具体芯片型号官方未逐一说明。
- ⚠️ **[两家下一代旗舰在 24 小时内同时「泄露」：GPT-6.2 Astra 与 Claude Mythos 5.5](https://www.jiqizhixin.com/articles/2026-11-02-2)**（2026-11-01 晚 ~ 11-02，**均非官方发布，未独立验证**）：之所以记一笔，是因为两边的「证据形态」都很有意思。**OpenAI 侧**：开发者在调试 Codex 时抓到的请求里出现了 `gpt-6.2-astra` 的 model 字段，账单数据显示新版已吃下约 **19.8%** 的真实流量（旧版 80.2%）——也就是说**灰度已经在跑**，只是没做发布。传言称原定的 GPT-6.1 Astra 因内部安全测试出问题被叫停、回炉后直接跳到 6.2，Codex 底层也为长时间自主运行重写过。**Anthropic 侧**：`anthropic.com/claude/mythos` 页面的 HTML 源码里出现 **6 处 "Mythos 5.5"**（正文仍写 5.1），随后被移除；更硬的间接证据是开源项目 **LiteLLM 的价格表曾在 10-13 加入 `azure_ai/claude-fable-5-5`（$10 / $50 每百万 token），10-14 又以「Azure 并未上架」为由撤下**。⚠️ 两处保留：**源码泄露的说法本身有冲突**——有媒体在两小时后重新抓取同一页面，只看到 43 次 "Mythos 5.1"、0 次 "5.5"，因此「页面是否真的对外提供过这段源码」无法确认；「53 分钟攻破 Linux 内核拿 root」「一句话生成 3D 游戏」这类配套故事只有转述，按传闻看待。对日常选型的人，实操建议只有一条：**别按泄露版本排期**，但可以留意 11 月中下旬这两个时间点。
- **[Grok API 从 11-07 起默认给文本输出加隐形水印](https://docs.x.ai/developers/advanced-api-usage/watermarking)**（2026-10-31 文档更新，11-07 生效）：如果你在做「AI 生成内容 → 展示到前端」的产品，这条会改变你对外承诺的措辞。范围很广：**7 个模型**（grok-4.7 / 4.6 / 4.5 / 4.3 / 4.20-reasoning / 4.20-non-reasoning / 4.20-multi-agent）、**全部端点**（Responses API 与 Chat Completions）、覆盖普通文本、结构化输出与 **tool call 的参数**。机制是**生成时的统计偏置**——轻微影响 token 选择，**不插入隐藏字符、不加标记、不改响应格式**，所以调用代码不用改；唯一可见的变化是响应头多一个 **`x-watermark: true`**，检测本身是统计性的（长文本更可靠，结果为「有水印 / 无 / 不确定」），检测 API 需要申请。**退出方式**：仅团队管理员可操作（Console → Team settings → Model output watermarking，可全员开 / 全员关 / 自定义），约 5 分钟生效，但要用它就得**确认符合法律例外并对标注责任负责**，部分模型可能被锁定为开启，所有变更进审计日志。官方理由是遵守欧盟 AI Act，⚠️ 而 xAI 目前并未签署欧盟的透明度行为准则；「不影响质量与速度」是官方自述，无第三方验证。
