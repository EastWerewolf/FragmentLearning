### 🤖 AI 与开发

- **[MCP 两周年：Skills over MCP 进公测，Tasks 与 Elicitation 转正，文件直传在路上](https://www.aichatdaily.com/ai-tools/anthropic-lets-mcp-servers-ship-skills-claude-tasks)**（**2026-11-24** 由 Anthropic 与 MCP 博客发布，11-25 媒体铺开；协议现由 **Agentic AI Foundation** 托管）：**这是 MCP 从「能力提供者」变成「行为规范者」的一步**。**① Skills over MCP（公测）**——MCP server 可以在工具之外**附带 `SKILL.md` 与可选附件**（领域最佳实践、多步工作流、账号 / 组织专属的打法），**按需加载**、随 server 更新，不用单独安装。早期接入的是 **Shopify**（设计 / 更新商家店铺）、**HubSpot**（客户 onboarding）、**Atlassian**（组织上下文分析），**Carta**（股权文书）在路上。**开关**：Pro / Max / Ultra **默认开**，Team 要管理员打开，Enterprise「即将」。**② Tasks（GA）**——server 可以返回一个**持久任务句柄**，把长任务或整段 agent 循环放后台跑，Claude 之后凭 **task ID** 取结果、可恢复；ZoomInfo 是早期用户。**注意取消是协作式的**：server 没有义务真的停下来。**③ Elicitation（GA）**——server 可以**在执行中途暂停**，用表单或链接向用户确认；Supabase（付费项目的破坏性 SQL）、Railway（删服务）、GitHub（删仓库前要手打仓库名）是典型用法；**规范明确禁止索要密码、API key、token 或支付凭证**。**④ 文件直传**——Claude 把 PDF / 表格 / 图片**直接交给 server**，绕过上下文窗口，「即将推出」。**生态数字**：SDK 月下载 **7 亿+**、Claude 侧 **10,000+** 个 MCP connector、多 server 场景下 **tool-search 懒加载把上下文占用砍掉 85%+**。⚠️ 四点：**skills 是「往你的上下文里塞指令」**，第三方 server 因此多了一条提示注入路径——规范用的是**对 skill 文件做 SHA-256 尺寸 / 摘要校验、与已批准清单比对、禁止预取**，但这是「缓解」不是「免疫」；**Enterprise 被刻意押后**，说明官方自己认为这块还没收敛；**Tasks 的取消不保证**，把它接进「可中断」的业务流程前要自己兜底；**Claude Code 侧要 2.1.331+**，且**云会话、一次性 CLI、GitHub Actions、Agent SDK 都还不支持**。

- **[Claude Code 2.1.332：斜杠菜单里出现 `server:skill`，新增 `PreSkillShellCommand` 钩子](https://code.claude.com/docs/en/changelog)**（**2026-11-25** 发布；紧接 11-24 那期推的 **2.1.331**，隔一天）：**它就是上一条 MCP 公测的客户端落地**：**MCP server 带来的 skills 现在以 `server:skill` 的形式出现在斜杠菜单里**，其它 skill 保持原名——好处是**来源一眼可见**，坏处是**同名 skill 不会再互相覆盖**。**新钩子 `PreSkillShellCommand`**：在 skill 或命令加载时，**可以拒绝其中的内联 shell 命令**——这是给「第三方 skill 里夹带 `rm -rf`」准备的闸门。**注意兼容性**：在 **2.1.331 或更早**的版本上写这个钩子名，**会触发启动对话框**（旧版本不认识它）。**修复集中在 MCP 的稳定性**：**本地 MCP server 输出吵**导致的卡死、**被中断的 SSE MCP 事件流**、**Read / @-mention / 压缩在命名管道上永久挂起**（现在 **20 秒后失败**，而不是一直等）；另有 Code Mode、Remote Control 与 VS Code 的一批修复。⚠️ 三点：**skill 从「本地文件」变成「server 下发」之后，审计对象也变了**——`PreSkillShellCommand` 能挡 shell，挡不住 skill 正文里的指令；**`server:skill` 的命名让「谁提供的」可见，但也让菜单变长**，skill 多的团队要做收敛；**一天一版**，2.1.331 的插件市场 11-30 默认自动更新那条仍然有效。

- **[Anthropic 把 Enterprise Frontier Safeguards 开进公测：跨请求监控 + 零数据留存](https://claude.com/resources/articles/zero-data-retention-with-enterprise-frontier-safeguards)**（**2026-11-23** 公测，9 月首次公布；私有测试方包括 **Bridgewater、Salesforce、Stripe、Cisco、Wells Fargo**，称与 100+ 客户共建、其中约四分之一是 Fortune 100）：**它补的是「单请求分类器看不见的攻击」**：把恶意操作**拆成多个单独看都无害的请求**，是 9 月那份威胁报告里针对约 50 家组织的 agent 攻击手法。**EFS 的做法**：**跨多个请求做自动安全监控**，命中后生成 **Safety Case**（危害类别、状态、被标记的对话 ID，**不含原始输入 / 输出**），通过**客户自己的云存储或 API** 交付，可接 SIEM。**零留存（ZDR）怎么成立**：**存储是客户自带的 S3 / GCS**，输入输出写进去后**立即从 Anthropic 侧删除**；**没有人工审阅输入输出**、**不用于训练**；加密密钥、访问策略、审计日志都在客户手里。**可用范围**：Claude Platform、Claude Platform on AWS、Amazon Bedrock、Claude on Google Cloud，**Microsoft Foundry 计划中**；**Anthropic 不收费**（客户自付存储与算力）。**排除项要记**：代码执行容器、Files API 上传、Batch API 结果、Claude Managed Agents 会话、HIPAA 模式工作区。**配套义务**：**Safety Case 要在约 7 天内调查**，否则可能失去访问权。⚠️ 四点：**它是「监控」不是「阻断」**，Safety Case 出来时动作可能已经发生；**ZDR 的前提是你自己搭存储与 SIEM**，没有这套基础设施的企业等于用不上；**排除项正好覆盖「最危险的那几类」**（代码执行、文件、批处理、托管 agent），别把它当成全覆盖；这是 Anthropic 对 **Fable 5 那套 30 天留存**引发的企业反弹的回应，**条款仍可能随公测调整**。

### 📚 好文精选

- **[ShellBench：5.3 万次运行告诉你，最好的 Agent 也只完成 62.5% 的日常任务，15.7% 的运行违反安全要求](https://arxiv.org/html/2611.32946)**（**2026-11-24** 由 **OpenClaw Foundation** 联合 Parsewave、Hugging Face、Red Hat、UC Berkeley 发布；arXiv:2611.32946；任务取自 **1000 万+** 匿名真实 agent 交互）：**它是这半年里最「不客气」的一份 agent 评测**，因为它**同时给 harness、配置和模型打分**，而不是只测 LLM。**规模**：**100 个任务**、**12 个模型 × 5 个 harness**（Claude Code、Codex CLI、Hermes、OpenClaw、Pi）= **53,100 次评测运行**；任务提示中位数 **43 个词**、工作区中位数 **188 个文件**——都是「日常活儿」的形状。**结果**：**GPT-6 Astra 62.5%**、**Claude Fable 5.2 61.9%**、**GPT-6.1 Sol 61.4%**；**DeepSeek V4.1 Flash 与 Meta Muse Wonder 1.0 约 39.7%**。**安全性是最该看的一段**：**全部 53,100 次运行里 15.7% 至少违反一条安全要求**；即使在**通过全部正确性标准**的 26,151 次里，**仍有 2,589 次（9.9%）违反了安全检查**。**具体失败**：**孩子接送时间安排错了 79.5%**、**建议了重复 / 错误的发票付款 40.3%**、**没有扣住敏感的银行上传 token 18.6%**。**一致性**：GPT-6 Astra **三次里至少一次成功 75.1%，三次全成功只有 48.8%**。**「模型 vs 壳」的结论和 11-18 那期一致、但更量化**：**模型之间的中位差 45.7 个百分点，壳之间只有 6.2 个百分点**；而且**模型越强，壳越重要**（Astra 在 Pi 里 65.3%，在 Claude Code 里 55.4%）。⚠️ 四点：**这是 OpenClaw 自家的基准**，被测 harness 之一是自家的；**模型没有在各自的「原生消费级壳」里测**，真实产品体验可能不同；**「15.7% 违反安全要求」不等于「15.7% 造成损害」**——它衡量的是「该确认时没确认、该扣住时没扣住」；最可落地的一条是：**给邮件、日历、支付这类动作加人工确认门与最小权限**，而不是等模型变好。

- **[JoyFrontBench：前端编码 Agent 任务分 87.69%，应用真正能跑只有 51.52%](https://arxiv.org/html/2611.14952v1)**（arXiv:2611.14952，**2026-11-11** 提交，**11-21** 起被多家日报转述；5 个模型 × 2 个 harness（**OpenHands / OpenCode**），**100 道前端题、764 个任务、2,596 条原子判据**，其中 **70 题**是测试集）：**它把「部分得分不等于能用」这件事量化了 36 个百分点**。**核心设计**：**验收契约在生成之前就固定**——每道题的**核心任务与强制判据**先写死，**一个应用只有「在同一次运行、同一份产物上」通过全部核心任务的所有强制判据才算成功**；参考实现与评分细则**在生成阶段对模型不可见**，评测用 **GPT-5.5 + Playwright 证据 + 确定性审计**。**数字**：OpenHands 下**平均任务分（ATS）87.69%**，**应用成功率（ASR）51.52%**；换成 **OpenCode，均值 ASR 约 46.76%**——**同一个模型换个壳就掉 5 个点**。**排名也会翻转**：**GPT-5.6 Sol 任务分最高（90.53%）但 ASR 只排第三（55.71%）**，**Qwen3.8 Max ASR 最高（57.62%）**。⚠️ 四点：**这是 11-11 的论文**，本周才被广泛转述，按「新研究」而非「今日新闻」看；**70 题的测试集不大**，结论按方向看；**「应用成功」的定义很严**（全部核心任务 + 同一产物 + 单次运行），比产品里的「看起来能用」苛刻得多；最值得抄的是**评测方法**——**先写验收契约、再让 Agent 生成**，这比事后看截图靠谱。
