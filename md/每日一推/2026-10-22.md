### 🤖 AI 与开发

- ⚠️ **[Anthropic 三年来首次更新 Claude API 版本：删除 `temperature` / `top_p` / `top_k`](https://platform.claude.com/docs/en/api/versioning)**（`2026-10-21` 版）：这是自 2023-06 以来第一次 API 版本变更，旧代码升级后**只要再传这三个采样参数就直接 400**。其他破坏性变更：assistant 回合里传 `documents`、user 回合里传 `citations` 也会 400；部分已废弃的 Admin / Enterprise Analytics 字段被替换。官方 SDK 已默认指向新版本；老 `2023-06-01` **仍可用、未弃用**，所以现有项目不必立刻迁，但新代码别再手写这三个参数了。迁移可用 Claude Code 的 `/claude-api api-version` 或 `/claude-api` skill 辅助。
- **[Claude Code v2.1.307 / 2.1.308](https://code.claude.com/docs/en/changelog)**（2026-10-21 ~ 22）：307 与上面的 API 版本强相关——新增 **`/claude-api api-version`** 迁移命令；OpenTelemetry 新增 **`claude_code.safety_event`**（权限规则、auto mode、安全检查、hook、沙箱 stop/prompt/return 任一环节拦下工具调用时都会打点）；HTTP MCP 修掉「连接中途断开导致重复调用」，现在**只重试只读/幂等工具**；自托管 runner 的 checkout hook 默认 **30 分钟超时**（可用 `--checkout-hook-timeout-min` 调）。308（10-22）官方只写 bug fixes。此前于 10-21 推过 2.1.304/305。
- **[Anthropic 推出常驻个人 Agent「Claude Duet」](https://thenextweb.com/news/anthropic-claude-duet-ai-agent)**（2026-10-21，研究预览）：和「等你开口的 Claude」不同，Duet 是**主动式后台 Agent**——主动查你连的 App、汇总任务、自己干活。基于 **Opus 5.5**，跑在自己的云虚拟机 + 浏览器里，**你关电脑它继续**；面向美国 Pro/Max（预览期不加价），有独立 iOS/Android App 和 web。经 Claude Marketplace 的 **6000+ 连接器**接 Gmail、Slack、QuickBooks、Stripe、HubSpot、Shopify 等，能做晨间简报、排期、起草邮件、追逾期发票、预测、搭看板，经批准后还能用 Stripe Link / Shop Pay 下单。护栏：敏感动作（发信/付款/签字/删文件）要人工批准，**硬禁证券交易与账户间转账**，用专用分类器防泄露信用卡/身份证等敏感信息。⚠️ 官方也承认会误解对话、误判紧急度。它一头扎进的正是 2026 下半年「个人 Agent 扎堆」赛道——Meta Muse（9-8）、OpenAI Dots（9-29）、Grok Bot（8-11）已先入场。
- **[Recursive 开源 Flint：40B 本地编程模型](https://huggingface.co/RecursiveSI/flint)**（2026-10-21，Apache 2.0）：Recursive Superintelligence（Richard Socher、田渊栋、Alexey Dosovitskiy 等创办）的首个开放权重模型——**39.8B 总参数 / 约 2.5B 激活**的 MoE，**256K 上下文**，面向本地 coding Agent（读代码库、修 bug、写测试）。自报基准：**SWE-bench Verified 74.2%**、SWE-bench Pro v2 89.7%、Terminal-Bench 2.1 54.9%。亮点是「AI 造 AI」：用自家自动化研究系统 **Eureka Machine** 在 **4 个月内**从零训练（含架构搜索、量化、GPU kernel 优化）。可本地跑：M4 Pro MacBook 上 125+ tok/s、RTX Spark 上 150+ tok/s；Ollama v0.40.8 已支持（目前仅 macOS）。⚠️ 基准为厂商自报、未独立复现。
- **[MoonshotAI 开源终端编程 Agent「kimi-code」](https://www.kimi.com/code/docs/en/kimi-code-cli/reference/kimi-acp.html)**（本周上热榜，7.9k★）：基于 **Kimi K2.7 Code** 模型的终端 Agent，最大卖点是**原生 ACP + MCP 双支持**——`kimi acp` 切进 Agent Client Protocol（Zed、JetBrains AI Chat 等 IDE 可直接驱动会话/工具调用），`kimi mcp` 管理 HTTP/stdio MCP server。一行脚本安装（macOS/Linux/Windows 均有）。这是继 OpenAI Codex、Google Antigravity 之后，国产模型方少见的「从协议层就对齐 ACP + MCP」的 CLI，值得关注它的生态兼容度。

### 🧰 工程化与安全

- ⚠️ **[LiteLLM 发布管线被劫持：v1.107.0 带凭据窃取器 + 后门](https://docs.litellm.ai/blog/security-incident-oct-21-2026)**（2026-10-21）：攻击者用**三枚失窃的 GitHub CLI OAuth token** 发起并批准了一个指向**仿冒 fork**（`Berri-AI/litellm` vs 官方 `BerriAI/litellm`）的发布流程，把恶意 1.107.0 推到 PyPI 与 Docker Hub/GHCR。载荷三个文件塞进 `site-packages`：**`cook.pth`**（每次 Python 启动都自动执行）、**`cook.py`**（窃取 16 类凭据：云密钥、SSH/GPG/TLS、浏览器密码、CI/CD secret、Claude/Codex/Copilot token，AES-256 加密外传到 `litellm[.]dev/healthcheck`）、**`sitecustomize.py`**（RAT，每小时查 GitHub 死信箱拿 C2 域名）。这是 LiteLLM **今年第二次**被攻（前一次 1.82.7/1.82.8 关联 TeamPCP）；Wiz 观察到外传后约 4.5 小时即有人用泄露凭据做 LLMjacking。处置：锁到 **1.106.2**、**手动删掉那三个文件**、在干净机器上轮换凭据。一个耐人寻味的细节：LiteLLM 怀疑 token 是**从 Claude Code 的响应里泄露的**——自家一个暴露公网的 LiteLLM 部署把 Claude Code 的回复记进了日志。
- ⚠️ **[GitLab 九天内第二次 CVSS 10.0 未认证 RCE（CVE-2026-110264）](https://cert.ug/gitlab-patches-second-cvss-100-unauthenticated-rce-nine-days-one-reaching-12-years-releases-cve)**（2026-10-21 修复）：Ruby **Onigmo 正则引擎**在处理恶意正则时整数溢出，未认证即可远程执行代码——影响**几乎每一个自托管 GitLab 实例，回溯到 2014 年的 7.0 版**（约 12 年版本线）。一次性在 **7 个分支**修复：19.5.1 / 19.4.3 / 19.3.6 / 19.2.9 / 19.1.9 / 19.0.10 / 18.11.13（有 4 个分支超出常规维护期专门回移植）。九天前（10-12）的 **CVE-2026-97229** 也是 CVSS 10.0 的未认证 RCE（CI/CD 正则编译器整数溢出）。约 **6 万个自托管实例暴露公网**；无在野利用，GitLab 已发 Sigma 检测规则。两个漏洞都指向同一个结构性问题：**正则引擎的整数溢出反复出事**，自托管 GitLab 务必尽快升。
