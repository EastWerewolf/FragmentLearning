- **[Chrome 160 的发布说明挂出：`SVGPathElement` 有了 `getPathData()`，CSS `corner` 简写进列表](https://chromestatus.com/release-notes/160)**（**2026-11-20** 前后 Chromium **Dev 通道**已到 **160.0.8171 / 8173**；按 chromestatus 的排期，**Chrome 160 于 12-02 进 Beta、2027-01-05 稳定**）：**对写图形与动效的人，这一版有两块硬东西**。**① SVG Path Data API**——`SVGPathElement` 上新增 **`getPathData()` / `setPathData()` / `getPathSegmentAtLength()`**：读出来是 `{type, values}` 的段数组，覆盖全部 **20 个**路径命令；**`getPathData({normalize: true})`** 会把相对转绝对、**把 `H/V/S/T` 简写展开、把二次曲线与弧线转成三次贝塞尔**——这一步以前靠 `path-data-polyfill` 之类的库。**注意它读的是 `d` 属性的基础值**，不是 CSS / SMIL 动画后的计算值。**② CSS `corner` 简写**——`corner-*` 长属性把 `border-radius` 与 `corner-shape` 合成一次写。**其余值得记的**：**`startViewTransition()` 的 `shadowRoots` 选项**（跨 Shadow DOM 的视图过渡）、**正则的缓冲区边界 `\A` / `\z` / `\Z`**（Unicode 模式下）、**Canvas2D 的 `toneMapping` 选项**（HDR 内容映射）、**Capability Elements 的 icon-only 模式**（`<camera>` / `<microphone>` / `<geolocation>` 上的 `displayhint`）、**Prompt API 的采样模式预设**。⚠️ 四点：**这是 Dev 通道的发布说明**，12-02 之前都可能改，**别按稳定版排期**；**SVG Path Data API 在 Firefox 137（2025-04）就有了**，Chrome 落地后**它才可能进 Baseline**——但 Safari 侧仍要看；**`normalize: true` 会改变段数**，做路径 diff / 动画插值的代码不能假设段一一对应；**`getPathSegmentAtLength()` 只在基础路径上算**，对 `<use>` / 引用到的路径不适用。

### 🎨 浏览器与 CSS

- **[Firefox 161 定在 11-24 稳定：`random()` 进 CSS，`var()` / `attr()` / `env()` 支持嵌套替换](https://developer.mozilla.org/en-US/docs/Mozilla/Firefox/Releases/161)**（稳定 **2026-11-24** 与 **ESR 153.8 / 115.46.0** 同日；当前 Beta **161.0b2**，发布负责人 Pascal Chevrel；MDN 的开发者说明仍在补写中）：**平台侧四项**：**① CSS `random()` 函数**（以及配套的 `random-item()` 方向）——**取值在元素的生命周期内固定，不是每次重绘都变**，这才是它和「JS 里 Math.random()」的关键区别；**② `var()` / `attr()` / `env()` 的主参数里可以嵌套任意替换函数**——以前要绕好几层；**③ `<meta name="color-scheme">` 现在会影响 `prefers-color-scheme` 的匹配**，这对**没有 CSS 只有 HTML 的老页面**是行为变化；**④ `text-autospace-size`**，以及 **WebTransport 的 `anticipatedConcurrentIncoming{Uni,Bi}directionalStreams`**（从 160 挪过来的）。**产品侧三条**：可自定义快捷键的「复制当前标签 URL」、应用菜单里的标签组、**导入 Chrome 历史时带上访问频次**（影响地址栏排序）。**修的部分**：**某些服务的 WebRTC 低分辨率 H.264**（158 起的回归）、标签组被删后会话恢复失败、Canva Docs 里输入法只出第一个字符、全屏时 Windows 任务栏压在上面。**Android 侧有一条性能的**：部分设备上 **`backdrop-filter` 渲染明显变快**，以及横屏页面打印不再被压成竖版。⚠️ 三点：**`<meta name="color-scheme">` 影响 `prefers-color-scheme` 是真正的行为变更**——靠 `@media (prefers-color-scheme)` 做主题、又同时在 HTML 里写了 `color-scheme` 的站点要复测；**`random()` 的值在元素生命周期内固定**，想「每次刷新变一次」得换元素或换 JS；**这份清单来自 beta / nightly 说明**，最终发布前仍可能删项。

- **[LangChain 发布 LangSmith Tool Gateway 公测：MCP 凭据不进 Agent，拒绝 / 审批策略在网关执行](https://www.langchain.com/blog/langsmith-tool-gateway)**（**2026-11-19** 公测，作者 Karthic Subramanian；仅 **LangSmith Cloud 的 Plus 与 Enterprise**，区域覆盖 GCP US / EU / APAC 与 AWS US，**不含 Azure US**）：**它把这周早些时候微软 Foundry Toolbox 那条的「另一面」补上了**——Foundry 管的是工具的**打包与版本**，Tool Gateway 管的是**调用时的身份、凭据与放行**。**机制**：把远程 MCP server（**只支持 HTTPS 上的 Streamable HTTP**）或 LangSmith 托管的内置 server 注册进来，**挑一组工具打成一个 tool kit**，再以**单个 MCP URL** 暴露：`/v1/managed-tools/kits/<id>/mcp`。**身份两种**：**以用户身份调用**（走 Okta / Entra ID 的本人凭据，未连接的普通用户会收到登录链接）与**以 Agent 身份调用**（Agent 自己的凭据或管理员配的共享 profile）；凭据有四类归属——user / agent / profile / workspace。**策略两种**：**deny**（直接拦）与 **approval**（在 MCP 客户端里弹确认）；官方明确写了 **「tool kit 负责筛选，策略负责执行」**——**kit 不是访问控制边界**，且 **deny 优先于 approval，默认是放行**。**可见性**：工具调用进 LangSmith trace（工具、server、用户、结果、延迟，**不含参数载荷**），**组织级审计日志仅 Enterprise**。**客户端不限**：文档的 quickstart 就是拿 **Claude Code** 接的，Cursor 与 LangChain 自家栈同理。**内置连接器**：Google Workspace、Microsoft 365 / Teams、Salesforce、GitHub、Linear、LinkedIn、Slack、X 走 OAuth；Exa、Tavily、Apollo、Ashby、Pylon 走 API key。**硬限制**：请求 **1 MB**、响应 **8 MB**、server **60 秒**内要开始应答、单 kit 至多 **10,000** 个工具、**100 req/s**（突发 1,000）。⚠️ 四点：**「默认放行」是最该改的一项**——不配策略等于把治理层当代理用；**trace 不记载荷**，排障时你只能看到「调了哪个工具」；**IdP token 调用者能触达工作区内所有 server**，除非策略收窄；**没有 GA 时间、也没有独立安全评估**，只有一家匿名客户的规模（50+ MCP server、1,000+ 工具）。

- **[OpenAI 的反蒸馏进展：GPT-6.2 Astra 的推理提取成功率从 54% 降到 0.2%，代价是「改历史就丢推理」](https://enterpriseai.economictimes.indiatimes.com/news/industry/openai-reduces-success-rate-of-ai-reasoning-theft-attacks-to-0-2/136046992)**（OpenAI 的《Combatting Adversarial Distillation》在 **2026-11-20** 发布，11-21 被 ANI 系的媒体铺开）：**两个数字先记住**：**对「先前请求」的推理提取**成功率 **54.0% → 0.2%**；**对「当前请求」**的提取 **22.9% → 0.9%**（Sol 约 0.5%）；口径是**聚合六个攻击模型的内部自适应黑盒红队**。**机制**：**受保护的推理与产生它的对话前缀绑定**（官方称 context lock，思路与 Anthropic 6 月那项措施接近）——**如果之前的消息或工具配置被改写，API 会丢弃后续推理**；更弱的旧模型也读不了新模型受保护的推理。**另有**：对抗训练、输入 / 输出分类器、API 侧限制，以及**每周对未授权蒸馏行为做执法**（据称涉及数千到数万个账号；OpenAI 此前在国会简报里点名过 DeepSeek，9 月又指向与 Moonshot / Kimi 相关的人）。**研究侧的一个结论**：**用「完整推理轨迹」做 SFT 的学生模型，在网络安全基准上强于用「摘要」训练的**，且这个优势在 RL 之后、推理预算更高时仍然存在——这正是要防的原因。⚠️ 四点：**所有数字都是 OpenAI 自家红队**，没有第三方复现；**「改历史就丢推理」对开发者是真实的副作用**——做对话裁剪、上下文压缩、重放（replay）的产品，**会同时丢掉 token 节省和此前推理**；**这条与 11-19 推的 GPT-6.2 独立复核是两条线**，那条讲能力与价格，这条讲防护；**执法口径涉及具体公司名**，属于 OpenAI 单方陈述，我不做独立验证。

- **[Thinking Machines 开源 Inkling 2 Mini：26.4B 的循环 Transformer，Apache 2.0，32GB 内存的 Mac 能跑](https://thinkingmachines.ai/model-card/inkling-2-mini/)**（**2026-11-20** 发布，权重在 Hugging Face 的 `thinkingmachines/Inkling-2-Mini`，**Apache 2.0**，也可从 **Tinker** 平台调用）：**它的卖点是「每 token 想得更久」而不是「更大」**：**24 层 MoE，中间 12 层每个 token 跑 3 遍**（合计 48 层应用），**总参 26.4B、激活 3.4B**（算上循环约 5.4B 等效）；**上下文最长 1M**，输入文本 + 图像、输出文本。**工程上值得抄的一手**：**checkpoint 约 20GB，训练与部署直接用 4-bit NVFP4（前段）+ 8-bit MXFP8（后四层）**，**避免「训练完再量化」的那次精度损失**。**能跑在哪**：**32GB 内存以上的 Mac 走 Ollama**、NVIDIA DGX Spark、GGUF（Unsloth / llama.cpp）、MLX、SGLang、vLLM；官方演示是**离线在 MacBook Pro 上搓出一个能玩的飞行模拟器**。**厂商口径的分数**：**DeepSWE v1.1 48.2%**、**SWE-bench Pro v2 Hard 77.9%**、**SWE-bench Verified 79.2%**、DeepSearchQA 85.3%，称在 100B 以下的开放权重里领先；**Artificial Analysis 智能指数约 20.1**。**明确承认的短板**：多轮对话（MultiChallenge 50.0%）与多约束指令（ComplexConstraints 33.4%）**不如 Qwen3.8-27B**，事实知识受参数规模限制。**还放了一个研究用 checkpoint**（`TML-d24-varloop-research`）与可解释性合作（NDIF、Goodfire）。⚠️ 四点：**分数全是厂商自报**，且「100B 以下领先」是比较集选出来的口径；**循环层意味着实际算力高于「3.4B 激活」的直觉**，长上下文下更明显；**Apache 2.0 是真的宽松**，但 20GB 的本地部署门槛仍在；**它在多轮与约束遵循上不如同尺寸常规模型**，拿来当「本地编码单发任务」的模型比当聊天模型合适。

- **[《Agent 凭记忆装了个包》：五个已弃用的 MCP server，一周仍被拉 49.6 万次](https://dev.to/ginigenai_hp_0ae441ead91f/the-agent-installed-a-package-from-memory-what-mcphantom-teaches-about-deprecated-mcp-servers-and-4cae)**（dev.to 的实测文 **2026-11-20**，查询 npm registry 的 **11-13 ~ 11-19** 下载数据；它所讨论的 MCPhantom 现象由 Glow Labs 在 **约 11-02** 提出，CSA 有对应的研究笔记）：**这篇的价值是把「弃用」从一句公告变成可核对的下载量**。**五个包的周下载**：`server-slack` **183,067** + `server-postgres` **147,218** + `server-github` **112,028** + `server-puppeteer` **27,283** + `server-brave-search` **26,774** = **496,370**。**MCPhantom 指的是什么**：编码 Agent **从训练数据里回忆起旧包名**、直接 `npx` 装已经被归档的 `@modelcontextprotocol/server-*`，而不是去 registry 查当前维护的版本——在 Claude Code、Cursor、Codex CLI 上都观察到，**98% 的情况下用户根本没提过那个旧包名**。**四个高危问题、零 CVE、没有补丁**：维护者把报告按「超出范围」关掉了，其中最严重的是 `server-puppeteer` 的提示注入导致的 RCE。**文章给的修法很具体**：**把 registry 的 `deprecated` 字段当成前置审批的判据**（而不是等 CVE），在 `PreToolUse` 之类的钩子里**拦掉对已弃用 `npx` 包的启动**，并把配置里（`~/.claude.json`、`~/.cursor/mcp.json`、`.mcp.json`）的旧 server 换成一等公民的供应商版（`github/github-mcp-server`、`@playwright/mcp`、`@brave/brave-search-mcp-server`）。⚠️ 四点：**49.6 万与另一批分析里的 62 万不可直接比**——包集（5 个 vs 11~12 个）与时间窗不同；**下载量不等于被 Agent 装**，它包含 CI、镜像与老项目的常规安装；**「98%」来自 Glow Labs 的观测样本**，不是全量统计；真正可落地的一条是——**「注册表里有」和「还在维护」是两件事，而 Agent 只认前者**。
