### 🎨 浏览器与 CSS

- **[State of HTML 2026 结果发布：`<dialog>` 使用率 67.8%，但 43% 的人不保证站点在无 JS 下能用](https://2026.stateofhtml.com/)**（调查窗口 **2026-10-01 ~ 11-01**，结果 **11-15** 上线；Frontend Focus **#767（11-18）** 由 Kilian Valkhof 做了首篇解读）：**这份数据比往年更值得看，因为它是「AI 写前端」之后的第一次全面体检**。**用得最多的交互特性**：**`<details>` / `<summary>` 72.5%**、**`<dialog>` 67.8%**；**Popover API 到了 40%**（三大浏览器都支持之后涨得很快）。**最痛的两块**：**`<select>` 与日期输入最难定制**，而 **customizable select 目前主要卡在 Firefox 没上**；**`<datalist>`** 使用率从 **30% 升到 44%**，但**好评率反而从 44% 掉到 34%**——样式、无障碍与浏览器 bug 三件事一起拖后腿。**愿望清单**：原生可排序 / 可筛选的**数据表格**排第一，其后是 tabs、combobox、switch，**HTML includes 又被人提起来了**。**两组最该记的数字**：**43% 的人不保证站点在不启用 JS 时可用**，只有 **4%** 把它当硬要求；**受访者代码中位数有 50% 是 AI 生成的**（CSS 只有 **13%**）。**结论句写得克制**：抱怨的重点已经从「浏览器行为不一致」变成「浏览器还没跟上」，移动端操作系统是最疼的一环——「行业也许在动荡，但我们的地基是好的」。⚠️ 三点：**这是自选样本的社区调查**，百分比看方向不看精度；**「50% 代码由 AI 生成」是自报中位数**，与真实提交比例不是一回事；另外数据页每天在更新（`2026.stateofhtml.com`），引用具体数字前先看它是哪一天快照。

- **[Safari 27.3 beta 2：全局隐私控制（GPC）落地，垂直标签与 Siri 进浏览器](https://hi-tech.ua/en/new-in-ios-27-3-and-macos-27-3-beta-2-smarter-siri-for-safari-and-iphone-duo-exclusives/)**（开发者 beta 2 **2026-11-17** 推送：macOS 27.3 为 build **26C5047e**、iOS / iPadOS 27.3 为 **24C5049d**；beta 1 在 **11-03**；正式版预计 **12 月中旬**）：**对做 Web 的人，这条只有前两项算技术面**：**① 全局隐私控制（Global Privacy Control）**——浏览器会发出 **`Sec-GPC: 1`** 头，站点可以据此当作「拒绝出售 / 共享」的法定信号，**加州等地的合规动作要跟着改**；**② 垂直标签**（iOS 上是 iPhone Duo 独占，iPadOS / macOS 也能切）；**③ Safari 里的 Siri** 能就当前网页问答并操作页面内容。**另据德文报道**，Safari 27.3 的发布说明里列了 **500+ 项** Web 标准与站点兼容性增改。**beta 1 带来的 Adaptive Dark Mode 仍在**：给不支持深色的站点自动反色，页面**用 `getComputedStyle` 探测不到**。⚠️ 三点：**这是 beta 2，正式版前还会变**；**GPC 是「信号」不是「强制」**——你若不处理 `Sec-GPC`，它就只是一行看得见的请求头，法务与前端要一起确认埋点与 Cookie 脚本有没有读它；**Adaptive Dark Mode 会让「我们的深色模式」与「系统强制的深色」叠在一起**，做品牌色的站点建议先测一遍。

- **[Edge 158 平台发布说明上线（11-19）：功能与 Chrome 158 同源，但 XSLT 要等到 Edge 159 才关](https://learn.microsoft.com/en-us/microsoft-edge/web-platform/release-notes/158)**（文档日期 **2026-11-19**；Chrome 158 已于 **11-17** 全量稳定，Edge 的同一批平台能力随之落地）：**这条唯一必须知道的新事实是「时间差」**：**XSLT 在预览通道从 Edge 157 起默认关闭，但 Stable 通道要到 Edge 159 才关**，临时策略 `XSLTEnabled` 与 Origin Trial **只到 Edge 176**。**平台特性与 Chrome 158 一致**：`<install>` 元素与 `navigator.install()`（含跨源安装，始终需要用户确认）、SVG `<textPath>` 的 `side` 属性、`focus-without-user-activation` permissions policy、`OfflineAudioContext` 的增量渲染、WebTransport 的 `reliability` 与 `supportsReliableOnly`。⚠️ 三点：**「Chrome 停了 XSLT」不等于「Edge 同天停」**，企业内网的老后台要按 Edge 的时间表排期；**`<install>` 受 `WebAppInstallByUserEnabled` 策略与 `web-app-installation` permissions policy 双重控制**，被企业策略关掉时不会报错、只是不弹；**别把这条和 Ignite 上 Edge for Business 的 Copilot 功能混在一起**，那是产品侧、不是 Web 平台。

- **[GPT-6.2 的独立复核：通用智能涨到 62，但编码分「Astra 持平、Sol 降 3」](https://www.deeplearning.ai/the-batch/gpt-6-2-astra-sol-cut-prices-to-match-claude)**（Artificial Analysis 的读数在 **11-18 / 11-19**；The Batch、4sysops、tinyfish 的日刊同日跟进；与 11-18 那期推的发布信息互补）：**这条把「厂商口径 vs 独立口径」的差摆到了台面上**。**通用智能（Intelligence Index v5，11-18）**：**Fable 5.2 65 > GPT-6.2 Astra 62 > Gemini 4 Carbon 60 > Opus 5.5 59 > GPT-6.2 Sol 57**；Astra 比 GPT-6 Astra 涨了约 5 分，Sol 涨约 2 分。**编码（Coding Agent Index）**：**Astra 相对 GPT-6 Astra 是持平的**，**Sol 相对 GPT-6.1 Sol 反而降了 3 分**，其中 **SWE-Atlas-QnA 掉了 14 分**——AA 的说法是 Sol 更容易漏掉关键事实。**榜单前五（11-19 读数）**：**Neon 58.64**、**Fable 5.2 58.47**、**Devin Fusion CLI 58.40**、**Fable 5.2（high）58.24**、**Opus 5.5（max）58.16**；**Astra 在 Codex 里最好只有 53.47**，落后约 5.2 分，且差距集中在 **FrontierCode 2.0** 这一项。**价格侧的变化是真的**：Astra 缓存命中从 **1.00 降到 0.40**，AA 测算的**每个智能任务成本 Astra 约 4.00 美元、Fable 5.2 约 26.54**（约 15%）；Sol 约 **1.01**。**两个负面信号**：**事实类问题的高幻觉率**（Astra 59%、Sol 55%，max 档）；**开发者口碑分裂**——Dan Shipper、Matt Shumer、Theo Browne 都偏负面，Ethan Mollick 相对中性，而 ClickUp 报的是「token 少约 40%、返工少约 30%」。⚠️ 四点：**榜单每一行是「模型 + harness」的组合**，不是纯模型分，Astra 的低分有一部分是 Codex 壳的问题（11-18 那期的 harness 元综述就是讲这个）；**幻觉率的口径要看清**是「事实类问题」而非全部输出；**成本对比建立在 AA 的任务集上**，和你的负载无关；最有用的结论只有一句——**这次降价是真的，编码能力的提升不是**，如果你的场景是写代码，先别急着迁。

- **[GitHub 把「会话跨设备续跑」的协议讲清楚了：Agent Host Protocol 双实现、客户端库六种语言](https://github.blog/engineering/engineering-principles/building-the-agent-host-protocol-for-sessions-that-continue-across-devices/)**（工程博客 **2026-11-17**；协议 **v1.0 随 VS Code 1.144 在 10-28 发布**，**spec 1.1.0 在 11-12** 发布，**1.2.0 仍是草案**）：**它要解决的是一个很具体的前端问题**：你在 VS Code 里开的 Agent 会话，**换到手机或云端还能接着跑**，而不是重开一个。**设计**：用 URI 标识的**通道**——`root`、`session`、`chat` 为必需，`terminal`、`MCP`、`OTel` 可选；**状态是 reducer 式的对象，服务端是唯一仲裁者**，客户端只发 action 并乐观展示待定结果；**协议刻意不规定 Agent 行为**，只管「客户端怎么和 Agent 交互」。**实现规模是这条最硬的部分**：**两个独立宿主**——VS Code 的 TypeScript 版约 **36.9 万行**、GitHub 的 Rust 版约 **30.5 万行**，替换掉原来 **40 万行以上**的 Copilot Chat 扩展；**客户端库覆盖 TS / Rust / Kotlin / Swift / Go / .NET**，MIT 许可。⚠️ 三点：**重连能补回错过的 action 或快照，但「离线时不确认的 action 不保证会跑」**，这是协议层面的边界，不是 bug；**会话的持久化仍取决于宿主**，协议本身不存状态；**1.2.0 还是草案**，现在接要留升级余量——但如果你在做「同一会话跨 IDE / 手机 / 云」的产品，这份设计文档比任何 SDK 都值得先读一遍。

### 📚 好文精选

- **[《我把 Modern Web Guidance 跑在一个 vibe-coded 落地页上，扫描器漏掉了最糟的部分》](https://dev.to/polydraft/i-ran-modern-web-guidance-on-a-vibe-coded-landing-page-the-scanner-missed-the-worst-parts-5f7c)**（dev.to，**11 月中旬**；与 seo-kreativ.de 在 **11-12** 的独立手测结论一致；MWG 1.0 本身在 **11-10** 发布，**11-12 / 11-14 / 11-17** 三期已从不同角度推过）：**这篇补的是前几期都没有的那块——扫描器的覆盖率**。**怎么测的**：拿一个合成的落地页（React 组件 + 静态 HTML + 两份样式表），里面放了一个 **`<div role="dialog">` 手搓弹窗**（自己处理 Esc 与 body 溢出）、`type="text"` 的邮箱框、裸密码框、`dangerouslySetInnerHTML` 的证言、IntersectionObserver 渐入、`localStorage` 深色开关、滚动监听的导航、只能 hover 的 tooltip、`::-webkit-scrollbar` 样式与 CDN 脚本。**结果**：跑 `npx modern-web-guidance@latest legacy-scan .` 只得到 **6 条、覆盖 5 篇指南**（autofill、complex-shapes、soft-edge-content-fade、自定义滚动条、深色模式开关）。**核心批评**：`legacy-scan` **只对约 38 篇指南（语料的 20%）有确定性规则**，其余 80% 要靠 `search` / `retrieve` 那条路；而**真正伤用户的问题全都没被扫出来**——div 弹窗的键盘与读屏陷阱、未净化的 HTML（XSS 路径）、滚动监听的导航、IntersectionObserver 渐入、只能 hover 的 tooltip、错误的邮箱输入类型。**还踩了一个坑**：目录名叫 `demo-site` 时返回 **0 条**，因为扫描器默认跳过 `docs` / `examples` / `demos` / `tests`，得加 `--include-docs-and-tests`。**它给的用法建议是对的**：把「**扫描 → 核对 → 报告 → 现代化**」写进 `AGENTS.md` / `CLAUDE.md`，而不是跑一次就算。⚠️ 四点：**这是单个合成 fixture**，不能当成覆盖率统计；**「20%」是规则覆盖率，不是「扫描有效性 20%」**；**finding 本身标着 provisional**，别直接当工单派；**不能因此说 MWG 没用**——它的价值在那 80% 的指南检索里，这篇真正提醒的是：**「扫描通过」不等于「页面没问题」，尤其在你只跑了扫描、没让 Agent 去检索的时候**。
