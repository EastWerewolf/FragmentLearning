### 🎨 浏览器与 CSS

- **[Interop 2027：`@function` 与 `corner-shape` 进入跨浏览器推进清单](https://www.oschina.net/news/503139/interop-2027)**（2026-10-20 ~ 21 集中讨论，缘起 [Josh W. Comeau《The Future of CSS》](https://diginews.johandenoyer.fr/article.php?id=48493)）：
  - **`@function`**：作者可定义返回值的自定义 CSS 函数（如 `@function --translate-polar(...)` 做极坐标→直角坐标换算），Chrome/Edge 已实现，Firefox/Safari 尚未跟进。
  - **`corner-shape`**：`border-radius` 之外的圆角方案（squircle / bevel / notch / scoop），关键区别是它**真的改变 border-box 几何**——`border`、`outline`、`box-shadow` 都会跟着新形状走（`clip-path` 只是视觉裁剪）。此前 10-17 只在 Firefox 158 里提过一嘴，现在是「四大厂商联手推进」的正式议题。
  - 决策机制：Mozilla 建了社区投票站，但最终名单要等 **12 月闭门共识会**，大厂基本有否决权（[Patrick Brosset 的解析](https://patrickbrosset.com/lab/interop-2027/)）。⚠️ 这些特性目前只在 Chromium 可用，做渐进增强没问题，跨浏览器要看 Interop 2027 最终选谁。

### 🧰 工程化与安全

- ⚠️ **[Plugin4Shell：四大 AI 编码 Agent 的 SHA 固定都能被绕过（zero-click RCE）](https://labs.cloudsecurityalliance.org/research/csa-research-note-plugin4shell-ai-coding-agent-supply-chain/)**（Air Security 9-18 披露，本周随 CSA 研究简报被集中报道）：Claude Code、OpenAI Codex、GitHub Copilot、Gemini CLI 的插件系统都**把插件 pin 到某个 commit SHA，但 checkout 之后不校验工作树是否真的落在这个哈希上**。攻击者控制插件仓库后，建一个**与 40 位哈希同名的分支**设为默认分支，`git checkout <SHA>` 就会落到攻击者控制的代码上（Git 在分支名与哈希冲突时优先解析分支）。Claude Code / Codex / Copilot 走 `git checkout <SHA>`；Gemini CLI 走 `git fetch <SHA>` + `checkout FETCH_HEAD`，一个默认分支名 `FETCH_HEAD` 就能劫持。修复状态：Claude Code 已修（v2.1.179）、Codex 已修（v0.146.0）、**Copilot 无客户端修复**（GitHub 称平台拒绝哈希形分支名已缓解）、**Gemini CLI 未修复**（产品已让位 Antigravity）。无 CVE、无在野利用、PoC 在研究者手里。教训一句话：**「pin 了 SHA」不等于「校验了 SHA」**——受害者恰恰是照正确姿势配了 marketplace 审查 + 哈希固定的那批人。
