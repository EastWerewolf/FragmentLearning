### 🎨 浏览器与 CSS

- **[一条分享链接接管你的 ChatGPT：沙箱没破，破在主页面上的 `postMessage`](https://www.parameter.ai/labs/we-found-a-gap-at-openai)**（Parameter Labs 2026-10-28 公开；OpenAI 于 10-26 在两个前端修完）：这条值得每个写 Web 的人逐段读一遍，因为它**每一步都踩在前端常识的失效点上**。前提是：ChatGPT 的 HTML Preview 沙箱**本身守住了**——问题出在主页面。攻击链四步：<br>① 主页面上的 **MathLive 虚拟键盘**注册了一个跨 iframe 的 message 监听，**没有校验 `event.origin` / `event.source`**，并且把收到的内容当作「键盘布局数据」处理；<br>② 它把这段数据写进 `innerHTML`，于是得到一个**没有 `sandbox` 属性的 `srcdoc` iframe**——`srcdoc` 会**继承父页面的源**，等于拿到了 chatgpt.com 的可信上下文；<br>③ ChatGPT 的 CSP 虽然禁了内联脚本，但**放行了 YouTube**，攻击者借 **YouTube oEmbed 的 JSONP 回调**把 JS 执行起来；<br>④ 之后就是受害者的身份：枚举最近会话、读到一个**从未分享过的私人对话**，并通过图片请求把数据外传。<br>投递方式是**别人发给你的一条公开 `/share/<id>` 链接**，最初要点一下 Preview，后来优化成**零点击**（页面加载约 4.5 秒后自动触发）。时间线：10-18 报告 → 10-21 复现并升为 P1 → 10-23 改 CSP → 10-26 两侧前端修完 → **$5,000 赏金**，官方称无野外利用。给平台方的四条硬教训：**跨窗口消息必须校验 origin 与 source**；**`srcdoc` 不等于沙箱**（要沙箱请用 `sandbox` 属性 + 独立源）；**CSP 的脚本白名单会因为 JSONP/oEmbed 这类老接口出现执行洞**；**第三方 Web Component 是随页面一起获得可信上下文的**，引一个虚拟键盘等于引一段自家代码。

### 🤖 AI 与开发

- **[Google 关停 Jules，能力并入 Antigravity：先只读、再下线，且必须手动迁移](https://jules.google/docs/changelog/)**（2026-10-29 宣布）：上线不到两年的异步编码 Agent 走到头。**11-11 之后进入只读**（不能再建新任务，进行中的会话要在此之前收尾），**12-31 完全关停**。迁移方式是**手动的**：官方给了 `@google/jules` CLI 做导出，覆盖账户设置、环境变量、定时任务、已连接仓库、记忆与完整会话历史，但**没有自动迁移进 Antigravity**，工作流得自己重建。官方定调是「合并而非失败」——把 Jules 的**远程后台自主执行**和 Antigravity 的**Agent 中心开发环境**并成一件事。同日 Antigravity 上线**插件市场**，合作方包括 Atlassian、Figma、Stripe、Datadog、Databricks、Canva、CrowdStrike、Dropbox、Unity。对用过 Jules 的团队，实际建议是：**先导数据再评估**，导出里有你调过的环境变量与定时任务，这些往往比会话历史更值钱。
- **[Google Connected Apps Platform：一次接入，同时进 Search 的 AI Mode 和 Gemini](https://techcrunch.com/2026/10/28/as-ai-agents-reshape-the-web-google-opens-gemini-and-search-to-more-apps/)**（2026-10-28 公测）：这大概是本周对**应用/前端开发者**最实际的一条。两条接入路径，覆盖面不同：**云端 MCP server**（一次接入可覆盖 Gemini App 与 Search 的 AI Mode，Android / iOS / Web 全端）或 **Android 端的 MCP——即 AppFunctions**（只覆盖 Android 上的 Gemini，本质是让 App 把选定的函数与数据暴露给**任意授权的 AI Agent**，不只 Gemini）。管理侧新开了 **Connected Console**（注册、测试、提交、看流量/延迟/错误）。官方称已有 **50+ 应用**接入，合作方包括 Adobe、Experian、Peloton、Instacart、Canva、YouTube Music 等。政策上有一条值得注意：**禁止用夸大的能力描述去「骗」模型选中自己**。⚠️ AppFunctions 仍处于**私测**阶段（`androidx.appfunctions 1.0.0-alpha13`、需 Android 16+），别按「现在就能上生产」规划。
- **[DeepSeek 开源 Super-agent 原型：Router 管调度、Worker 干活，p95 从 29.5 分钟压到 15.7 分钟](https://github.com/deepseek-ai/dsh-superagent-prototype)**（2026-10-31，MIT，上线一天约 4,000 star）：明确标注是**研究原型、不是官方产品**，但设计很值得抄。五个模块：**① Router / Worker 双层**——Router 是常驻的全局调度者（可用更轻的模型），只管接单、派活、维护共享上下文，**且只有它对用户说话**；Worker 拿隔离上下文与完整工具，可并行、可再调子 Agent。**② 事件驱动 + 两级过滤**——先走确定性 Fast Path（来源、群组、白名单），再走 LLM 语义判断的 Slow Path。**③ 订阅穿透**——某个 Worker 认领了 PR 后直接订阅该线程，后续评论**绕过 Router**。**④ 上下文即缓存**（Inline & Spill + 链式召回、异步 ReAct）。**⑤ 计算与状态分离 + 外部 Watchdog**——会话落库、本地只留轻量守护进程，Watchdog 检测卡死的循环并介入。主动性分 `off` / `observe`（默认，只记录「我本会接这个活」）/ `auto` 三档。合成负载下的数字：p50 **12.4 分钟**、p95 **15.7 分钟**，对比单会话 Subagent 的 p95 29.5 分钟；加上订阅穿透后 Router 决策数降约 30%，Router 批处理把单次决策从 6.4 秒压到 1.6 秒。⚠️ 官方自己强调这测的是**调度**不是编码质量；部署要独立 GitHub 账号、Node ≥22.19、GitHub CLI ≥2.48，Worker **以完整 OS 用户权限运行**（建议换独立系统账号）、仅支持 github.com。
- **[商汤开源 SenseNova Loop-9B-Preview：32 层权重，跑出 56 层的计算深度](https://huggingface.co/sensenova/SenseNova-Loop-9B-Preview)**（2026-10-30，Apache 2.0）：今年少见的**架构侧**开源，而不是又一个大模型。核心是**权重循环**：32 个解码器层里，**第 4–27 层这 24 层以共享权重连跑两遍**（记作 B(B(h))），首尾各 4 层只跑一次——所以每次前向**实际算 56 层，但只存 32 层的权重**。配套还有两处设计：**混合注意力**（每 4 层一组，3 层 Gated-DeltaNet 线性注意力 + 1 层全注意力，循环边界与四层组对齐）与 **mHC（流形约束超连接）**，在循环段里开两条并行残差流，用可学习的 Sinkhorn 归一化路由（20 次迭代）控制信息读写混合。参数：总参约 **9B**、官方称「推理参数」约 **14.6B**，训练上下文最长 **262,144**，文本+图像输入。自报在 8 项基准里 6 项超过 Qwen3.5-27B（WorkBuddy Bench 66.89 vs 60.53、RaccoonPPTBench 70.70 vs 59.08 等），mHC 消融给 GPQA Diamond +4.42、TeamBench +13.34。⚠️ **三处保留**：全部为自报且**技术报告未发布**；对标的是 Qwen3.5-27B 而不是更新的 Qwen3.8；社区 GGUF 量化**需要打过补丁的 llama.cpp**，上游 llama.cpp / LM Studio / Ollama 均未支持该架构——它的优势在**参数效率与显存**（8–16GB 可跑），不在速度。

- **[我们是怎么接管 ChatGPT 账户的：一次「不靠漏洞、只靠实现细节」的利用](https://simonwillison.net/2026/Oct/31/how-we-took-over-chatgpt-accounts/)**（Simon Willison，2026-10-31；技术链路见上方 🎨 条）：这篇的价值不在复述攻击，而在**为什么这类洞总是被低估**。作者点出三层：**第一，沙箱审计容易只看「沙箱里」，忽略了沙箱外的宿主页面**——这里 MathLive 是第三方库，它的监听器天然带着完整信任；**第二，CSP 的「放行名单」会变成攻击面**，只要名单里有一个能回调解的旧接口（oEmbed、JSONP、各类 widget），脚本执行就绕开了 `script-src` 的本意；**第三，`srcdoc` 这个 API 的语义反直觉**——很多人以为「我没写 sandbox 就等于安全」，实际是没写 sandbox 就等于**同源**。对做富内容预览（AI 生成的 HTML、Markdown 渲染、白板、组件市场）的产品，这篇文章可以直接当威胁建模的检查表。
- **[DeepSeek 又开源了：Super-agent 架构的技术文章拆解](https://www.zhidx.com/p/606311.html)**（2026-10-31）：配合上面那条读设计动机。最值得看的是它为什么**把 Router 单独拆成一个常驻进程**——不是为了分层好看，而是因为「多轮任务里最贵的不是生成，而是**判断这条消息该不该现在处理**」，所以把 Fast Path 做成确定性的、把 Slow Path 做成模型判断，并且用**订阅穿透**让已经开工的 Worker 绕开中心调度，避免所有消息都回灌到 Router。文章也把「上下文即缓存」讲清楚了：Inline & Spill 加上链式召回，本质是**让 Agent 不必每轮重读全部历史**。作者同时诚实地列了代价——Router 本身会成为单点，Worker 全权限运行是明显的安全缺口。

- ⚠️ **[Anthropic 官方 Claude Code 扩展被投毒：Cursor 市场 11 小时，装完即开后门](https://thehackernews.com/2026/10/official-claude-code-vs-code-extension.html)**（2026-10-29 事发，10-30 披露）：**同一天里对开发者最危险的一条**。一个被篡改的构建版本以**官方扩展 ID `anthropic.claude-code`** 发布在 **Cursor 市场**上，存活区间约 **美西 02:27 – 13:35（约 11 小时）**，Cursor 估计**至多 5,000 名用户**受影响。技术细节：在压缩后的 `extension.js` **开头插入 66 行 loader（IIFE）**，在 Node 加载时即执行、**早于扩展的 `activate`**，不需要任何用户操作。它做的事有四步：把带标签 **`svc-telemetry`** 的 SSH 公钥写进 `~/.ssh/authorized_keys`；尝试开启 SSH；**向 `134.209.82.225` 建反向隧道**（每 60 秒重试）；用 macOS LaunchAgent（`com.apple.sysmond`）、Linux `@reboot` cron、Windows 计划任务 `SysMon`（兜底放启动文件夹）做持久化。侦察信标走**明文 HTTP**，上报公网 IP、主机名、用户名、系统与架构、家目录与当前目录、Git 邮箱，以及**最多 40 个名字里含 KEY/TOKEN/SECRET/PASS/AWS/GCP 的环境变量名**（初始不上报值）。修复与善后：恶意版本 10-30 移除，**2.1.314** 发布到 Open VSX 与 Microsoft 市场，市场短暂下线、轮换密钥并做了审计。⚠️ **最容易踩的坑**：`ssh` 在 macOS / Windows 上因权限不足通常起不来，隧道登录多半失败，但**公钥、持久化与侦察数据都已经成功落地**；而且**卸载扩展不会清掉它们**——检查 `authorized_keys` 与计划任务，并轮换相关凭据。另外「投毒版本是 2.1.313 还是 2.1.312」各源口径不一，攻击者如何拿到发布权限目前**没有结论**。
