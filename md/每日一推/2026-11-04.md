- **[Next.js 11-03 安全版落地：7 个中危，16.4.5 全修、15.5.29 只修三个](https://nextjs.org/blog/nextjs-november-2026-security-release)**（2026-11-03，此前 **11-02** 只做了预告）：按预告发了，受影响面比「中危」听起来要大——**七个里五个跟 `use cache` / Cache Components 的跨请求缓存有关**：嵌套 `use cache` 跨 root param 值泄漏缓存（CVE-2026-119351）、通过 `unstable_cache()` 调 `use cache` 时的跨 root param 信息泄露（CVE-2026-119790）、请求侧占位路由参数污染共享 fallback shell（CVE-2026-119350）、`use cache` 的二进制裁剪参数导致跨用户缓存泄露 / 污染（CVE-2026-119349）。另外三条更通用：`dangerouslyAllowSVG: false` 下的**图片优化 SVG 拒绝绕过**（CVE-2026-119347）、Edge Route 通过内部 `x-middleware-set-cookie` 头**暴露 HttpOnly cookie**（CVE-2026-119346）、自托管应用在特定 HTTP/1.1 代理后转发 fetched 响应时的**跨客户端响应注入 / 响应分帧问题**（CVE-2026-119348）。**升级口径**：**16.4.5**（Active LTS）修全部七个；**15.5.29**（Maintenance LTS）只修 SVG 绕过、Edge cookie 暴露、跨客户端响应注入三个——**所以还在 15.x 的团队，除非你不用 Edge Route、不开 `dangerouslyAllowSVG`、也不在代理后自托管，否则升到 16 才叫修完**。平台侧另有工作量：Netlify 称其中几条因按请求隔离而天然不受影响，但 OpenNext 适配器要升到 `@netlify/plugin-nextjs` **5.16.6**。⚠️ 严重级别有分歧：官方与多数报道为 **7 个 medium**，Pantheon 的整理写成「1 个 high + 6 个 medium」，CVSS v4 大致落在 **6.3–6.9**。
- **[Claude Code v2.1.318：登录过期终于可见，且不再自动给你装 IDE 扩展](https://code.claude.com/docs/en/changelog)**（2026-11-03 晚发布，`latest` / `next` 均为 2.1.318，`stable` 仍停在 2.1.311；约 47 项修复）：此前于 **11-03** 推过 2.1.317，这一版挑无人值守场景最相关的四条。**一、凭据过期可见**：`claude auth status` 输出 `loginExpiresAt`、`claude -p` 的 JSON 结果带 `credential_expires_at`、文本模式在**到期前 10 天**开始往 stderr 打一行警告，过期失败也会明确指向 `claude auth login` / `claude setup-token`——对跑 CI 或定时任务的人是刚需，之前的问题是**失败信息模糊**。**二、行为变化**：从 IDE 终端启动时**不再自动安装 IDE 扩展**（改为 `/ide` 或从编辑器扩展视图装）——如果你的初始化脚本依赖它自动装，会静默少一步。**三、成本归因**：Claude apps gateway 的 Bedrock（mantle）上游支持 `assume_role`，可以跨账号承担角色并按开发者分摊 AWS 账单；Google 联合身份令牌临近过期会告警。**四、长任务更稳**：后台子 Agent 遇到**超过 3 分钟**的 shell 命令会转到后台执行（所有 provider），目的是保住 prompt cache；自托管 runner 新增 `CLAUDE_RUNNER_SPAWN_REASON`（`runner_lost`、`resumed` 等）与 `session_turn_state` 指标（busy / waiting / rest / lost）。另外两条容易踩的：**`claude -p` / SDK 在什么都没变时不再重写 `~/.claude.json`；而 `~/.claude.json` 不是合法 JSON 时现在直接启动失败**，不再用默认值覆盖（issue #87551）；`claude mcp add/remove` 开始获取配置锁，冲突时等待或 `exit 1`。⚠️ 已开源的 mods 类型定义（`mods/types/claude-code.d.ts`）**还没暴露**本版宣布的 `$.model.fork` 的 `effort` 字段，用它的扩展会类型检查失败（issue #107096）。
- **[TanStack Redact 0.2.0：不改一行 React 代码，Vite 打包小 70%](https://tanstack.com/blog/introducing-tanstack-redact)**（2026-10-26 发布，Tanner Linsley；此前未推过，日期已超出 7 天窗口但前端侧这是本月最大的一个变化）：它不是 Preact 那种「另一个框架」，而是**在构建期把 `react` / `react-dom` / `react/jsx-runtime` / `scheduler` 换成一个 API 完全兼容、实现简单得多的替代运行时**——业务代码、hooks、第三方库一行不改。用法是 Vite 插件 `@tanstack/redact/vite`，或 Next.js 的 `withRedact` 包装（支持 Next 15.5 与 16.0–16.4，Turbopack / Webpack 都行）。gzip 后的整包对比（同一示例应用）：**TanStack Start 109.3 → 62.3 KB（−43.0%）**、**Vite 68.3 → 20.1 KB（−70.5%）**、Vinext 138.1 → 98.8 KB（−28.5%）、**Next.js 175.6 → 139.9 KB（−20.4%）**；开启特性裁剪后还能再降（Start 到 59.8 KB，纯客户端 Vite 配 `preset: 'nano'` 到 12.6 KB）。覆盖范围要看清：React 19 的元素模型、全套 hooks、类组件、Suspense / Portal / Error Boundary、流式 SSR 与水合、`useTransition` / `useDeferredValue`（同步实现）、Server Actions 与乐观状态都在；**Flight 客户端反序列化器、DevTools 协议、真正的并发模式**不在范围内，Next.js / Vinext 下 React 仍负责 SSR 与 RSC，Redact 只接管水合与客户端渲染。**代价写得也很诚实**：渲染是**完全同步**的，没有时间切片、没有可中断渲染——微基准里稀疏更新更快，但**水合慢约 21%**、**Suspense 重试轮次慢约 125%**（每轮约多 0.15 ms）、保留堆略高，官方建议先拿最忙的页面压测。⚠️ 0.2.x 仍是小版本号，且它已在 tanstack.com 自己生产环境跑了半年（自 4 月起）——这是加分项不是担保。

### 📚 好文精选

- **[《The agentic web is here》：网页正在被重建，而新读者不是人](https://www.technologyreview.com/2026/11/02/1147846/the-agentic-web-is-here/)**（MIT Technology Review，Grace Huckins，2026-11-02）：配合上面 Chrome 157 那条一起读最合适——**前端的「入口」正在从页面转移到接口**。文章的框架很好用：先是 2001 年语义网的失败（要给页面人工打标签，成本高、收益低）与 LLM 的对比（**不需要标签就能解析页面**），再是真正的冲突点——**平台开始自行决定哪些 Agent 可以行动**：Meta 的 Muse 被亚马逊拦下，因为亚马逊要推自己的 Alexa for Shopping。经济侧的三个数字构成了压力来源：Pew 的研究显示带 AI Overview 的结果**点击率低约 40%**、Digiday 称出版方广告供给 **Q2 下降最多 40%**、以及一项研究发现 Agent 会**惩罚标注为 sponsored 的条目**。建设路线也分成两派：**把 Agent 训练得像人一样浏览**，还是**给 Agent 造机器原生的工具与 API**（McGill 的 Siva Reddy 从浏览器方案转向了工具方案）。对做产品的人，读完只剩一个具体动作：**你的站点/应用是否有一个「给 Agent 用」的入口，而不只是给人看的页面**。
- **[等一下，那篇 MIT 科技评论把「部分得分」算成了 73% 成功率](https://sxz.io/mit-technology-review-agentic-web-is-here-osworld-partial-score-doordash-agent-orders/)**（2026-11-02 ~ 03）：这篇是对上面那篇的**事实核查**，价值在于教你怎么读 AI 报道里的数字。两处纠正：**一、OSWorld 的分数不是成功率**——原始指标是**部分给分（partial credit）**的任务完成度，报道里把它当成了「73% 的任务被完成」；**二、DoorDash CEO 说的「外部 AI Agent 订单数百」不是增长数据**，而是对量级的描述，与「Agent 已经在替你下单」的叙事无关。它还指出被引用的一项预印本（Allouah 等人的 *What Is Your AI Agent Buying?*）自己明确说明**「Agent 惩罚 sponsored 条目」不等于「付费广告不赚钱」**，因为付费位仍然买的是首屏位置。**结论不是「别信报道」，而是：凡是被反复转述的百分比，回到论文里看它的分子分母是什么。** 这条对做技术选型的人尤其重要——你引用进 PPT 的那句「某模型完成率 73%」，很可能在原始论文里是另一回事。

### 🧰 其他值得关注

- **⚠️ [MCP 生态的「安全债」被两份审计同时摊开：61 个厂商 server 里 36 个仍在用已废弃的注册方式](https://theagenttimes.com/articles/mcp-auth-audits-find-pervasive-spec-gaps-across-remote-serve-6998552a)**（2026-11-03）：两条独立审计指向同一个问题——**规范已经往前走了一版，生态没跟上**。X1Y1 的审计按 **2026-07-28 版规范**扫了 67 个厂商 MCP server：只有 **25/61** 声明支持 **CIMD**（Client ID Metadata Document），**36 个仍在使用已废弃的动态客户端注册（DCR）**，**40/61 缺 RFC 9207 的 `iss` 参数**（授权响应来源校验），**22/61 完全没有 scope 提示**。另一份「patchbay 审计」扫了 25 个端点：**8 个无需凭据即可公开访问**，其中 **2 个暴露了会改数据的工具**。再叠上 Glow Labs 在 **11-02** 报的 **MCPhantom**——Agent 会**从训练数据里「回忆」出早已废弃的 `@modelcontextprotocol` 参考 server 并装上去**，其中一个带**未修复的 RCE**——风险链条就完整了：**客户端装错 + 服务端鉴权弱 + 授权校验缺参数**。可执行的动作三条：**审计你自己的 MCP server 有没有 `iss` 与 scope 声明、把 DCR 换成 CIMD、在 Agent 侧固定 server 版本与来源白名单而不是让它自由"想起"某个包**。反过来看，Vercel 在 11-03 把自家 MCP **开放给任何发布 CIMD 的客户端**，并上了第一个 MCP App（在 ChatGPT 里显示部署卡片）——说明 CIMD 这条路正在成为事实标准。
- **[OpenAI 启动 Grid Protectors：电网吃紧时，自家数据中心主动降载](https://openai.com/index/grid-protectors-program/)**（2026-11-02 宣布）：这条对国内读者略远，但它解决的是一个所有做大规模推理的人都会遇到的问题——**算力和电网的关系正在写进商业合同**。机制是需求响应：**在电网承压时削减自家园区的用电**，削减的是**弹性负载**（批处理训练、预取、评测），保住**对延迟敏感的推理**，必要时也会上现场发电与电池。首个试点是佐治亚州 Effingham 县的 **Project Camellia**（**3.2 GW**，2028 年投运、2028–2032 分期交付）：与 Georgia Power 的 **25 年**协议在 **8 月**获批，允许电力公司在需要时削减**最多 1,000 MW**——约为该园区峰值负载的 **31%**，大致相当于 **70 万户家庭**的平均用电。Georgia Power 估算，这种灵活性到 **2029** 年起每年可为用户省约 **9.5 亿美元**（普通 1,000 kWh 住户每月至少省 15 美元）。⚠️ 三个保留：**这是「非约束性」的自愿承诺，不是合同**；**只覆盖 OpenAI 自建的园区**（租用与合作伙伴的不算），且目前只点了这一个站；**灵活性替代不了新建发电与输电**。
