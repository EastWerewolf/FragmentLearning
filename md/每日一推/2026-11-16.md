### 🚀 框架与工具链

- **[Vite 开发服务器可被远程执行代码：`__vite-browser-external` 虚拟模块没做转义](https://github.com/vitejs/vite/security/advisories/GHSA-p4f5-76q4-ffq7)**（GHSA-**p4f5-76q4-ffq7**，修复随 **8.3.7（11-09）** 及各维护线补丁版发出；中文周报第 154 期在 **11-16** 汇总）：**漏洞机制很直白**：解析插件生成的 **`__vite-browser-external:<suffix>`** 与 **`__vite-optional-peer-dep:<suffix>`** 两个虚拟模块，**把 URL 派生的模块 ID 原样嵌进去、没有转义**，于是构造一个 HTTP 请求就能往模块里注入任意代码。**两个后果**：**①** 被注入模块 import 的东西**绕过 `server.fs` 允许清单**——`import '/path/to/secret.txt'` 之后，原本 403 的路径可以通过 `/@fs/...` 读出来；**②** Vite 为 `new Worker` / `import.meta.glob` 取值用的 `eval` 让攻击者能**在服务端执行代码**（PoC 用 `globalThis.process.getBuiltinModule` 绕过 exports/require 黑名单）。**受影响**：8.3.0–8.3.6、8.2.0–8.2.4、8.0.0–8.1.6、7.0.0–7.3.7、4.0.0–6.4.5，以及 `vite-plus` ≤1.5.0。**修复**：**8.3.7 / 8.2.5 / 8.1.7 / 7.3.8 / 6.4.6**，`vite-plus` **1.5.1**；v8 的实际修复在 **Rolldown** 二进制里（8.3.7 依赖 Rolldown **1.2.17** 的修复，8.1.7 依赖 **1.1.7**），所以**只升 Vite 就够，前提是你没有自己覆盖 Rolldown 版本**。⚠️ 四点：**前置条件是 dev server 被显式暴露**（`--host` 或 `server.host`），**只在本机 `localhost` 跑的不受影响**——但「用 `--host` 给手机真机调试」正是很多人的日常；**dev server 不是生产服务**，可这个洞能读走你本机任意文件，等价于把开发机交出去；`vite-plus` 是另一条线，别只升 vite 包；另外这条 GHSA **页面本身没给出发布日期**，日期以 npm 上的补丁版本为准，**建议今天 `npm ls vite` 对一遍**。

- **[《11 月的浏览器更新，悄悄给博客主题减了 18KB：脚注、浮层、下划线，不用 JS 了》](https://aimomo.pages.dev/en/blog/blog-chrome-anchor-positioning-blog-theme/)**（**2026-11-14**）：**这篇的价值是把「新特性」换算成「能删掉哪个依赖」**。**① 锚点定位**：`position-anchor` + `position-area` + `position-try-options` 配合 `popover`，替掉 Popper.js（**18KB**）/ Floating UI（**12KB**）——视口碰撞检测、自动翻转、滚动重新锚定都由浏览器做，**12KB+ 的依赖换成不到 200 字节 CSS**（标题里的 18KB 就是这么来的）。**② `text-decoration-inset`**：直接调下划线/上划线/删除线的起止点，解决中文博客里链接下划线**遇到全角标点或半角括号会多伸出一截**的老问题，不用再靠 padding + `text-underline-offset` 或背景渐变伪造。**③ HTML setter 方法**：`setHTML()`、`replaceWithHTML()`、`beforeHTML()`、`prependHTML()`、`appendHTML()`、`afterHTML()` 及 unsafe 版本，**走浏览器内置 sanitizer**，做搜索高亮和评论渲染比手拼字符串安全得多。**④ 顺带提到** HTML-in-canvas 与 Firefox 新增的 SpeechRecognition。**作者自己的结论也是最该抄的那句**：这些能力**只在 Chrome / Edge 就位**（**Firefox 至今不支持锚点定位**），所以**渐进增强，别直接删依赖**。⚠️ 三点：**18KB 是「可以删」不是「应该删」**——你的浮层如果带复杂定位逻辑或需要 Firefox 一致行为，保留 Floating UI 更省事；**`::highlight(*)`、`text-decoration-inset`、HTML setter 的浏览器覆盖各不相同**，逐项查 Baseline 再动手；**「浏览器内置 sanitizer」不等于零风险**，`unsafe` 版本仍会执行你传进去的内容，用在评论渲染上要配合 CSP。
