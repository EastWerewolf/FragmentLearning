### 🤖 AI 与开发

- **[Modern Web Guidance 1.0：把 200+ 篇 Web 平台指南装进 coding agent，还拉上了 Edge / Firefox / MDN](https://developer.chrome.com/blog/modern-web-guidance-v1)**（2026-11-10 发布，Philip Walton 执笔，11-11 起被广泛转述；今年 5 月 I/O 上的 preview 转正）：**它解决的是「Agent 写 2019 年的代码」这个问题**，做法是把「什么才是现在该用的写法」变成可安装的 skill：`npx modern-web-guidance@latest install`（用 `update` 更新）。**1.0 新增四件事**：**① modernization workflow**——`legacy-scan` 用 AST / DOM / CSS 解析器**静态**扫 HTML/CSS/JS/TS/`package.json`，找出过时写法并映射到现代替代（**不花 token、不走 LLM**）；**② 指南库扩到 ~200+ 篇**（覆盖约 250 个 Web 平台特性）；**③ 更深的人工审核**——领域 tech lead 签字 + 面向用户的指南单独过无障碍评审；**④ 公开的 eval 面板**——每晚跑「带指南 / 不带指南」的对照，**在真实浏览器里检查 DOM、样式与源码**。**治理侧是关键信号**：项目已变成跨浏览器合作，**Chrome、Microsoft Edge、Mozilla/Firefox、MDN 共同参与**，GitHub 治理文档（11-09 上传）定了 6 个席位：**Chrome 2 席、Edge 1 席、Mozilla 1 席、独立专家 2 席**——**没有 Apple/Safari 的席位**。**跑分**（Google 自述，11-08 夜间批）：**带指南约 88% 通过、不带约 56%**，每个 agent 199–215 个任务；分 agent 看 **Antigravity/gemini-4-argon 60% → 98%**、**Codex/gpt-6.1-sol 50% → 86%**、**Claude Code/opus-5-5 58% → 94%**。**早期用户**：日本 note inc. 在 180 次运行里从 60.8% → 76.5% → 94.0%（不带 → 带但没点名 → 带且点名）；MetaMask 拿它当 PR 审查机器人，5 周约 480 个 PR，评论 64 个、修掉 43 个、修复中位耗时 15 分钟。⚠️ 四条保留：**一、带指南的跑法更慢、更费 token**，这是明确的取舍不是免费午餐；**二、eval 面板的无障碍评审不等于 WCAG 审计**，而且**提示词里不会点名「请用这条指南」**，要靠 agent 自己判断何时适用；**三、所有跑分都是 Google 自己的**，独立复现还很少——Adrian Roselli 对 5 月 preview 版的独立测试就发现过 WCAG 不合规与 Firefox 下动画失效；**四、没有 Apple 席位意味着 iOS 上的行为不在这个知识库里被保证**，做 Safari 兼容的项目要自己补。
- **[Gemini Decisions API / Decision 1：一个不生成文本的模型，只输出概率，$0.10 每百万输入](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/)**（2026-11-11 在 AI Studio 开放 preview，模型 ID `gemini-decision-1`）：这是本周最有意思的 API 设计，因为它**把「判断」从「生成」里拆了出来**。**机制**：不给候选选项写一段话，而是**一次前向计算给每个候选打分**，返回概率与置信度；支持**是/否、多选（最多 255 个选项）、按评分标准打分**三种形态；输入可以是文本、图片、音频、视频、PDF。**延迟**：模型计算中位 **50–100 ms**，端到端 **150–250 ms**；**请求内问题数从 1 涨到 100，延迟几乎不变**（问题并行评估、彼此不可见）；**单请求最多 1,000 个问题**，单条多模态输入最多 **256K token**。**定价**：输入 **$0.10 / 百万 token**，**输出不计费**——Google 自己的测算约比 Gemini 3.5 Flash-Lite 便宜 5 倍。**内部已经在用**：Gemini Notebook 用它做「该用哪个模型 / 哪档思考强度」的路由，**日常请求延迟降了最多 40%**；Stitch 与内部 app「CC」也在用。⚠️ 四点：**一、它是 preview**，SLA、区域可用性、限额都还没承诺；**二、它只能回答「哪个更好」，不能给出理由**——需要解释链路的地方仍要回到生成模型；**三、1,000 个问题一次请求听起来很爽，但问题之间互不可见**，需要「后一个问题依赖前一个答案」的场景用不了；**四、$0.10 的单价看似极低，实际成本取决于你把多少上下文塞进去**（256K 的多模态输入按输入价计），**做成本评估要按「每次判断带多少上下文」算，而不是按问题数算**。

### 📚 好文精选

- **[《AI 在 Web 开发中容易出错的 10 大问题》：前沿模型也过不了一半现代 Web 检查](https://developer.chrome.com/blog/top-10-things-ai-gets-wrong-in-web-dev)**（Chrome for Developers，**2026-11-11**）：和上面 Modern Web Guidance 1.0 是配套的一篇，但**单独读更有用**，因为它把「Agent 写的代码哪里不对」从感受变成了条目。作者的起点是那句被反复引用的话：**即使最前沿的模型，也大约有一半的现代 Web 检查过不去**。已确认的前四类问题都极其具体：**① 焦点管理**——打开新视图不把焦点移进去、关闭不还原；自建模态框用手写 JS tab 陷阱而不是 `<dialog>` 或 `inert`；工具栏/网格的每一项都成了独立 Tab 停靠位而不是 roving tabindex；自定义 `:focus-visible` 轮廓对比度低于 3:1。**② reduced motion**——无条件全局 `scroll-behavior: smooth`；滚动驱动动画不检查减少动画偏好；只删 transition 时长却留下 transform 导致跳变；用一刀切 `0.01ms` 重置把必要过渡也清掉；跨文档视图过渡无条件开启。**③ 表单验证 / 格式提示 / 自动填充**——用 JS blur 重造 `:user-invalid`（Tab 跳过必填字段就被误标）；`aria-invalid` 与可见错误不同步；靠会消失的 placeholder 提示格式；提示放在 input 下方被软键盘或 autofill 遮挡；`:autofill` 只改边框颜色、没有非颜色提示。**④ 手势**——惯用命令式 JS 自写滑动物理，而不是 `touch-action` 与滚动捕捉这类能跑在主线程外的原生能力。⚠️ 两点：我看到的抓取摘要**只到第 4 条**，**第 5–10 条（推测涉及性能与安全）需要打开原文**；另外**这篇是 Chrome 团队自述**，结论和 Modern Web Guidance 的 eval 面板同源，**当成「一份高质量的缺陷清单」来读，而不是独立评测**——但清单本身可以直接拿去写你自己项目的 review 规则。
