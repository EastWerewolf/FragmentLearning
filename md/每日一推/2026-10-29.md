### 🚀 框架与工具链

- **[Wails v3.0.0 正式发布：用 Go 写桌面应用，四年 alpha 终于落地](https://v3.wails.io/blog/)**（2026-10-26 稳定版）：如果你在评估 Electron 的替代品，这是一个真正的节点。首个 v3 alpha 在 2023 年 1 月，v3.0.0 把 v2 时代欠的东西补齐了——**多窗口、系统托盘、原生菜单与对话框、service 自动生成绑定**、基于 Taskfile 的构建系统、应用内更新器，以及实验性的 **iOS / Android 移动端**支持。Linux 默认切到 **GTK4 + WebKitGTK 6.0**（GTK3 靠 `-tags gtk3` 保留到 v3.1），用 **Go 1.26** 构建。两条工程影响：**v3 之后改为每周发版**（配每日 nightly 与紧急 hotfix），节奏明显快于 v2 时代；`wails` 与 `wails3` 是两个可共存的 CLI，**v2 进入只修严重问题的维护状态**。迁移要按真正的移植来估——应用与窗口生命周期、service 绑定、运行时 API 全变了，不是改个版本号能过的。⚠️ 移动端仍是实验性；生态与文档成熟度与 Electron / Tauri 还有差距。
- **[TanStack Redact：把 React 的运行时换成三分之一大小的兼容实现](https://tanstack.com/blog/introducing-tanstack-redact)**（v0.2.0，2026-10 中旬发布；10-28 的技术周刊仍在讨论，按「近期持续发酵」收录）：做法是**构建期换心脏**——通过 Vite 插件把 React / ReactDOM 的公开 API 换成一份更小的实现，应用代码一行不改；已支持 TanStack Start、Vite、Vinext、Next.js（App 与 Pages Router 都行）。官方给的是整包 gzip 对比：Start **109.3 → 62.3 KB**、纯 Vite **68.3 → 20.1 KB**、Vinext 138.1 → 98.8 KB、Next.js 175.6 → 139.9 KB（关掉可选特性后纯客户端可到 **12.6 KB**）。**代价必须讲清楚**：它是**同步渲染**，没有并发时间切片、没有可中断渲染，重渲染会卡输入；第三方复测里 Suspense 重试慢约 **125%**、水合慢约 **21%**。所以它不是「React 更快了」，而是「用一部分调度能力换体积」。⚠️ 仍是 pre-1.0，基准是整包总量而非单页，也没测渲染速度。

- **[Axiom Math：数十个 Agent 花 24 天，把「有限单群分类」完整形式化进 Lean](https://axiommath.ai/research/the-enormous-theorem-formalized/)**（2026-10-26 宣布，10-27 放出仓库）：这是「AI 做数学」里规模最夸张的一次——原定理（CFSG，绰号「巨大定理」）由约 100 位数学家在 500+ 篇论文里写了 **1.5 万页**，Axiom 用 **AxiomProver** Agent 集群在 **24 天**内产出约 **4310 万行 Lean 4**、**205 万条声明**、108 个里程碑 / 约 380 个任务、715 条参考文献，建立在 Mathlib 与 TauCeti 之上，并复用了 Qiuzhen-CFSG 的约 120 万行。过程细节比结果更有信息量：10-01 开 Slack 频道、10-02 集群上线，Agent 自己在 GitHub issue 里**认领任务**；10-10 打出「WE PROVED MONSTER IS SIMPLE」；10-13 卡住后重新规划；早期因为 Agent **偷偷引入未证明的假设**，删掉了几万行。最有价值的产出是 **34 处与已发表文献的偏差**，其中一处是 **John Walter 1986 年研究非平衡群定理路线里躺了近 40 年的缺口**（闭包步骤存在反例），团队用一个基于 Ronald Solomon 1976 年工作的新结果（「单顶点保持定理」）补上；顾问是 **Richard Lyons 与 Ronald Solomon** 本人。⚠️ 关键保留：**尚无独立评审或外部重建**，行数口径在不同来源间不一致（Axiom 自己的推文曾写 5000 万行），而且 Lean 只能验证「推导合规」，**不能验证形式化陈述真的等于 CFSG**——这一点和 10-27 推过的 OpenAI 三项证明是同一类问题。
- **[Meta Andromeda：单台 GH200 每秒筛 100 亿条广告，推理 FLOPs 降约 300 倍](https://engineering.fb.com/)**（2026-10-28 工程博客）：推荐系统里「检索」这一段的范式变了。老办法是拿轻量模型把海量候选砍到几千条再精排，Andromeda 直接**把接近精排的质量搬到检索阶段**——用 **retrieval MoE**（多个专门的 user tower 当专家 + 基于注意力的门控）替代单塔。撑住这个代价的是**模型-系统-硬件协同设计**：单个融合 kernel 把中间结果留在寄存器/共享内存里，绕开 HBM 带宽瓶颈；索引匹配、打分、top-K **全部落在同一块 GPU 上**，网络流量降约 100 倍。官方数字：相比 2024 版**吞吐 100 倍**、FLOPs 约 1/300，单台 **NVIDIA GH200 Grace Hopper** 上融合 kernel 超过 **100 亿广告/秒**；与 NVIDIA 的合作（2026 年初启动）把门控 kernel 提速 5.3 倍（约 85% 峰值 HBM 带宽）、INT8 量化收益翻倍、索引匹配超过 **1000 亿广告/秒**。业务侧自报 Facebook 转化 **+2.4%**。⚠️ 全部为 Meta 自报，没有绝对延迟、成本变化与第三方复现；从工程视角看，这条对我们做前端/后端的人真正的提示是：**「把中间结果留在片上、把相关步骤放到同一设备」**这条优化路线，在被 GPU 逼到墙角之后又回到了系统设计的中心。
- **[蚂蚁发布灵光 2.0：退出对话，任务还在后台跑](https://m.ithome.com/html/1018252.htm)**（2026-10-27 发布，10-28 媒体集中报道）：从「任务执行者」转向「事务管理者」。三处升级值得分开看：**主动发现需求**（用户授权后，它自己识别潜在任务并发起分析、监控、跟进，在关键节点汇报）；**独立云主机 + 长程任务调度**，即使用户退出对话，任务仍在后台运行并按新信息调整；**跨会话记忆 + 工具连接**（开放环境下可调 MCP、CLI、浏览器，内置支付宝账单、会员、出行，以及钉钉、飞书、邮箱、米家）。演示场景很具体：盯机票酒店降价、从支付宝账单里找出被遗忘的自动续费、把班级群通知抽成待办并排版文档。安全上接入蚂蚁 **APASS**，**授权密钥与智能体分离托管**，用户可随时查看、调整、撤销授权。⚠️ 厂商口径，后台常驻任务的资源与费用模型、以及「主动发起」默认的授权粒度都还没公开细则；媒体把它称作「中国版 Muse」，但两者在分发与生态上并不对应。
