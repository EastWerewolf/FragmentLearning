### 🚀 框架与工具链

- **[jQuery 4.1.0 与 3.8.0 同日发布：3.x 只修关键问题，官方开始管「机器生成的贡献」](https://blog.jquery.com/2026/11/17/jquery-4-1-0-and-3-8-0-released-passing-the-torch/)**（**2026-11-17** 发布，标题就叫「Passing the Torch」；4.1.0 是 4.x 的第一个次版本，3.8.0 是 3.x 的**最后一个功能版**）：**这条对仍在维护老站的团队是硬信息**：**3.x 从今往后只收关键修复**，新功能只进 4.x。**两个版本共有**：**新的 AJAX transport `completeCallback` API**（回调改成收单个对象，不再用位置参数）、**修了选择器标识符匹配里的 ReDoS**、选择器内部的文档比较改为宽松比较。**4.1.0 独有**：`jqXHR` 加了 **`responseURL`**；`.serialize()` / `.serializeArray()` 支持**表单关联自定义元素**；`.css()` 这类方法在**非 XHTML 的 XML 文档**里可用；内部从 `getElementsByTagName` / `getElementsByClassName` 换成 **`querySelectorAll`**；非法的选择器转义序列解码为 **U+FFFD**；**`jQuery.uniqueSort` 去重从 O(N²) 降到 O(N)**；规避 **Safari 27 的正则解释器**问题。**文档侧有条新鲜事**：新增 **TuxCare 作为商业支持供应商**，并写了**「机器生成贡献」的处理准则**——对一个 20 年历史、AI 生成 PR 大量涌入的项目，这个动作比版本号更值得注意。⚠️ 三点：**升级 4.x 前先跑一遍插件依赖**，3.x 只修关键问题意味着第三方插件不会陪你等；**ReDoS 修复也回填到了 3.8.0**，所以「不想升 4」和「不安全」是两件事；**`uniqueSort` 的复杂度变化是大数组场景的实际收益**，但它不改变 API 语义，别指望排序结果变——它只去重。

### 🎨 浏览器与 CSS

- **[Chrome 159 发布说明上线：`@property` 描述符可省、Canvas 文本度量增强、跨源 iframe 可预渲染](https://chromestatus.com/release-notes/159)**（Beta 自 **2026-11-11** 起（159.0.8154.6），Android beta **.18** 于 **11-18** 推送；**Stable 定在 12-08**）：**先挑对写样式的人有用的五条**：**① `AccentColor` / `AccentColorText` 跟随 `accent-color`**——这两个系统色现在反映元素的**实际强调色**，不再只取平台系统色；**② 背景层数不再被 `background-image` 的层数对齐**——`background-*` 长属性的计算值会**保留作者写的逗号层数**，不再重复或截断；**③ `CSSImportRule.styleSheet` 在没有关联样式表时（包括 `supports()` 条件为假）返回 `null`**；**④ `@property` / `CSS.registerProperty()` 的描述符可以省略**，默认是通用语法、可继承、initial 为 guaranteed-invalid；**⑤ 单轴滚动容器的 scroll snap** 改为按轴处理，非滚动轴交给最近的祖先滚动容器。**Canvas 那条是这次最实用的**：**增强的 `TextMetrics`** 给了**选区矩形、包围盒查询与按字形簇（glyph cluster）的操作**——做文本编辑器、光标定位、命中测试、逐字效果的，不用再自己算度量。**其余几条**：**Sanitizer API 新增 `javascriptURLs` 选项**（把 `javascript:` 导航的净化改成**显式开启**，不再靠「安全方法」的副作用）、**跨源 iframe 可预渲染**（顶层响应要带 `Supports-Loading-Mode: prerender-cross-origin-frames`）、Service Worker 静态路由对「被取消的 `race-network-and-fetch-handler`」给出独立的 `TypeError`、**Web Speech 的 `SpeechRecognitionResult` 加了 `speechStartTime` / `speechEndTime`**、`MediaSession.setMicrophoneActive()` / `setCameraActive()` 改为返回 Promise（文档非完全活跃时 reject `InvalidStateError`）、**AudioWorklet 支持共享 MessagePort**（主线程与 worklet 全局作用域可直接通信，省掉 bootstrap processor）。Origin Trial 里还有 **WebAuthn Conditional UI 的 Passive（Ambient）模式**。⚠️ 四点：**这是 beta 的发布说明，12-08 前都可能改**；**「背景层数保留」会让依赖「计算值被对齐」的代码出现差异**，尤其是读 `getComputedStyle` 做动画的库；**`javascriptURLs` 是安全姿态的变化**——默认不再帮你处理 `javascript:` URL，用了 Sanitizer 的地方要显式打开；**跨源预渲染需要服务端配合发头**，前端单方面改不动。

### 🤖 AI 与开发

- **[Google 在 Gemini API 上预览 Tool Retrieval：工具 schema 按需加载，远程 MCP server 也能整体延迟](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/)**（**2026-11-19** 在 **Interactions API** 上线预览；仅支持 **Gemini 3.6 及以后**，含全部 Gemini 4 模型）：**它解决的是「工具太多，schema 把上下文塞满」这个具体账**：**做法**：加一个 **`tool_search` 工具**，并给要延迟的工具设 **`defer_loading: true`**——模型仍然看得到**每个工具的名字与描述**，但**完整的参数 schema 不进上下文**；模型需要时，API **在同一次请求内**把 schema 载进来再调用。**调试**：`tool_search_call`、`tool_search_result`、`function_call` 三步都会出现在 `interaction.steps` 里。**不需要你建索引、也不需要托管检索服务**。**对 MCP 生态最关键的一条**：给 **`mcp_server` 工具设 `defer_loading: true`**，**该 server 暴露的所有工具都按需加载**——大 MCP server 不用再逐个列出工具。**另一种模式**：把 `tool_search` 声明为 **`"execution": "client"`**，检索跑在你自己的应用里（多一次往返，但能**在对话中途暴露工具**、按用户权限过滤）。**计费**：没有单独的检索费，按标准 token 计价；开 `tool_search` 会多一小块固定输入，**被加载的 schema 仍按输入计费**。⚠️ 四点：**这是预览**，且**只在 Interactions API**，老的 `generateContent` 不支持；**Google 没有公布任何 token 或准确率数据**——Anthropic 去年上同类「Tool Search」时是带基准的，这次只能自己测；**工具一旦被检索出来就不能卸载**，且**每次请求仍要重发完整 tools 数组**，所以省的是「模型看到的上下文」，不是「你发出去的字节」；**它是把「工具选择」变成两次模型决策**，对延迟敏感的场景要实测。

- **[GitHub 给 Copilot 加了 8 个官方 MCP connectors：Supabase、Box、Webflow、Wix 等进公开预览](https://github.blog/changelog/2026-11-18-connect-supabase-box-calendly-and-more-to-copilot/)**（**2026-11-18** 发布，加入已有的 **25+** 个 GitHub 验证过的 MCP server（Slack、Figma、Sentry 等））：**新增的八个**：**Box**（内容检索与管理、Box AI）、**Buildkite**（流水线与构建）、**Calendly**（日程）、**ClickUp**（任务与项目）、**Mixpanel**（产品分析）、**Supabase**（项目与数据库）、**Webflow**（站点与内容）、**Wix**（站点与业务工具）。**官方给的用法很务实**：让 Copilot 先看某次 Buildkite 构建为什么失败、**在同一个会话里直接修**；或写迁移前先查 Supabase 的 schema。**入口有四个**：Copilot 应用「Customize → Connect」、Copilot CLI 的 `/mcp` → Connectors、VS Code 的 Agents 窗口 → Customizations、github.com 的 Copilot 定制页；**连一次，跨 Copilot 各端通用（包括 GitHub Mobile 的会话）**。**可用性**：**所有 Copilot 套餐**都能用公开预览；**Business / Enterprise 需要管理员打开「Editor preview features」策略**，如果组织用过**逐 connector 的 MCP 允许清单**，要把新的条目加进去；**Box 还要求服务侧管理员批准 MCP 访问**。⚠️ 四点：**「verified」不等于「随便连」**——这八个里有**可写**的（Supabase 改 schema、Webflow / Wix 改线上站点），先用只读或测试项目试；**真正该问的是「谁能授权」**，一次授权会把你的数据面交给 Agent，个人连和组织统一连是两种风险模型；**组织允许清单是硬门槛**，别以为个人能连就都能用；另外这条与 11-17 的 Copilot Evals、benchmarks 是同一条产品线的延伸，不是新协议。

- **[微软在 Foundry 推 Toolboxes：把工具、技能、Agent 打成版本化包，用一个 MCP 端点喂给整个 Agent 舰队](https://devblogs.microsoft.com/foundry/build-once-reuse-across-your-agent-fleet-tools-and-toolboxes-in-foundry/)**（**2026-11-18** 于 Ignite 发布；文档与示例已同步到 `learn.microsoft.com` 与 `microsoft-foundry/foundry-samples`）：**它把「工具」从单个 Agent 的配置提升成组织级资产**：一个 **Toolbox** 是**工具 + 技能 + Agent（A2A）的版本化集合**，通过**一个 MCP 端点**暴露，所有 Agent 共享同一份。**端点有两种形态**：**消费侧（默认版本）** `https://<account>.services.ai.azure.com/api/projects/<project>/toolboxes/<name>/mcp?api-version=v1`——它永远服务 `default_version`，**升级版本不用重新部署 Agent**；**开发侧（钉版本）** 在中间加 `/versions/<n>`。**鉴权**：Entra 的 bearer token，scope 为 `https://ai.azure.com/.default`，`api-version=v1` 必填。**怎么用**：Agent Framework 里有 **`FoundryToolbox`（Python）/ `AddFoundryToolboxes`（.NET）**，LangGraph 用 **`AzureAIProjectToolbox`**，也能拿任意 MCP 客户端直连；VS Code 支持**一键把 toolbox 写进 `.mcp.json` 给 GitHub Copilot 用**。**配套能力**：**按需的工具检索（tool search）**、**基于 Azure Policy 的工具策略预览**（允许 / 拒绝）、浏览器自动化 GA，**web search 仍是「即将推出」**。⚠️ 四点：**「默认版本 + 钉版本」是这套设计的核心**，但**默认版本的切换本身就是一次全局变更**，要当作发布来管；**工具策略是 Azure Policy 侧的执行**，不是模型自己守规矩；**它是 MCP 端点的封装**，所以 MCP 的安全问题（授权、数据边界）一个不少；**web search 还没上**，别按完整工具箱排期。

- **[Claude Code 三天连发 2.1.327 / 328 / 329：MCP 配置改走 stdin，`mcp_tool` 钩子终于能「失败即阻断」](https://github.com/anthropics/claude-code/releases/tag/v2.1.329)**（**2.1.327 于 11-17、2.1.328 于 11-18、2.1.329 于 11-19** 发布；是 11-19 那期推的 **2.1.326** 之后的三连）：**对写脚本和做自动化的人，最重要的是 327 的两条**：**① `claude mcp add-json <name> -` 从 stdin 读 JSON**——**token 不再出现在命令行历史里**（注意：**只能在会话外**用）；**② `/status` 变成诊断面板**，会列出**损坏的 agent / skill / command / output-style 文件、键位绑定错误、沙箱不可用、被忽略的权限设置，以及永远匹配不到的 hook matcher**。**权限与配置的文件安全**：`claude mcp add --scope project` 在 `.mcp.json` 缺 `mcpServers` 键时**不再覆盖文件**，`add/remove` 也**不再删掉 `$schema` 这类顶层键**；在 `/permissions` 里加的规则**写不进设置文件时会明确报警**。**2.1.328 的核心**：**`mcp_tool` 钩子支持 `"onFailure": "block"`**，与 `command` / `http` 钩子对齐——**钩子里的 MCP 调用失败时阻断动作**，默认仍是 `continue`。**2.1.329 的核心**：**信任对话框会告诉你某个文件夹的 hooks 声明在哪里**；managed settings 的钩子在非交互宿主（Desktop / SDK）加载失败时会**在对话里警告**；**Code Mode 里 `PreToolUse` 钩子报错不再直接拒绝脚本的工具调用**（与非 Code Mode 行为对齐）——想「失败即阻断」就显式给 `command` / `http` / `mcp_tool` 钩子设 `onFailure: "block"`；**`/tasks` 范围扩大**（定时任务、`/loop` 唤醒、fork），**`/mcp` 的 server 页加了「Server message」行**显示 JSON-RPC 错误；另外修了 `~/.claude.json` 被重置、macOS 反复登出，**`/code-review` 改为审查当前检出的分支而不是 PR**。⚠️ 四点：**三天三个版本，行为变更集中在钩子**——尤其 Code Mode 的「报错不再阻断」，升级后先确认你的阻断策略还在；**`/code-review` 的审查对象变了**，CI 里按 PR 预期写的检查要复核；**`add-json` 的 stdin 只在会话外**，别在会话里试；`/status` 会是排查权限问题的第一站，但它的输出也会变长。
