- **[tsrs：Cloudflare 与 VoidZero 把 TypeScript 编译器用 Rust 重写了一遍](https://blog.cloudflare.com/typescript-rust-port/)**（2026-10-20，Apache-2.0，v0.18 实验版）：起点很极端——作者 Max Schwenk（Owner.com）**一行代码都没手写**，由 AI Agent（据称以 Claude Opus 5.5 为主）以 TypeScript 约 **15,197 条 conformance 用例当规格**做成移植；动机是内存，他 3.7 万文件的后端在 TS 7.0 单线程下要 **19 GiB / 80 秒**。性能口径分三层：同 checker 数下比 **TS 7.0 快至 8×、内存少约 70%**（仓库 RESULTS.md 里 MUI docs 4 checker 约 11.8×、VS Code 约 13×）；作者自己对微软 Go 版 nightly 是 **2.5–5×、内存约 1/3**；有开发者指出把 worker 数对齐后**「8×」更接近 3×**。选 Rust 而不选 Go 的关键理由是 **WebAssembly**：Go 二进制要自带 GC，Rust 不用，所以能塞进浏览器、Workers 和 Agent 沙箱里做类型检查。微软在**同一天**发了 TypeScript 7.1 beta，Daniel Rosenwasser 承认部分优化是从 tsrs **上游回馈**的。现状：无 watch/LSP、只出 macOS ARM 与 Linux 二进制，正与 Theo Browne 的 **tsc-rs** 合并成一包。

### 🎨 浏览器与 CSS

- **[Safari 27.2 正式版：`flow-tolerance` 改名 `fit-tolerance`，新增 `::field-content`](https://webkit.org/blog/18515/webkit-features-for-safari-27-2/)**（2026-10-26 随 iOS / iPadOS / visionOS / macOS 27.2 发布，另供 macOS 26 与 Sequoia）：功能面不大但改动很具体。**Grid Lanes（masonry）的属性改名**——CSS WG 把 Safari 26.4（今年 3 月）引入的 `flow-tolerance` 定为 `fit-tolerance`，旧名保留为废弃别名、Web Inspector 会把要改的地方标出来；它的默认值是 `normal`（即 `1em`），WebKit 建议**多数场景应该明显调大**，否则卡片会往前一列挤、Tab 顺序也跟着乱。**可定制 `<select>` 多了 `::field-content`**，不用 `<selectedcontent>` 就能给选中项内容做样式；`appearance: base-select` 的默认样式也调了（垂直居中、`text-overflow` 继承、`flex: 1` 保住图标位）。顺带 **20 处修复**，其中两处对 Web 开发者有实际意义：一是**修掉了对 CNAME 托管站点误加的 7 天上限**（只影响页面响应里设置的 cookie，**不是**撤销 ITP 的脚本可写存储 7 天策略，别搞混）；二是 WebCodecs 的 H.264 Main/High 卡死、AAC/M4A 的 `decodeAudioData()` EncodingError、以及 Safari MCP 被控时抢焦点等问题。同批还有大量 WebKit 安全修复。

- **[微软开源 Agensh：1,024 个编码 Agent 没有「工头」，自己抢活干](https://github.com/microsoft/Agensh)**（2026-10-24 开源，MIT；论文 arXiv 2609.26781 于 9-22 挂出）：结构上刻意去掉中心编排——**每个 worker 跑同一套循环**：收集上下文 → 发 `CLAIM` 认领子任务 → 执行 → 验证 → 合并 → 发布，异步推进；**协调逻辑写在 prompt 里而不是运行时里**，除 ID 外所有 Agent 拿到的提示词完全一样。撑起协作的只有三样朴素设施：**Gitea** 当共享工作区（分支、PR、冲突都看得见）、**Mattermost** 当消息层、一块改造自 DeLM 的 **append-only 看板**（`OBSERVED` / `FACT` / `FAIL` / `CLAIM` / `PATCH_SUMMARY`），整体搭在单 Agent harness / GitHub Copilot CLI（ACP）之上。成绩单是 ProgramBench 最难的五项重建任务（FFmpeg、gromacs、pandoc、PHP-src、ctags），6 小时、离线：GPT-5.6-sol 五任务均值 **19.31%（1 agent）→ 28.78%（128）**；pandoc 单项 33.89% → 50.94%（128）→ **55.06%（1,024）**；换成 GPT-6.1-sol，pandoc 从 56.19%（1）到 **79.59%（32）**。有意思的是规模上去后**自发出现了同伴协调、集成流程和专门角色**。⚠️ 没有与中心化编排的对照实验、1,024 agent 只在 pandoc 一个任务上跑过、**大规模并行的 token 成本没披露**，别把「更多 Agent = 更好」当成结论。
- **[腾讯开源 Hy-Nomas：8B 交互式视频世界模型，单张 4090 能跑](https://github.com/Tencent-Hunyuan/Hy-Nomas)**（权重 2026-10-21 上传 Hugging Face，10-23 官方宣布，Apache-2.0）：不是「一句 prompt 出一段视频」，而是**逐段生成一个可以被操控的世界**——每一轮用文本指令加相机轨迹引导，靠 lifelong KV cache 保持前后一致，演示里能直接用 **WASD / 方向键**走位。规格：8B 参数，**720×1280 / 24fps / 最长 60 秒**，**360K token 上下文**；骨干是 54 个双流 MMDiT block，文本编码器用 **Qwen2.5-VL-7B-Instruct**，解码器是微调过的 PixelUMM，latent 为 32 通道 DCAE-V；训练用 **Segment Forcing**，蒸馏 checkpoint 支持 **4/6/8 步**去噪。开源包里东西很全：base + distilled + **INT8 DiT**、Cinematic LoRA、Robotics LoRA（双臂数据集）、Nomas-PE prompt 增强器、训练/推理/数据标注代码、web demo，以及 **Hy-Nomas-Bench**（280 个用例，覆盖多轮文本与相机控制、交错控制、空间记忆）。部署上，**单张 RTX 4090** 靠 INT8 权重与缓存 + FP8 解码器 + CPU offload + 18 帧滑窗能跑（代价是速度和显存上限），实时流式 profile 则是 **8× B200 + ≥128GB 主机内存**。⚠️ **没有技术报告**（链接标注 coming soon 但 404），也**没有公开基准分数**，质量全凭官方 demo；发布一周热度不高（X 约 900 赞、GitHub 约 186 star），ComfyUI 移植倒是很快出现。
