### 🎨 浏览器与 CSS

- **[倒计时：11-17 的 Chrome 158 将停用 XSLT，两条续命通道只到 2027-08](https://developer.chrome.com/docs/web-platform/deprecating-xslt)**（时间表已推进到执行阶段；今天 Edge 157 发行说明补充了它的节奏）：如果你维护着任何**用 `<?xml-stylesheet type="text/xsl"?>` 渲染的 RSS / 站点地图 / 旧报表 / 企业内网页面**，这条是本月唯一「不改就坏」的事。完整时间线：**142**（2025-10-28）先出控制台警告 → **143**（2025-12-02）正式弃用，控制台与 Lighthouse 都会提示 → **145** 在 Canary/Dev/Beta 默认关闭 → **146**（2026-03-10）开放**企业策略（EP）** → **152**（2026-08-25）开放 **Origin Trial（OT）** → **158（2026-11-17）稳定版停用**，仅 OT 与 EP 参与者可用 → **176（2027-08-17）OT 与 EP 一并结束**，对所有人彻底禁用。Edge 的节奏慢一步但更早亮牌：**157 的 Canary / Dev / Beta 已默认关闭 XSLT，Stable 的关闭定在 159**。理由在官方文档里写得很直白：`libxslt` / `libxml2` 是日渐老化的 C/C++ 代码库、反复出内存安全漏洞（CVE-2025-7425 等），而**用到 XSLT 的页面加载只有约 0.02%**；WebKit 与 Gecko 也支持移除。**注意边界**：移除的只是 **XSLT**——XML 本身还在，`type="text/css"` 的 XML+CSS 渲染照常工作；Chromium 还计划把 libxml2 换成内存安全的 Rust XML 解析器。迁移有四条路：**服务端渲染**、改成 JSON + JS 渲染、用 Saxonica 的客户端 XSLT 3.0、或者上 **WASM polyfill**（可一行 `XSLTProcessor` 替换，也能用一行 script 标签覆盖 PI 文档）。**怎么知道自己中招了**：用 `ReportingObserver` 监听 `deprecation` 类型、id 为 `"XSLT"` 的报告，或用 Chrome Enterprise 的 Legacy Tech Report 扫。⚠️ 一个已经踩过的坑：Chrome 曾注入「XSLT 已禁用」的**警示横幅**，把内嵌 XSLT 输出的企业界面撑坏，该横幅在 M154 被 Finch 临时关掉——如果你的页面会被注入这类横幅，布局要留余量。
- **[Firefox 160 定档 11-10：`::-webkit-input-placeholder` 成了正式别名](https://developer.mozilla.org/en-US/docs/Mozilla/Firefox/Releases/160)**（Beta 自 2026-10-26，稳定版 **2026-11-10**）：两条对写 CSS 的人有用。**一、`::-webkit-input-placeholder` 现在被当作 `::placeholder` 的别名支持**（纯为站点兼容）——意味着你 CSS reset 里那串 `::-webkit-input-placeholder` / `::-moz-placeholder` / `:-ms-input-placeholder` 的兼容三连**可以删到只剩 `::placeholder`**（除非还支持很老的浏览器）。**二、CSS anchor positioning 现在会考虑锚点元素自身的 transform**（bug 2059840）——之前锚点被旋转/缩放后定位框会飘，这个修复让「tooltip 挂在被 transform 的元素上」终于能对齐。其余：**Web Speech API 补上了识别端实现**，可以在 40 种语言上做本地实时语音转文字；CSS Typed OM 的 `CSSNumericValue` 有了 `add()` / `sub()` / `mul()` / `div()`（要开 `layout.css.typed-om.enabled`，`max()` / `min()` 要等到 161）；非 Web 平台的还有置顶浮动「Mini Window」、画中画 0.25x–2.0x 倍速、MKV 容器里 FLAC/MP3/PCM 音频可播、macOS 上 WebGL 走 Metal、Android 默认开启 Local Network Access 限制。

### 📚 好文精选

- **[Qwen 3.8 27B 在我笔记本上也能「读懂」模型权重](https://simonwillison.net/2026/nov/3/qwen-can-interpret-model-weights/)**（Simon Willison，2026-11-03）：这条值得读，是因为它把一个听起来像营销的论文**变成了你今晚就能复现的实验**。原论文是 MIT CSAIL 的《Sparks of Weight-Space Programming》（Rikiya Takehi、Jayden Teoh、Alex Zhang、Omar Khattab），最炸的说法是前沿模型能直接读、直接改神经网络的浮点权重（例：只动 Qwen3.5-0.8B **0.016%** 的权重，把 MATH-500 从 **7.9% 提到 48.1%**）。Willison 复现的是**「无工具读取」**那一半：研究者用 PPO 在 10×10 的简化网格上训了四个策略网络（**Breakout / Pong / Pac-Man / Freeway**），**架构完全一致**（500→32→32→5 的 MLP，共 **17,253 个权重**），只有数值不同；把权重以文本喂进去、不给任何工具、单次回答，问它是哪个游戏。他在笔记本上用本地 **Qwen 3.8 27B**（17 GB 的 Q4_K_M 量化，LM Studio）跑出来的结果：**Pac-Man 对**（72% 置信，46 分 12 秒，43,506 reasoning token）、**Pong 对**（75%，1 小时 4 分 54 秒）、**Breakout 对**（88%，52 分 25 秒）、**Freeway 错**（被判成「类 Pac-Man 的网格游戏」）；另用 OpenRouter 上的 **Kimi K3.1 Pro** 9 分 41 秒答对 Breakout。**真正有用的是那些工程细节**：必须把上下文窗口从默认的 **8,192** 调上去，单次推理要跑 **45 分钟到 1 小时**——也就是说这是「可做」不是「可用」。**批评也要一起读**：spaCy 作者 **Matthew Honnibal** 直指论文**把「无工具读权重」和「有代码辅助改权重」混为一谈**，属于误导；Sean Goedecke 则把那个 0.8B 的例子拆成「人类 ML 研究者本来就会做的步骤」。Willison 自己也很克制：**「我不准备宣布源码时代结束了。」** 想自己试的，prompt 就放在 `RikiyaT/lm_understand-logs` 仓库的 `exp1_which_game/` 下，是自包含的。
- **[快手：AI 生成代码占比从 26% 到 60%，我们怎么管住增量风险](https://www.infoq.cn/article/XieGrL5pws7jG1zxKPle)**（InfoQ，AICon 北京演讲整理，2026-11 上旬）：这是一篇**讲落地约束**而不是讲能力的文章，正好补上「Agent 写得多之后怎么办」这个缺口。核心思路是把 AI Coding 的风险**按增量切**：不是等代码评审时才发现问题，而是在生成、提交、合并的每一步设闸。文中给出的抓手有三层——**415 条规则**构成的检查基线、**分层防御**（不同风险等级走不同网关门）、以及 **Skill 质量门禁**（把「这个 Skill 的产出可信吗」变成可校验的对象，而不是靠人肉抽查）。对已经在用 Claude Code / Cursor 的团队，最可抄的是它的**度量方式**：先承认 AI 生成占比会涨到 60%，再把「能不能合并」的判断拆成规则可判定的部分与必须人工的部分，**别指望用更长的提示词解决流程问题**。⚠️ 这是演讲整理，具体规则清单与门禁实现细节需以分享者原始材料为准。

- **⚠️ [PolinRider 回来了：10 个被劫持的 npm 包里藏了 12 个恶意版本，用区块链当死信箱](https://www.ox.security/blog/polinrider-returns-hijacked-npm-packages-use-ethereum-blockchain-to-conceal-malware-infrastructure/)**（2026-11-03 ~ 04，Sonatype 追踪号 `sonatype-2026-010515`）：**这条对每个装包的人都有直接影响，因为 `--ignore-scripts` 挡不住它**。涉及包以 `@adminide-stack/*` 一族为主（`client-redux`、`health-api-server`、`user-activity-browser`、`utils`、`forms-core`、`yantra-help-browser`），另有 `server-hemera-mongo`、`cdeops`、`@cdmbase/wiki-browser`、`@pubngo-stack/help-browser`；OX Security 还点了 `react-contact-forms` 与 `tailwindcss-form-utils`——**注意这批包大多是长期没动静的项目，被接管后才发的毒版本**。手法是这次最值得记的部分：**用以太坊区块链做死信箱（dead-drop）**——loader 去查硬编码钱包 `0x1eef0849eda15d87f64e51c73c8442cf3c8bcef3` 的交易记录，从中解出 C2 的 IP，再下载 XOR 编码的 JS 并用 `eval` 加分离的 `node -i` 进程执行（**不落盘、无文件**）。混淆有两种变体：Base64（`eval(atob(...))` 藏在约 150 个制表符之后）与字符置换 + `Function` 构造器引导。**关键点在于触发时机**：**没有 install / postinstall 钩子**，代码在**模块被 import、应用启动时**执行——所以**`--ignore-scripts` 这类常规防御完全无效**。Sonatype 把它归入与朝鲜相关的 PolinRider 活动（未确认与 GhostAction 有关），相关包已被下架。处置建议很直接：把装过这些包的机器**当作已失陷**，轮换密钥与 token，检查 lockfile / CI / 构建记录，把依赖钉到已验证版本，并考虑**最小包龄策略**（比如只允许安装发布满 N 天的版本）。
