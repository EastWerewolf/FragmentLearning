### 🎨 浏览器与 CSS

- **[Safari 27.3 的自适应深色：`color-scheme` 是唯一开关，而 `light only` 在 beta 1 里还不生效](https://webkit.org/blog/18541/introducing-adaptive-dark-mode/)**（WebKit 2026-11-03 公布，细节于 11-04 ~ 05 被逐条拆解；此前 **11-05** 已推过功能概览，这里补实现细节）：对写 CSS 的人来说，这条的关键不是「苹果帮你做深色模式」，而是**它认哪一行声明**。机制分三档：**① 声明了 `<meta name="color-scheme" content="light dark">` 或 CSS `color-scheme: light dark` 的页面——完全不碰**，你已经是原生深色了；**② 整体偏暗的页面——保持原样**；**③ 浅色页面——套一层色彩矩阵变换**：倒转明度、保留色相，目标是 **WCAG 4.5:1** 的文字对比度；渐变会跟着变换，大多数图片不动，但 **SVG 会按需重着色、简单的黑白位图 logo 会被反相**（靠像素直方图判断），`<canvas>` 里的内容不动，而被变换元素上的 `mask` 与 `mix-blend-mode` **可能失效**——如果你的插画或图标依赖这两者做镂空/叠加，会看到破图。**想退出**：`:root { color-scheme: light only; }` 或 `<meta name="color-scheme" content="light only">`。⚠️ 两个坑，第一个是真的会坑人：**WebKit 明确说 `only` 关键字在 27.3 beta 1 里还没被支持**，也就是说**现在写下这句退出声明可能不起作用**；第二个是语法——单独写 `color-scheme: only` 是**无效值**，会被静默丢弃（正则是 `normal | [light | dark | <custom-ident>]+ && only?`），自测方法是 `getComputedStyle(document.documentElement).colorScheme` 应该读到 `"light only"`，读到 `"normal"` 就说明整行没生效。另外两个值得知道的设计取舍：**站点无法探测自己有没有被变换**（JS 读到的仍是作者写的颜色值），这是为了防指纹；官方给的动机数字是**约 40% 的页面加载来自深色模式用户，而只有约 10% 的页面支持深色模式**。Chrome on Android 的自动深色用的是同一套声明，所以这一行写对了是**跨两端同时生效**的。实践建议：logo 用 SVG、背景用 CSS 渐变而不是平铺位图、内容图带透明背景——这三件事能显著减少被算法翻车的机会。

### 📚 好文精选

- **[《Making features generic in CSS》：为什么 `flex-start` 要改名成 `flow-start`](https://rachelandrew.co.uk/archives/2026/11/making-features-generic-in-css/)**（Rachel Andrew，2026-11 上旬；经 Frontend Focus #765 推荐）：一篇能帮你理解**CSS 工作组到底在按什么逻辑改规范**的文章，比记一个关键字的用法值钱得多。核心变化：CSS Box Alignment Level 3 引入了 **`flow-start` / `flow-end`** 两个定位关键字，它们是 **`flex-start` / `flex-end` 的别名**——语义上完全一样，改名的原因是**「flex」这个词把功能说窄了**：现在需要在一套「逻辑起点与物理起点不一致」的布局里对齐（典型例子是 CSS Grid Lanes / masonry 里的 `fill-reverse`、`track-reverse`），叫 `flex-start` 就名不副实。文章顺着这条线讲了 CSSWG **为什么总在改名**、以及「把某个布局特有的概念提升为通用概念」这件事在规范层面要付的代价（序列化要返回新名字、旧名字得长期保留为别名）。**实际影响**很小但值得知道：写新的对齐代码可以用 `flow-start`，老的 `flex-start` 不会失效；Chrome 158（Beta 中，稳定 11-17）已经支持。补充一句上下文：这一期的 Frontend Focus（#765）头条正是「**Safari 会替你把站点改成深色**」，上面 🎨 那条的技术细节就是从那一路报道里来的。
