### 🚀 框架与工具链

- **[Node.js 10-21 安全更新落地：26.12.1 / 24.22.1 / 22.23.4，共 10 个 CVE](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)**（2026-10-21）：此前 10-20 只推过「三线 HIGH 级预告」，具体清单现在出来了——**CVE-2026-111497**（Brotli 解码器越界写，可能 RCE）、**CVE-2026-105482**（`dns.resolve` 截断含 NUL 的域名）、**CVE-2026-105483 / CVE-2026-106069**（TLS 主机名校验可被全角数字与宽松解析绕过）四条 HIGH；中低危还有 keep-alive 响应混淆、`crypto.randomUUID()` 在 snapshot / SEA 里的熵缓存、`node:zlib` ZipFile 前缀字节泄露（仅 26.x）与 Permission Model 绕过。依赖侧同步升了 c-ares、ca-cert（含 eMudhra 中间 CA 被攻陷）、OpenSSL 与 Undici。**Node 20 已于 2026-04 停止支持，本轮没有补丁**——还在 20.x 的 CI 镜像该排期了。
- **[Vite 6.4.4 / 6.4.5 安全补丁](https://github.com/advisories/GHSA-9jrq-w75r-8gcw)**（2026-10-20 / 10-21）：两条 advisory 一起修——**CVE-2026-112945**：使用 `middlewareMode: true` 或 `appType: 'custom'`、且把未改写的 request URL 直接喂给 `server.transformIndexHtml` 的应用，构造 `//evil.example/payload.js?/../../package.json` 这类 URL 就能让 dev server 输出一个指向外站的 module script 并被执行（跨源脚本执行）；**CVE-2026-112946**（CVSS 4.0 6.3）：非 Windows 机器上项目路径与系统路径重合时，`server.fs.allow` 之外的文件可能被 dev server 读出。修复版本：**6.4.4 / 7.3.7 / 8.1.6 / 8.2.4 / 8.3.3**，6.4.5 是 6.x 线上的后续补丁。只影响 dev server，但把本地开发端口暴露到局域网的团队要当成真漏洞处理。

### 🎨 浏览器与 CSS

### 🤖 AI 与开发

- **[Claude Code v2.1.309：堵沙箱与权限漏洞，`sed -i` 行为变了](https://code.claude.com/docs/en/changelog)**（2026-10-22）：39 项修复 + 13 项改进，没有新功能，重点是安全——**沙箱化 Bash 在 macOS / Linux 上执行前会在沙箱外跑 shell 启动文件**（`~/.bashrc` 等）被修掉；macOS `denyWrite` 的 glob 在路径经符号链接解析到真实位置时失效；沙箱内命令与 auto-accept 编辑能改 `--mcp-config` 传入的 MCP 配置；`Edit(path)` 拒绝规则可被含子 shell 的 Bash 重定向绕过；Windows 上部分 `Set-Location` / `cd` 被自动放行、PowerShell hook 在没装 Git for Windows 时 fail-open。两个会打断脚本的变更：**`sed -i` 现在走标准 Bash 权限提示、按原样执行，且不再被 `/rewind` 还原**；**`claude ultrareview` 需要 workspace trust**（终端会提示，非交互环境需 `--trust-workspace` 或 `CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1`）。此前于 10-22 推过 2.1.307 / 308。
- **[Claude Security 从「按需扫描」变成「持续监测」](https://runtimewire.com/article/anthropic-claude-security-continuous-code-scanning)**（2026-10-21，Claude Enterprise 公测）：先做一次深度基线扫描，之后**每次提交都按风险重扫**，不再按固定周期；发现项在修复落地后自动关闭，漏洞回归则**自动重开**。仓库支持 GitHub（含 GHES）与 GitLab / Bitbucket / 其他 Git（token 接入），单项目最多 **8 个仓库**，可分「in scope」与「仅作上下文」做跨服务分析。可编辑的**威胁模型**与知识库会直接影响告警与分级；新增 **API、webhook 与 MCP connector**（Claude.ai / Claude Code 都能接）。按 token 直付、无平台费，符合条件的企业两个月内每月最多 **$25,000** 额度（至 2026-12-31）。⚠️ 不支持 Zero Data Retention，欧盟团队要先过合规。
- **[MiniMax 开源 M3.1 Flash 权重](https://www.ithome.com/1/016/800.htm)**（2026-10-23，此前 10-20 推过发布与定价，这里补「权重真的开了」）：**总参数 428B / 激活 23B** 的 MoE，官方称上线 **72 小时处理超过 100 万亿 token**，并同步放出推理优化与芯片生态适配。结合 1 元 / 百万输入的价格，它把「Agent 全流程跑一天」的成本压到了可批量试错的区间；做本地 / 私有化部署的团队现在可以真正评估了。⚠️ 参数与吞吐为官方口径，尚未见到第三方复现。
- **[OpenAI 模型与 Codex 进 Google Cloud Model Garden](https://openai.com/index/openai-models-google-cloud/)**（2026-10-21 ~ 22）：OpenAI 的前沿模型（GPT-6 Astra / 6.1 Sol / 6 Luna）与 **Codex agentic workflow** 将以原生服务进入 Google Cloud，经 **Cloud Marketplace** 交易、可抵扣企业已有的 GCP 承诺消费；目前是定向私测，官方口径「未来数周」GA，暂未公布按 token 的公开定价。同时宣布 OpenAI 模型「很快」进入 **Google Antigravity 与 Gemini Agent**。这是继 AWS Bedrock（4 月）、Oracle Cloud（6 月）之后**第三个卖 OpenAI 模型的大厂云**，微软仍是主要云伙伴。对企业技术选型的意义：**模型采购正在和云消费承诺绑在一起**，前端 / Agent 团队选 SDK 时要把「模型从哪家云出」也算进成本模型。
- **[科大讯飞发布端云一体星火 X2.6](https://www.stcn.com/article/detail/4232926.html)**（2026-10-22，1024 开发者节）：主打**全国产算力**上的代码与智能体能力突破，官方称多项公开基准对标业界一流；技术上首次给出「端云一体」协同架构——端侧 **X2.6-4B** 按任务难度、端侧能力与数据安全需求路由（纯端侧 / 端云协同 / 纯云侧），基于评语模型的路由协同训练把路由准确率做到 **96.1%**，敏感信息本地脱敏后才上传；官方预计未来 60% 应用本地完成、30% 端云协同、10% 纯云。同期还有 SparkAudio 1.0 语音基座、WinWork 数字员工平台。对做国内 to B / 信创方案的人，「端侧可跑 + 数据不出内网」这套叙事比跑分更有说服力。

### 🧰 工程化与安全

- ⚠️ **[PHP2Shell：两个 CVSS 9.2 的 PHP 未认证 RCE，补丁发布后 19 分钟即被利用](https://www.helpnetsecurity.com/2026/10/21/php2shell-php-vulnerabilities-patched-cve-2026-109618-cve-2026-109619/)**（原定 10-22 披露，因提前泄露，补丁于 2026-10-21 提前发布）：影响 **PHP 5.4 以来的所有版本**、约七成网站。**CVE-2026-109618**：内存上限中断请求时留下半初始化数据，清理阶段当成合法对象用（UAF），可经大体积 multipart 上传触达；**CVE-2026-109619**：请求归属的全局状态在释放后残留，同一 worker 的下一个请求复用（依赖默认开启的 `session.upload_progress.enabled`）。mod_php 风险最高，PHP-FPM / php-cgi / FrankenPHP / LiteSpeed 同样受影响。修复版本 **8.5.12 / 8.4.27 / 8.3.36 / 8.2.35**（另 8.6.0 RC4），7.4 / 8.0 / 8.1 只有源码级 backport。**打补丁后必须重启 PHP / Apache worker**，发行版 backport 往往不改版本号，要查 changelog 确认。
- **[「Patch the Planet」：GPT-5.6 Sol 参与挖出这个 14 年老洞](https://openai.com/index/coordinated-disclosure-of-critical-vulnerabilities/)**（2026-10-22）：PHP2Shell 的发现侧同样值得看——安全公司 Calif 在 OpenAI **Patch the Planet** 计划支持下，用 **GPT-5.6 Sol** 在约两周内定位到 PHP 内存安全问题（研究员 7-30 开始审计、8-1 找到利用路径、8-11 上报）；Wiz 用自家 Atlas + 模型独立复现。这个洞 2024 年曾被 Quarkslab 看到但判定「不可利用」。OpenAI 借势提出**五阶段协同披露框架**（验证 / 上游修复 → 给受影响方留时间 → 与政府协调 → 准备跨产品更新 → 发布指引），并承诺 **10 亿美元的 Daybreak 补贴额度**给防御方，还把 PHP 版本检查器做成了 **Codex skill**。⚠️ Calif 自己强调：**领域专家比模型更关键**，没有哪个模型能靠一句 prompt 挖出「所有漏洞」。
