### 🚀 框架与工具链

- **[Rolldown 1.3.0：实验性 import attributes，但别用 overrides 把它塞进 Vite 8.3.6](https://github.com/rolldown/rolldown/releases/tag/v1.3.0)**（2026-11-05）：这版的主角是 **`experimental.importAttributes`**——它把 **import attributes 纳入模块身份**，也就是说同一个文件带不同 attributes 导入会变成**两个独立模块、各自一份实例**；attributes 会贯穿 `resolveId` / `resolveDynamicImport` / `load` / `transform` 与 `this.resolve` / `this.load`，`type: 'json' | 'text' | 'bytes'` 不装插件就能用，且 `type` 属性优先于资产/复制插件的 `moduleTypes`。**真正影响所有构建（无需开实验开关）的是 externals 的修复**：过去同一个 external 用不同 attributes 导入两次会被合并成一份、丢掉一个 import，而且遗留的 `assert` 关键字会被原样写进产物——**Node 22+ 直接加载不了**；现在改为按模块身份渲染 attributes，并对 `assert` 给出 `DEPRECATED_IMPORT_ASSERTION` 警告。⚠️ **升级路径是这条的重点**：Vite 对自己的 rolldown 版本是 lockstep 锁定的（HMR、chunk 生成、插件容器都依赖其非公开行为），社区已有明确提醒——**不要用 `overrides` / `resolutions` 把 1.3.0 强行注入 Vite 8.3.6**，1.3.0 改了默认行为，出错方式往往是**静默的**（HMR 坏掉、chunk 划分异常）而不是报错；正确顺序是先升 Vite，再用 `pnpm why rolldown` 看它带上来的是哪一版。这条提醒来自第三方分析而非 Vite 官方公告，但结论与 Vite 一贯的锁定策略一致。

### 🤖 AI 与开发

- **⭐ [PSI：一个未公开的 Anthropic 模型，三天证出悬了 18 年的 Aaronson–Ambainis 猜想，并过了 Lean 核验](https://github.com/physical-superintelligence/aaronson-ambainis)**（Physical Superintelligence 于 **2026-11-06** 公布；论文 + Lean 4 形式化以 Apache 2.0 公开在 GitHub）：这条值得单独读，因为它可能是**今年第一个「AI 产出的数学结果，其正确性可以被机器独立复核」**的案例。**结论是什么**：Aaronson–Ambainis 猜想（2008 年提出）问的是**量子计算什么时候能带来指数加速**——证明的结论是**在没有稀有结构的随机是/否输入上，量子优势最多是查询数的多项式级**，也就是说 Shor 那种指数加速必须依赖输入的特殊结构，不是普遍现象。技术上它接在 Lovett–Zhang 的工作上，把一条开放不等式换成了一个新界（常数约 **0.0025**）。**过程**：PSI 的内部研究系统运行**未公开的 Anthropic 模型实例**，在**第 3 天**给出完整证明，之后又改进了两次。**可核验的部分**：主定理与猜想的表述都形式化进 **Lean 4**，四个定理**没有占位符、没有额外公理**，并用**两个独立的 Lean 内核实现**复核过。**谁负责**：PSI 的 David Turturean 搭的系统、对正确性负责；Jim Halverson 审证明、Phiala Shanahan 审形式化。**外部反应**：Stanford 的 Guy Blanc、Jordan Docter、Carmen Strassle、Li-Yang Tan（他们 8 月刚证了并行轮数的特例）正在读证明、已发来意见、并准备写一份更短的行家版说明，评价是「**a huge result**」「各部分拼起来的方式相当神奇」。⚠️ **四个保留，一个都别省**：**一、未同行评审**，这是一家 9 月才成立的公司的主张，只是附了可检查的产物；**二、Lean 只保证「从假设到结论」的推导**，**「Lean 里的 `PrintedConjecture` 是否等于论文里那个猜想」仍然要人来看**——这条和 10-29 那篇讲 Axiom 有限单群证明的文章是同一个教训；**三、散文部分的证明没有机器验证**，且有一个定理依赖别人尚未形式化的结果；**四、Anthropic 没有确认用的是哪个模型**，它至今未发布。
- **⚠️ [ThisBash：一个普通浏览器扩展就能借 Claude Dispatch 在你机器上执行命令，而 Anthropic 表示不修](https://www.theregister.com/research/2026/11/05/anthropic-wont-fix-a-claude-dispatch-flaw-that-could-let-attackers-execute-remote-commands-across-corporate-boundaries/)**（The Register 于 2026-11-05 首发，研究者 Gal Weizman / Forever Security 有完整技术复盘）：这条对**装了 Claude Desktop 且浏览器里有扩展**的人是直接风险。**根因不是浏览器漏洞**：Dispatch 的接口与 API（含 `GET /v1/sessions?tags=cowork-dispatch-local`）在**普通的已登录 Web 会话**里就能访问，于是扩展可以「以用户身份」发指令。**六步链**：扩展在 claude.ai 注册一个 **MAIN-world content script** → 在一个极小的隐藏弹窗里打开 Dispatch → 用用户的 cookie 拿到 Desktop Agent 的 session ID → **用「提示词施压」多轮诱导**模型主动去跑命令（例：劝它 `npm install` 某个包）→ **以约 1 秒间隔自动点掉每一个「Allow」审批按钮**（所以不需要有人盯着）→ 恶意 npm 包的 `preinstall.js` 触发，PoC 打开了计算器。**跨设备**是它最麻烦的地方：同一 Claude 账号在另一台机器上登录着，就能从**个人浏览器打到公司笔记本**。**Anthropic 的回应**：2026 年 5 月就确认有效，但**按内部重复问题关闭**，**无 CVE、不发赏金**；原计划 10 月底下线 Dispatch，**但截至 10-30 它仍在面向 Pro / Max / Ultra 老用户的限时 beta 里**。Weizman 说同一套「共享会话」设计缺陷仍存在于 **Claude Cowork** 与 **Claude Code Remote Control**。**能做的**：关掉跨设备 Dispatch、审计有 claude.ai 权限的扩展、在受管设备上别用个人账号。⚠️ 无在野利用报告，PoC 为演示性质；Anthropic 未就「为何不修」给出公开说明。
- **[Claude Code 一直在往 User-Agent 里写你的邮箱：代理挡住了，但只是「礼貌」](https://github.com/anthropics/claude-code/issues/107757)**（issue 于 2026-11-05 提交，600+ 赞、约 1,500 分上 HN；Anthropic 11-06 回应）：现象是 Web 请求头里出现 `ClaudeCode/2.1.311 (contact: you@example.com)`，发给第三方站点；报告者说自己每天收到几十封诈骗邮件。**为什么会有**：据 Anthropic 的 Lydia Hallie，账号邮箱被放进模型上下文，是为了**防止它在写 `@author` 标签时瞎编名字**；而当模型自己写 `curl` 去访问那些要求留联系方式的站（Wikipedia、SEC EDGAR、Liquipedia、crates.io），它就把这个地址当联系人用了。**这不是新问题**：更早的 issue **#81138（7-25）**与 **#55743（5 月）**都报过。**当前的缓解不完整**：2.1.317 起内置 `cc-plugin-privacy` 并默认开启（约 171 行正则/词匹配，只匹配「字面邮箱 + User-Agent 关键词」），它的 README 自己就写着这是「**a courtesy, not a boundary**」——**跳过 WebFetch 与 WebSearch**、拦不住 `From:` 头、`curl -u`、运行时算出来的值（`$(git config user.email)`）、双重编码与非 ASCII 邮箱；有测试者跑 23 个用例**漏了 8 个**；也有人反馈 mod 没出现在 `/plugins` 里或根本没生效（`stable` 渠道当时还停在 2.1.311）。**承诺的修法**是**把账号邮箱从模型上下文里彻底移除**，时间点说的是「下周早些时候」，截至发稿没落地。**给你的动作**：只要你会在 Claude Code 里让它上网，就假设 UA 里出现过你的邮箱，检查一下是不是该换一个更低噪音的账号。
- **[Claude Enterprise 把「推理钩子」扶正：提示词与工具调用先过你的 DLP，但默认是放行](https://claude.com/resources/articles/claude-enterprise-security-updates)**（2026-11-05，官方博客）：对企业安全团队这是本周期最实质的一次更新。**唯一 GA 的是 inference hooks**，分两种：**prompt hooks**（把支持的 Claude 产品里的提示词先发给客户自托管的 HTTPS 端点 / DLP 做「允许或拒绝」判定）与 **pre-tool-call hooks**（执行前检查工具调用）；厂商侧点名了 Netskope、Proofpoint、Reco。**其余全是 beta**：**Security Center**（拿当前配置对比 Anthropic 推荐值、可导出审计报告、支持记录与风险接受）、**Parent Console**（`admin.claude.com`，跨多个 org 统一管 SSO / SCIM / 域验证 / 组 / Compliance API key，支持多 IdP）、**Admin API 单次全员登出**（结束会话但**不影响 API key 与云会话**）、IP 允许列表、在受管设备的 Claude Desktop 上禁止个人账号、workspace 目录限制、以及在 Cowork 本地 VM 里跑**只检测模式**的 EDR（CrowdStrike / SentinelOne / Tanium）。⚠️ **钩子的四个边界决定了它不能当唯一防线**：**默认 fail-open**（5 秒超时即放行）、**不检查图片**、判定只有 allow / deny、**Bedrock 与 Google Cloud 上不可用**——把「已经接了 DLP 就安全了」当成结论是错的。
- **[OpenAI Images 2.6：能出 GIF，也给得出 SVG](https://openai.com/index/introducing-images-2-6/)**（2026-11-04 上线、11-05 公布；ChatGPT、Codex 与 API 全量，免费档也有）：对前端来说，这版真正的新东西是**输出格式**而不是画质。**GIF**：原生文本转循环动画，API 侧 `output_format: "gif"` + `frame_count`（2–64 帧）+ `frame_duration_ms`，实现方式是**逐帧 sprite sheet** 而不是视频扩散——所以它给出的是一条可控帧数的动画而不是短视频。**SVG**：**API 独有的静态矢量导出**，意味着图标、插画这类素材可以直接拿到矢量结果再人工清理，而不必先出位图再描。其余：整体**快约 50%**（Flare 在低质量档约 **6 秒**出图）、API 开放了原本只在 ChatGPT 里有的**图像标注编辑**（圈定要改的区域）、新增 **`complexity`** 参数把「规划投入」与 `quality` 解耦、多轮编辑对角色的保持更好。模型是 `gpt-image-2.6-flare` 与 `gpt-image-2.6-sunburst`，**价格与 2.5 相同**（$8 / $30 每百万图像 token，文本输入 $5、缓存图像输入 $2）；安全侧带 **C2PA + SynthID** 水印，并对 GIF 加了跨帧的运动审查（召回 77.7%）。⚠️ 官方称每周生成约 **40 亿张**图，这个数字无法独立验证；SVG 导出的保真度（路径数量、是否含位图嵌层）也需要自己压测。
- **[给 Agent 的「发现层」正在成形：`/.well-known/ai-catalog.json` 与 Lighthouse 的 ARD 审计](https://www.searchenginejournal.com/google-microsoft-back-draft-ai-agent-discovery-spec/579894/)**（ARD 规范 2026-06 起由 Google、Microsoft、GitHub、Hugging Face、Cisco、Databricks、NVIDIA、Salesforce 等联合推进；**Lighthouse 13.6 已把 ARD 审计升到 v0.91**）：这条是「前端要开始考虑非人类访客」的具体落点。**ARD（Agentic Resource Discovery）** 只解决一件事——**发现，不执行**：MCP / A2A 规定「怎么调一个工具」，ARD 规定「怎么知道你有哪些工具」。两个原语：**Catalog** 是发布者自托管的 JSON，放在 **`/.well-known/ai-catalog.json`**（域名本身即信任锚），必填 `specVersion`、`host`、`entries[]`；**Registry** 是类搜索引擎，抓取 catalog 建索引，用 `POST /search` 回答自然语言查询。**站点侧的四条发现通道**：`robots.txt` 的 `Agentmap:` 指令、HTML 里的 **`<link rel="ai-catalog">`**、**HTTP `Link:` 响应头**、以及 `/.well-known/` 兜底。工具侧有 npm 的 **`ai-catalog`**（`npx ai-catalog validate` / `discover`）可做校验。**为什么现在值得看**：Lighthouse 13.6 的 ARD 审计 v0.91 已经**认这三种新位置并对旧 `ai-catalog` 位置告警**，也就是说「你的站点有没有 Agent 入口」开始变成一项可测的分数。⚠️ **这仍是草案不是标准**：版本号在 v0.9 / v0.91 之间，各来源的日期与条目 ID 格式（`urn:ai:` vs `urn:air:`）互相矛盾，Google 的 Agent Registry 只是「未来几个月」支持——**现在写进 catalog 是为了提前占位，不能当成承诺**。
